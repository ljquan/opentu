# 供应商自定义模型接入经验

## 背景

部分兼容供应商不提供 `/models` 接口，或返回的模型列表不完整。即使供应商的 Base URL 和 API Key 已配置正确，用户仍无法把未被发现的模型加入 OpenTu 原有的文本、图片、视频和音频调用流程。

本功能在现有供应商配置中增加“添加自定义模型”能力。自定义模型继续复用供应商档案、模型选择器、任务路由和请求传输链路，不引入脚本执行器或第二套模型系统。

## 新增能力

### 1. 在当前供应商下添加模型

用户可在供应商的模型区域填写：

- 模型 ID。
- 模型类型：文本、图片、视频或音频。
- 调用方式。
- 可选显示名称和描述。

添加成功后，模型立即进入当前供应商的“已添加模型”列表，并可被相应类型的模型选择器和默认模型预设选中。

### 2. 复用站内已有调用方式

调用方式提供文本对话、多模态文本、图片生成与编辑、异步图片任务、视频任务和音频任务等已有接口预设。

选择预设后，系统自动保存对应的协议、请求格式、提交路径、响应格式和可选轮询路径。生成面板仍负责提供提示词、参考图、尺寸、时长等参数，用户不需要重复配置这些运行时输入。

### 3. 受控的自定义 HTTP 接口

无法套用已有预设时，可配置：

- 请求地址和 Method。
- JSON、FormData 或 Raw 请求体。
- 额外 Headers。
- 同步结果字段路径。
- 任务 ID、状态、结果、错误字段及轮询路径。

请求模板仅解析受支持的运行时变量，例如 `model`、`prompt`、`messages`、`image`、`images`、`size`、`duration` 和 `params`。响应解析使用有限字段路径，不执行任意 JavaScript。

## 数据与路由设计

### 模型目录

自定义模型写入当前供应商的 `ProviderCatalog.discoveredModels`，同时加入 `selectedModelIds`。因此手动添加和自动发现的模型共用同一份运行时模型目录，无需维护额外的全局模型常量。

再次获取远端模型列表时，系统合并并保留手动添加的模型。用户显式移除模型后，才会从已添加列表和对应手动绑定中清理。

### 调用绑定

模型的调用配置保存在 `ProviderCatalog.manualBindings`，内容包括模型类型、协议、请求与响应格式、提交路径及轮询信息。

路由仍使用 `ModelRef` 的 `profileId + modelId` 定位模型。这样即使不同供应商存在相同模型 ID，也能使用各自的 Base URL、API Key、鉴权方式和能力配置。

用户显式保存的手动绑定优先于自动协议推断，避免自定义请求地址或模型协议被默认规则覆盖。

### 更新和冲突规则

- 同一供应商下再次添加相同 ID、相同类型的模型时，更新其显示信息和调用绑定。
- 相同 ID 已被另一模型类型占用时，拒绝静默覆盖，提示先移除原模型或更换 ID。
- 删除模型时同步删除对应手动绑定，避免残留配置继续参与路由。

## 安全与性能边界

- 不允许在设置页编写或执行任意脚本。
- API Key 继续由供应商档案管理，不写入模型目录、文档或请求模板示例。
- 模板只做有限变量替换和字段路径读取，不提供无限制表达式求值。
- 自定义模型仅保存轻量配置，不保存媒体二进制、Base64 内容或完整响应历史。
- 请求继续复用现有 transport、超时、错误归一化和任务轮询机制，避免新增长期监听和无界内存缓存。

## 经验规则

### 规则 1：自定义模型属于供应商目录

模型必须保留供应商归属，不能只保存裸模型 ID，否则同名模型会错误复用其他供应商的凭据和接口。

### 规则 2：显式配置优先于自动推断

用户已配置调用方式或自定义 HTTP 时，路由不得再用模型名称猜测协议和请求地址。

### 规则 3：刷新远端列表不能删除手动模型

自动发现结果是补充来源，不是自定义目录的全量覆盖来源。只有用户主动移除才能删除手动条目。

### 规则 4：运行时参数由原生成入口提供

设置页只描述接口结构。提示词、参考图、尺寸、时长等任务参数仍由原有文本、图片、视频和音频入口传入，避免形成两套生成流程。

### 规则 5：自定义能力必须保持受控

使用固定变量、字段路径和请求体类型即可覆盖常见兼容接口，无需引入脚本执行带来的密钥泄露、代码注入和不可控资源占用风险。
