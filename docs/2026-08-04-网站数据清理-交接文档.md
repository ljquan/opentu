# 网站数据清理功能交接文档

更新日期：2026-08-04

## 背景

网页长期运行后会积累图片、媒体缓存以及任务、聊天、素材和画板等本地业务数据。此前缺少统一入口，用户需要依赖浏览器开发者工具逐项清理，且容易误删登录状态或个人配置。

本功能在桌面端左侧工具栏最下方新增“清理网站数据”入口，通过明确的数据白名单提供“仅清除缓存”和“清除全部本地数据”两种模式。

## 最终行为

- 桌面端左侧工具栏在任务队列下方显示垃圾桶按钮，悬停文案为“清理网站数据”。
- 移动端和触屏布局不显示该入口。
- 弹窗默认选择“仅清除缓存”，不会删除生成记录或本地文件。
- “清除全部本地数据”始终要求输入“确认清除”。
- 存在活动任务、运行中工作流或未同步变更时，弹窗追加具体风险提示；用户确认后仍可继续清理。
- 清理成功后刷新当前页面；清理失败时保留当前页面并显示错误信息。
- 不提供服务端数据删除能力。

## 清理范围与保留范围

### 仅清除缓存

| 数据类型                       | 处理方式                                                         |
| ------------------------------ | ---------------------------------------------------------------- |
| 统一媒体缓存                   | 清空 IndexedDB 中的媒体元数据与二进制缓存                        |
| 图片与缩略图缓存               | 删除对应 Cache Storage，并通知 Service Worker 清理运行时图片缓存 |
| 角色头像缓存                   | 清空头像缓存数据                                                 |
| 图片、视频预览缓存             | 删除对应的 LocalStorage 预览缓存键                               |
| 任务、工作流、聊天、素材、画板 | 保留                                                             |

### 清除全部本地数据

在“仅清除缓存”的基础上，额外清理以下浏览器本地业务数据：

- 当前任务、历史任务、运行中工作流和工作流历史。
- 生成提示词历史及旧版图片、视频、批量生成记录。
- 聊天会话、知识库内容及知识库聊天记录。
- 素材、角色、音频播放列表和各创作工具生成记录。
- 本地工作区、文件夹、画板及画板状态。
- 旧版任务队列及待处理工具、画布操作等兼容数据。

### 明确保留的数据

- Cookie、登录状态和 Service Worker 注册。
- 主题、语言、模型、接口及其他用户偏好。
- `aitu-app/config` 等与业务数据共库的配置存储。
- 提示词预设、用户隐藏记录和用户编辑覆盖值。
- 不在清理白名单内的 LocalStorage 与 IndexedDB 配置数据。
- 所有服务端数据。

实现不调用 `localStorage.clear()`，也不删除整个 IndexedDB 数据库，只清理明确列出的业务 store 和键，避免误删同库配置。

## 用户流程与确认机制

1. 用户点击左侧工具栏最下方的垃圾桶按钮。
2. 弹窗读取活动任务、运行中工作流和未同步变更状态。
3. 默认可直接执行“仅清除缓存”。
4. 切换到“清除全部本地数据”后，确认按钮保持禁用，直到输入完全一致的“确认清除”。
5. 执行期间忽略重复点击，并禁止通过遮罩或 `Esc` 关闭弹窗，避免后台清理结束后突然刷新。
6. 成功后刷新当前页面；失败时显示具体错误且不刷新。

未同步草稿或任务不支持主动同步、导出或恢复。用户完成强确认后，相关内容会被放弃。

## 数据流与执行顺序

### 缓存模式

1. 暂停新的页面侧媒体缓存写入，等待已开始的写入收敛后，清空统一缓存的媒体元数据和 Blob 数据。
2. 删除页面侧图片与缩略图 Cache Storage。
3. 通过现有 Service Worker RPC 清理其图片、视频内存缓存及 Cache Storage。
4. 清空头像缓存和图片、视频预览缓存键。
5. 刷新页面，使页面内存状态重新初始化。

### 全部模式

1. 暂停任务与工作流持久化写入。
2. 中止活动任务、停止图片恢复流程并销毁运行中的工作流引擎。
3. 清理任务、工作流、缓存、聊天、素材、角色、知识库、创作记录和工作区内容。
4. 成功后刷新页面，重建干净的运行时状态。

任务、工作流与媒体缓存均设有清理写入屏障：先阻止新写入并等待已开始的写入收敛，再执行删除。Service Worker 缩略图生成同样在删除缓存前等待进行中操作结束。若完整清理中途失败，写入器会恢复，页面不会自动刷新。

## 失败与恢复边界

- 多类浏览器存储无法组成跨数据库事务；任一步骤失败时，之前已成功清理的数据不会自动恢复。
- 清理失败会显示错误信息并保留当前页面，用户可处理浏览器权限或存储异常后重试。
- “清除全部本地数据”不可撤销，产品不提供回收站或自动备份。
- 本功能不删除服务端或 GitHub 远端数据；保留同步配置时，已同步的内容可能在刷新后被重新拉取，这不视为本地清理失败。
- 页面刷新前，成功的完整清理会保持任务与工作流写入暂停；媒体缓存清理会先等待清理前已开始的受管写入收敛。
- 未注册 Service Worker 时只执行页面侧清理，不会创建或注销注册；已建立通道但清理 RPC 明确失败时，缓存清理按失败处理。

## 性能与安全边界

- 使用已有缓存、任务、工作流和存储服务，不引入新的持久化实体。
- IndexedDB 按已存在的数据库和 store 白名单清理，不为缺失数据创建空数据库。
- 大型媒体数据由浏览器存储接口直接清除，不读取或复制完整文件到 JavaScript 内存。
- 清理前中止活动任务并停止后续写回，避免持续网络请求和无效内存占用。
- 不清除 Cookie、不注销 Service Worker、不调用服务端删除接口。
- 界面仅在桌面端提供入口，符合本次需求范围。
