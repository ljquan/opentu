# AI 任务栏提示词复用、跟随尺寸与局域网图片插入交接文档

**日期**: 2026-08-04
**适用版本**: 基于 `origin/develop` `3befb62b`
**关联 QA**: [2026-08-04-AI任务栏跟随尺寸与局域网图片插入测试](../qa/2026-08-04-AI任务栏跟随尺寸与局域网图片插入测试/2026-08-04-AI任务栏跟随尺寸与局域网图片插入测试.md)

## 问题

1. 任务栏跟随窄图片时，宽度会被目标图片宽度压缩到 `420px` 左右，模型、尺寸、数量等选项被挤压或裁切。
2. 通过局域网 HTTP 地址访问 OpenTu 时，浏览器处于非安全上下文，Service Worker 不可用。画板保存的 `/__aitu_cache__/...` 图片无法由 Service Worker 返回，手动插入任务图片时连续提示“插入失败: 未知错误”。
3. 选中带历史提示词的生成图片时，原提示词直接进入输入值，容易被误提交；用户也无法区分“历史参考”与“当前已输入内容”。

## 最终行为

### 跟随任务栏

- 目标图片只决定任务栏的吸附位置，不再决定任务栏宽度。
- 桌面端继续使用原任务栏响应式尺寸，最大宽度 `720px`。
- 跟随前后不写入额外的内联 `width` 或 `max-width`。
- 任务栏仍优先显示在目标下方，空间不足时切换到上方，并保持视口内左右边界。
- 移动端沿用既有底部全宽布局。

### 历史提示词候选

- 选中带历史提示词的图片后，输入值保持为空；原提示词以淡化 placeholder 显示，并提示“按空格或回车复用”。
- 输入为空且未使用修饰键时，按空格或回车只把候选填入输入框，不立即提交；再次按回车才按现有流程提交。
- 用户直接输入新内容，或点击任务栏中的上传、素材库、模型、参数、数量、发送等按钮后，候选立即消失，不写入输入值。
- 方向键、`Shift/Alt/Ctrl/Command` 组合键、中文输入法组合输入和打开下拉菜单时，不误复用候选。
- 同一图片的 URL、任务或 anchor 元数据异步刷新时，不覆盖用户当前输入，也不重新显示已经取消的候选；切换到另一张图片后才建立该图片自己的候选。
- 没有历史提示词、普通本地图片、取消选择或多选时不显示候选。

### 局域网图片插入

- 缓存图片继续在画板数据中保存稳定虚拟 URL，不写入临时 `blob:` 或大段 base64。
- Service Worker 不可用时，插入链路直接从 IndexedDB Blob 缓存读取图片尺寸。
- 画布渲染虚拟图片失败时，从 IndexedDB 读取 Blob 并创建临时 Object URL。
- 图片 URL 变化或组件卸载时立即回收 Object URL，避免长期占用内存。
- Service Worker 正常可用时继续使用原虚拟 URL 路径，不改变线上行为。
- 局域网生成请求使用固定同源前缀，避免浏览器直接请求上游导致 CORS/`Failed to fetch`。当前支持：
  - `/__opentu_tuzi_proxy__/api`
  - `/__opentu_tuzi_proxy__/apius`
  - `/__opentu_tuzi_proxy__/apicdn`
  - `/__opentu_tuzi_proxy__/sydney`
  - `/__opentu_tuzi_proxy__/ourzhishi`
  - `/__opentu_tuzi_proxy__/ourzhishi-sz`

## 数据与性能边界

- 不新增图片副本到画板 JSON。
- 不把缓存图片转为 base64 后持久化，避免白板数据和内存膨胀。
- Object URL 只作为当前渲染会话的临时地址，并在换源或卸载时释放。
- 现有 Cache Storage 与 IndexedDB 双写策略保持不变。
- 修复不改变图片生成、任务队列、目标替换和素材库的数据结构。
- 候选提示词只存在于当前 React 会话状态，不新增后端接口、持久化字段、权限或大字符串副本。
- 元数据并发刷新沿用元素 ID 边界；取消标记只保存一个元素 ID，不随历史任务数量增长。

## 启动要求

OpenTu 开发环境依赖 `sw.js`。标准启动应使用项目的 PWA 启动链路：

```bash
pnpm start
```

指定其他应用端口时，也必须先以 development 模式构建或监听 Service Worker：

```bash
./node_modules/.bin/vite build -c apps/web/vite.sw.config.ts --mode development
pnpm exec vite --config apps/web/vite.config.ts --host 0.0.0.0 --port 7024 --strictPort
```

局域网 HTTP 地址即使无法启用 Service Worker，图片插入和画布渲染也必须通过 IndexedDB 回退正常工作。

局域网验收不能只检查 SPA 页面返回 `200`。至少还要确认固定代理返回 JSON 或真实上游错误而非 HTML，并完成一次“生成结果插入画板”的端到端流程。

## 回归重点

1. 窄图、宽图和缩放后的图片进入跟随态，任务栏宽度均与普通态一致。
2. 模型、参数、数量、发送按钮保持可见，不出现横向裁切。
3. 历史提示词仅以候选显示，空格/回车可填入；输入、按钮点击、组合键和 IME 不误触发。
4. 同一目标异步刷新不覆盖用户输入或重新显示已取消候选，快速切换目标时不串提示词。
5. `localhost` 有 Service Worker 时，虚拟缓存图片正常插入和显示。
6. 局域网 HTTP 无 Service Worker 时，单图和多图均可插入并显示。
7. 固定同源代理返回上游响应而非 SPA HTML，生成阶段不再出现浏览器 CORS 型 `Failed to fetch`。
8. 快速切换、删除图片或卸载组件后，没有遗留 Object URL 或异步回写旧图。

## 一句话结论

任务栏现在把历史提示词作为可取消候选，只有空格或回车才复用；跟随图片时不压缩自身，局域网 HTTP 也通过同源代理与 IndexedDB 回退保障生成和插入链路。
