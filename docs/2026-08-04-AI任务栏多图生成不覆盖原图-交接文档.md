# AI 任务栏多图生成不覆盖原图交接文档

更新日期：2026-08-04

## 背景与根因

AI 任务栏绑定一张画布图片后，无论用户选择 `1个`、`5个` 或其他数量，提交逻辑都会把有效生成数量强制改为 `1`，并始终附加当前图片的原位替换参数。因此，选择多个时仍只生成一张图片，且结果会覆盖原图。

本次修复保留既有单图跟随体验，同时把多图生成切换为独立新图流程。

## 最终行为

- 绑定图片且生成数量为 `1`：继续原位替换当前图片。
- 绑定图片且生成数量大于 `1`：保留原图，并严格按用户选择的数量生成独立新图。
- 多图生成继续使用当前绑定图片作为参考输入，但不把任何结果写回原图。
- 提示词、模型、尺寸等现有生成参数保持不变。
- 未绑定图片时，单图和多图生成行为保持不变。

## 实现逻辑

1. `AIInputBar` 不再因为存在绑定图片而把 `selectedCount` 强制改为 `1`，用户选择的数量会继续传入输入解析和图片工作流。
2. `buildBoundTargetGenerationParams` 同时接收绑定目标与生成数量：
   - `count = 1` 时返回原位替换参数；
   - `count > 1` 时返回 `null`，进入普通新图生成流程。
3. 只有单图替换流程会把绑定图片作为 `replacementBoundImageTarget`，并把目标、来源信息写入生成锚点。
4. 多图流程沿用已有批量锚点布局，每张图使用独立锚点和批次序号，避免多张结果争用同一个替换目标。

## 数据边界

单图原位替换允许携带以下绑定目标字段：

- `generationMode: image_to_image`
- `replaceElementId`
- `targetElementId`
- `anchorId`
- `sourceTaskId`
- `sourcePrompt`

多图生成不得携带上述替换参数，也不得把原图片的 `targetElementId` 或 `sourceTaskId` 写入新图锚点。新任务只共享当前提示词、模型、生成参数、参考图片与批次标识；每张新图拥有独立的锚点、批次序号和结果生命周期。

本次不新增数据库、持久化字段或迁移，不修改历史任务，也不回填历史生成数量。

## 性能与安全边界

- 复用现有批量工作流、批次标识和锚点布局，不新增图片副本、Base64 转换或额外文件读取。
- 只传递绑定目标元数据和数量判断，不缓存图片二进制，不创建 Object URL，不增加常驻监听器。
- 多图任务按既有独立锚点处理，避免共享可变目标状态或并发覆盖原图。
- 生成数量仍受现有 UI 选项和下游任务系统约束，本次不扩大并发上限。
- 不记录 API Key、完整上游响应或其他敏感数据。

绑定图片时，生成 `1个`仍原位替换；生成多个时保留原图，并按选择数量创建独立新图。
