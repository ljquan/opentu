# 主画布整合与工作流模式退役

## 当前效果

OpenTu 使用主画布承载创作，已删除独立工作流模式及其页面、专属配置/插件/Canvas Agent、资源和构建入口。主画布已有的提示词历史、素材库、模型渠道、逐目标输入草稿、引用、蒙版、再次生成和批量工具继续使用原实现。

主画布选中单张图片后，工具栏增加：

视角回填保留画布来源 ID。回填图片与当前选中或绑定图片的来源 ID、规范化地址及蒙版相同时，缩略图和生成参考列表仅保留一份；不同画布对象即使地址相同也不合并。视角指令保留为新的临时生成输入，不覆盖原图片草稿；移动鼠标或缩放画布不会丢失刚回填的内容，再次点击图片时恢复原有图片草稿。原草稿为空时，继续显示原生成提示词的复用提示，按空格或回车才填入原提示词。取消选择后，回填参考图仍保留在临时输入中。

弹窗和输入栏内的点击不会被判定为再次点击画布图片。本地缩放图片没有自身生成提示词时，使用已有 `localImageOperation.sourcePrompt` 显示原图提示词复用提示；图片自身明确记录的生成提示词优先。

- **编辑图片**：统一进入裁剪、拆分、滤镜和缩放，同一个窗口内切换；工具栏和工具栏设置不再提供独立的“手动拆图”或“本地放大”入口。在“拆分”中用百分比填写横纵分割线，多条用逗号分隔，清空某方向表示该方向不拆；预览显示分割位置和数量，点击顶部确认按钮后批量插入新图片，保留原图及来源关联。拆分始终使用原图，裁剪、旋转和滤镜编辑不会应用到拆分结果；切回其他工具保留已有编辑状态。插入失败时保留窗口和参数，可纠正后重试；插入期间禁止重复提交和切换工具。智能拆图仍使用原入口。
- **本地缩放**：位于“编辑图片 → 缩放”。可选择 0.25×、0.5×、1×、2×、4×，自动换算目标长边；也可直接输入像素，匹配预设时自动显示对应倍数，否则显示“自定义”。奇数尺寸按整数像素取整。目标长边小于原图时缩小像素，大于原图时放大；例如 4000×3000 缩到长边 2000，输出为 2000×1500。选择高质量、平滑或最近邻插值，查看输出宽高，点击顶部确认后保持比例并创建新图片；目标输出与原图像素相同时提示调整，避免重复创建。确认后依次显示“正在缩放图片”“正在保存并加入画布”，期间参数、关闭及工具切换禁用；成功后提示新图片的像素尺寸并选中新结果，原图保留。缩放始终使用原图，裁剪、旋转和滤镜不会混入缩放结果；切回其他页签保留缩放参数与既有编辑状态。进度条不表示百分比，不调用供应商，也不增加真实细节。新图片沿用画布统一显示尺寸；修改像素尺寸与画布上的显示大小、页面缩放分别控制。画板切换、源图删除/替换或编辑器卸载会使尚未写入的操作失效。详情中“本地缩放（非 AI）”显示源/输出像素和长边倍数，缩小到一半显示 0.5×。
- **AI 视角编辑**：填写水平、俯仰、距离和镜头设置。角度必须是有效数值，可填写负数和小数；相对拍摄距离必须大于 0，支持小数。字段无效时立即提示并禁用回填，空角度不自动转成 0；无效距离失焦后恢复上一次有效值。确认只将说明和原图填入既有生成输入栏；用户手动发送后才提交生成。预览是平面示意，模型实际是否正确生成新视角需要真实供应商验收。
- **图片工具栏设置**：在“设置 → 画布显示 → 图片工具栏”选择固定工具、是否显示工具文字，更改立即保存并更新工具栏。取消固定的工具仍可在图片工具栏的“更多图片工具”菜单访问；全部固定时隐藏更多按钮。沿用原有本地偏好配置，此配置仅影响单图片工具栏，不改变其他元素工具。

沿用原有图片加载和画布插入服务、错误提示、任务归属与画布保护。工具不静默调用生成 API，也不新增生成并发、重试和超时上限。较大本地图片和拆分数量受浏览器内存与 Canvas 能力限制，未进行压力验收。

裁剪、滤镜（含预设和原图对比）、拆分、本地放大和视角编辑的预览直接绘制已读取的原图，按比例适配窗口，避免重复加载缓存虚拟地址或已释放的临时地址。编辑器读图期间显示加载状态，失败时显示错误并禁用保存。裁剪和滤镜预览缓冲区长边最多 2048 像素，滤镜预设最多 96 像素；这仅限制预览缓冲区，输出处理继续使用完整原图，不使用预览缩略图。关闭预览时释放其 Canvas 缓冲区。

本地放大和视角编辑弹窗采用分区面板：宽屏左侧预览、右侧设置，700px 及以下改为上下排列。放大前后的尺寸单独对照；标题区提供关闭按钮，底部提供原图保留提示与操作按钮，处理期间关闭按钮同样禁用。拆分沿用图片编辑器的工具面板、预览和顶部确认按钮。配色、输入框焦点和按钮样式沿用各自既有样式。

本地放大结果的“图片详情”显示本地处理时间、处理方式、实际输出像素、原图像素、插值方式及长边放大倍数。原图元素已有提示词时记录为“原图提示词”；不会为本地处理伪造 AI 模型或生成记录。处理记录存入新图片元素的 `localImageOperation`，随画布数据保存和恢复。此记录不改变画布显示尺寸。更新前已生成且未保存处理记录的图片不能准确补回处理时间、源尺寸与插值方式，需要重新执行放大以记录。

手动放大完成后会选中新插入的结果图，因此工具栏详情对应放大结果及其处理记录；原图仍保留。AI 自动插入继续使用原有选择行为。

来源关联线使用柔和灰色平滑曲线，圆头圆角，线宽保持约 1.5 屏幕像素，避免缩小画布时细到难以辨认、放大后又过粗。线条从面向结果的图片侧边留少量间隙，水平伸出一小段后转弯，末端水平进入目标；上下排列且横向重叠的节点沿用上下连接。空间足够时，同一出点的分支共享 32 个画布单位的水平出线段，短间距按比例缩短。已有线条使用相同的 SVG 外观，保留原有持久化样式字段和锁定策略；解锁、单独删除与撤销/重做由独立 PR #318 提供。点击命中使用实际绘制曲线的采样与 Plait 原有容差，与 #318 合入后共享。来源关系、各自的关联数据和跟随移动行为保留；普通手绘线条不受影响。此基础版没有增加全局避障布局。任务进行中主动删线后，后续异步任务确认仍可能按既有规则补线，未增加永久禁止补线标记。

底部输入栏“我的提示词”快捷菜单只插入正文：输入为空时填入，已有正文时在末尾追加（末尾没有空白时先换行）。保留当前参考图片、上传图片及蒙版、画布引用、知识上下文和生成模式/模型参数，不再弹出覆盖确认或根据历史类型切换模式。点击浮层保持画布选中状态；选择后回到输入栏继续编辑，仍需手动发送。若要替换全文，可先清空正文再选择。

普通图片生成按来源排列：

- 使用画布图片时保留原图及位置，新结果出现在全部实际参考图的右侧，并连接每张来源；即使两张画布图片共用同一地址，也按各自元素 ID 保留两条来源线。图片的横竖比例不再决定方向。普通单图生成也创建新结果，明确的语义主体替换与画框内生成沿用专门流程。
- 上传或粘贴的参考图在点击发送、输入和凭据准备通过后才加入画布。已有画布图片直接复用；同一上传地址再次发送或恢复画布后复用已有来源，不重复插入。混合来源时，新参考图排在已有来源下方，结果位于来源整体右侧。
- 同来源再次生成在右侧同一列向下排列；使用结果图继续生成才延伸下一列。没有图片参考的独立创作在来源主列向下新增，不受无关选中项或远处派生图片影响。
- 一次多图预先保留各自位置和连线，完成顺序不改变排列。占位预留结果最大显示范围，避免自动比例图片完成后压住相邻任务。重试使用原来的占位和来源；用户主动移动占位时沿用其位置。

参考图会先全部读取与缓存，成功且画板未切换才统一插入；任意图片失败、来源在准备时被删除/修改或画板切换均中止提交并保留输入。参考图已落到画布后若供应商生成失败，保留这些来源以供重试。来源去重按规范化地址/持久摘要和画布元素身份识别；不同地址但内容相同的独立文件不承诺合并。上述自动布局应用于主输入栏普通图片生成，其他媒体、Agent/Skill、自定义画框和显式替换入口保持原有语义。

生成占位的“正在显现”阶段以本次插入图片实际加载完成为准，不等待同一历史任务的其他旧副本；本次多图结果仍需全部加载。浏览器已解码的缓存图片即使没有新的 load 事件，也会根据当前图片的完成状态确认就绪。历史预览可见本身不作为画布原图加载成功的依据。

## 旧数据保留与恢复

旧 `/workflow` 和深层链接进入主画布并打开“备份 / 恢复 → 旧工作流数据”；类似 `/workflower` 的路径不会被归一化。该入口按需加载兼容模块，不加载旧应用。

1. 使用原浏览器、原站点来源打开数据入口，点击“读取旧数据”；也可打开本次格式的 `opentu-legacy-canvas.zip`。其他来源、浏览器或设备的本地数据不会自动出现。
2. 优先“导出去凭据备份”，保存清单与可用本地媒体；配置、JSON 字符串及常见 URL 认证字段经过脱敏，插件源码和非媒体二进制不纳入普通备份。原数据库始终保留。
3. 点击“将可转换内容导入主画布”，创建新画布和可转换素材，文本素材与缓存提示词进入提示词历史。重复操作会创建新画布，不覆盖原有画布；素材和提示词采用既有规则。
4. 保留、下载转换报告。失败项目不以部分元素写入；后续写入失败时报告此前成功内容，当前新画布尝试回滚，源库不变。

图片、文本、视频、音频尽量保留坐标、尺寸和提示词，直接资源连接转换为主画布来源关联线。配置节点、分组、插件、聊天、历史任务和多图槽位原始资料留在备份；不会恢复旧执行语义，多图节点目前转换主图。未知版本可导出但拒绝转换。过期 blob/远程媒体没有本地文件时只报告缺失，不自动下载。

不自动导入旧渠道或 Key，不猜测同名模型映射，不重发在途生成。主画布共享任务系统仍按原契约查询其已有任务；专属旧任务仅作为资料，未承诺可继续查询或完成。

普通备份是业务数据恢复资料，不是旧执行环境快照；源数据库和敏感配置保留于原浏览器。兼容入口不提供清空旧数据库按钮。

## 维护边界

- 已删除 `packages/drawnix/src/workflow-mode/` 与模式专用脚本、资源插件、别名、测试命令及独占依赖。
- 保留 `WorkflowEngine`、`WorkflowContext`、workflow 提交/完成服务、SW 通信、Agent、视频/MV 及主画布相关工具。它们不是独立工作流模式，不能按名字批量删除。
- 数据兼容位于 `services/backup-restore/legacy-canvas-data.ts`，只读旧数据库和显式创建主画布记录，不承担生成或插件运行。
- 回滚代码可恢复旧界面；当前实现不改写旧源库。已经导入的新画布属于新的主画布数据，回滚代码不自动撤销这些用户操作。
- 无新增服务器、环境变量、数据库版本迁移或部署顺序。重新安装依赖使用更新后的锁文件；无需重建旧工作流资源。

验证范围见 [QA](./qa-canvas-consolidation.md)。
