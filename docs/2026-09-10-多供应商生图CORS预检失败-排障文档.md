# 多供应商生图 CORS 预检失败排障经验

更新日期：2026-09-14

## 典型现象

浏览器图片请求只显示 `Failed to fetch`，而 curl 可以访问接口。这通常说明正式 POST 之前的 CORS 预检失败，不能直接归因于模型、提示词或 HTTP 500。

加入 `X-Request-Id` 后，浏览器会在 `OPTIONS` 中声明：

```text
Access-Control-Request-Headers: authorization,content-type,x-request-id
```

目标节点必须在 `Access-Control-Allow-Headers` 中明确放行该头。

## 当前可信节点边界

可信 Tuzi 节点与 Request-ID-CORS 兼容节点必须分开维护。

已验证允许 `X-Request-Id`：

- `bus.tu-zi.com`
- `bus2.tu-zi.com`
- `bus3.tu-zi.com`
- `business.tu-zi.com`

六个普通可信节点为 `api.tu-zi.com`、`apius.tu-zi.com`、`apicdn.tu-zi.com`、`api.sydney-ai.com`、`api.ourzhishi.top`、`apisz.ourzhishi.top`。当前所有图片请求均直连用户配置节点；这些普通节点的同步图片 `POST` 不附加 `X-Request-Id`，避免因该自定义头触发不兼容的 CORS 预检。
Request-ID-CORS 节点不得混入普通请求的全局备用列表，避免改变其他接口路由。

## 修复原则

- 自定义头必须由共享 provider transport 统一判断，不能散落在各 adapter。
- 六个普通可信节点和 Request-ID-CORS 兼容节点均直接请求用户配置地址，不再经过 `/__opentu_tuzi_proxy__/`；仅兼容节点附加 `X-Request-Id`。
- 正式 `POST` 前仍持久化 `submissionRequestId`、提交标记和调用路由。传输层不会因网络模糊失败或 HTTP 错误自动重提正式 POST；结果未知或页面刷新后，以同一 ID 对原节点执行只读轮询。明确 `model_not_found` 后的既有模型别名纠正单独处理。
- 只读恢复 GET 不携带 Request ID，故障后只在下一轮查询原配置节点。
- 绝对第三方 URL、非可信供应商不得收到任务 ID 或 Tuzi 凭据。
- 本地、局域网、`opentu.ai`、`pr.opentu.ai`、Vercel、Netlify 和自托管页面使用同一图片直连规则。
- 图片代理的 Vite、Vercel、Netlify 与 Nginx 部署配置已移除；账户接口 `/__opentu_tuzi_session__/` 同源代理继续保留，与图片路由无关。

## 排障顺序

1. 用无自定义头请求验证 Base URL、Token、模型和请求体。
2. 单独检查带 `x-request-id` 的 OPTIONS。
3. 在浏览器 Network 中确认图片 `POST` 和恢复 `GET` 的最终 Request URL 均为用户配置节点，不应命中 `/__opentu_tuzi_proxy__/`。
4. 普通六节点确认正式 `POST` 不含 `X-Request-Id`；兼容节点确认该头与持久化 Request ID 完全一致。
5. 区分请求头 `X-Request-Id` 与响应头 `X-Oneapi-Request-Id`。
6. 确认网络结果不明后没有向原节点或其他节点发送第二个图片 POST，只有原节点只读结果查询。
7. 刷新恢复场景另行确认结果 GET 不携带 Request ID。
8. 普通节点刷新后能发出 `GET .../result?request_id=...` 即满足客户端行为；由于提交未携带请求头，上游是否能关联结果需单独验收，不能仅凭轮询发出宣称恢复成功。

## 安全与性能

- 不记录或持久化 API Key 副本。
- 不把 Request ID 发送到不可信地址。
- 不用健康请求并行轮询来掩盖 CORS 问题。
- 轮询必须有并发上限、超时、退避、响应体限制和资源清理。

## 能力边界

Request-ID-CORS 兼容节点可在提交时收到 `X-Request-Id`，具备按该 ID 关联刷新恢复链路的条件。六个普通节点只保证本地保存 `submissionRequestId` 并在刷新后继续发送结果查询；如果上游没有其他关联机制，查询可能持续返回 `processing_or_not_found`，客户端不会为此重新提交图片 `POST`。
