# AI 生成素材导入修复交接文档

**日期**：2026-08-06

**适用分支**：`codex/fix-generated-asset-import-pr`

**基线**：`origin/develop` `ad4d0851`

**关联 QA**：[AI 生成素材导入修复人工测试文档](../qa/2026-08-06-AI生成素材导入修复-人工测试文档.md)

## 问题

AI 图片生成完成后，素材库可以显示新图片，但在以下两个入口选择同一素材时会提示“加载图片失败”，参考图保持为空：

1. AI 图片生成窗口的“参考图片”；
2. AI 视频生成窗口的首帧、尾帧或参考图片。

问题在局域网 HTTP 页面稳定出现，AI 生图和 AI 视频共用的素材选择组件同时受影响。

## 复现条件与路径

### 条件

- 页面运行于局域网 HTTP 环境，无 Service Worker 和 Cache Storage 能力；
- 素材库中存在当天生成的 AI 图片；
- 生成结果只保留 `apioss*.sydney-ai.com` 远程 URL，IndexedDB 的 `media-blobs` 中没有对应 Blob。

### 路径

1. 使用 `gpt-image-2` 完成一次图片生成；
2. 打开 AI 图片生成窗口，在“参考图片”中点击“素材库”；
3. 选择刚生成的图片并点击“使用”；
4. 在 AI 视频生成窗口对首帧图片重复相同步骤。

**原实际结果**：两个窗口均提示“加载图片失败”，参考图为空。

**预期结果**：新生成图片显示为参考图，并可继续提交生成。

## 根因

调用链为：

```text
生成任务完成
  -> 缓存远程结果失败后保留远程 URL
  -> AssetContext 仍将已完成任务展示为素材
  -> ReferenceImageUpload 选择素材
  -> 浏览器读取远程响应体失败
  -> 显示“加载图片失败”
```

根因由三部分共同构成：

1. CDN 响应包含重复的 `Access-Control-Allow-Origin: *`，浏览器判定 CORS 响应无效；
2. `<img>` 可以跨域展示该图片，但 `fetch` 无法读取响应体，因此“素材库能看见”不代表“素材内容可转为 Base64”；
3. 远程缓存失败时任务仍保留远程 URL，原组件却要求素材必须能被浏览器读取为 Blob。

局域网无 Cache API 时，原缓存状态检查还会把“只有元数据、没有 Blob”误判为已缓存，进一步掩盖数据状态。

## 最终行为

- 素材选择优先从统一缓存服务读取 Blob；读取成功时继续校验非空内容、图片 MIME 和 25MB 上限。
- 虚拟缓存 URL 缺 Blob 或返回零字节 Blob 时继续明确失败，不生成空 data URL。
- 只有同时满足以下条件的素材，才允许在 Blob 不可读时保留远程 URL：
  - URL 为 HTTP(S)；
  - 来源为 `AI_GENERATED`；
  - 类型为 `IMAGE`；
  - MIME 为空或属于 `image/*`。
- Tuzi GPT 图片 JSON schema 支持直接传入远程参考图 URL，不再强制由浏览器读取后转 Base64。
- AI 视频保持既有远程图片 URL 提交语义，并将共享组件的加载错误同步到窗口错误区。
- 批量选择部分失败时保留成功素材，同时显示加载失败；全部失败时不再错误清空提示。
- 局域网无 Cache API 或 Cache API 访问失败时，缓存状态以 IndexedDB 中是否存在真实 Blob 为准。

## 关键实现

- `packages/drawnix/src/components/ttd-dialog/shared/ReferenceImageUpload.tsx`
  - 统一读取缓存 Blob；校验空内容与 MIME；收紧远程 AI 图片 URL 回退条件；保留批量失败提示。
- `packages/drawnix/src/components/ttd-dialog/ai-video-generation.tsx`
  - 将参考图加载错误接入视频窗口现有错误状态。
- `packages/drawnix/src/services/media-executor/fallback-adapter-routes.ts`
  - 对支持远程图片的 Tuzi GPT JSON schema 直接透传 HTTP(S) 参考图。
- `packages/drawnix/src/services/unified-cache-service.ts`
  - LAN 无 Cache API 时检查 IndexedDB Blob 实体，不再仅凭元数据判定缓存成功。
- `packages/drawnix/src/components/ttd-dialog/shared/ReferenceImageUpload.test.tsx`
- `packages/drawnix/src/services/unified-cache-service.test.ts`
- `packages/drawnix/src/services/__tests__/media-executor.test.ts`
  - 覆盖缓存命中、远程 URL、非图片响应、缓存缺失、零字节 Blob、LAN 缓存状态和供应商透传。

## 性能与安全边界

- 未恢复默认 `b64_json` 响应，避免 Base64 带来的额外响应体积和内存占用。
- 未使用缩略图代替原图，不会静默降低参考图质量。
- 未新增 Blob 副本、Object URL、常驻监听器、轮询、数据库表或迁移。
- 远程回退不是无条件兜底；本地素材、虚拟缓存素材、视频素材和非图片 MIME 均不能进入该路径。
- 日志与文档不记录完整签名 URL、API Key、Cookie 或鉴权头。

## 剩余风险

- CDN 重复 CORS 响应头仍存在，浏览器会记录预期的网络读取失败；本次修复不修改外部 CDN 配置。
- 未执行真实供应商生成，因此供应商最终接受远程参考图 URL 的完整端到端结果仍需在发布前按关联 QA 验收。
- 非 Tuzi GPT JSON schema 的图片适配器继续遵循既有 Base64 语义，不在本次范围内改变。

## 一句话结论

素材库现在能把只有远程 URL、没有本地 Blob 的新生成图片正确带入 AI 生图和 AI 视频参考图表单，同时继续拒绝损坏或类型不符的缓存内容。
