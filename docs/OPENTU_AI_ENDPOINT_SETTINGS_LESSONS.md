# OpenTu AI 网页版端点设置经验

更新日期：2026-06-15

## 背景

OpenTu AI 网页版的文本模型和生图模型会走不同供应商端点。用户希望在应用菜单的设置里直接管理站点端点：默认由系统选择最优路径，同时保留手动选择能力。

这次最终形态是：在“应用菜单 → 设置 → 供应商 → API 地址”下方新增端点管理面板，和供应商配置放在同一个上下文中。

## 问题表现

- 用户需要的是站点端点，不是画布节点；端点管理应该落在设置页的供应商配置区域。
- 文本和生图都需要默认自动选择最优端点，同时保留用户手动覆盖能力。
- 端点列表不能由前端临时硬编码，否则来源不可追溯，也无法跟随上游端点配置维护更新。

## 架构变更

- 设置页新增端点管理面板，挂在当前供应商的 `baseUrl` 字段下。
- 端点来源改为读取 [tuziapi/tuzi-api](https://github.com/tuziapi/tuzi-api) 的 `https://api.tu-zi.com/api/status`。
- 解析 `data.api_address_list` 中的 `name`、`url`、`description`，并只展示 tuzi-api 配置的站点端点。
- 默认保持自动选择模式，测速后选择延迟最低的端点。
- 用户手动选择端点时，切换为手动模式并写入当前供应商草稿的 `baseUrl`。
- 自定义端点只保存在当前设置会话中，避免污染上游来源。
- 底部 AI 输入栏保持模型、参数和提交职责，不承载站点端点管理面板。

## 经验规则

- 端点管理属于供应商配置，不属于输入栏快捷控件。
- 站点来源必须能追溯到上游配置，避免在业务组件中维护一份隐形列表。
- 自动选择应该是默认路径，手动选择只作为用户显式覆盖。
- 端点选择最终要落到 `ProviderProfile.baseUrl`，不要额外引入平行配置源。
- 测速失败不能阻塞设置保存；失败只影响排序和提示。
- 输入栏可以展示自动路由后的模型，但不要承载端点配置面板。

## 验证

- 设置页打开后能显示 `tuzi-api` 来源和端点数量。
- 选择端点会更新当前供应商 API 地址。
- 勾选自动选择后，测速完成会切到最快端点。
- 添加自定义端点后可立即选择，且可删除。
- 底部 AI 输入栏保持模型、参数和提交职责，不承载端点管理控件。
- `pnpm nx run web:typecheck` 通过。
- `git diff --check` 通过。
