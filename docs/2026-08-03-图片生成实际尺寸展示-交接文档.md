# 图片生成结果实际尺寸展示经验

更新日期：2026-08-03

## 背景

图片任务曾使用请求参数或缩略图加载结果推断尺寸，可能出现请求条件为竖图、任务栏却显示 `1024×1024`，而上游最终图片实际为 `1024×1536` 的情况。比例文案也无法表达上游最终文件的真实像素尺寸。

本功能统一以“上游最终图片”为准，在任务列表中显示 `宽×高`，例如 `1024×1536`，不再显示 `1:1`、`2:3` 等比例文案。

## 最终行为

- 已完成图片任务显示上游最终结果的实际像素尺寸。
- 尺寸格式固定为 `宽×高`，乘号使用 `×`。
- 不使用请求参数、请求比例或预设分辨率补齐结果尺寸。
- 上游响应没有尺寸元数据时，读取最终图片本身的真实像素宽高。
- 元数据和最终图片都无法提供有效宽高时，显示“未知尺寸”。
- 批量生成按每个图片任务独立记录尺寸，允许同一批次返回不同尺寸。
- 缩略图使用完整展示方式，不裁剪、不拉伸；图片悬停时不再放大。
- 不追溯补写历史任务；旧任务没有结果宽高时仍可显示“未知尺寸”。

## 尺寸来源优先级

尺寸只按以下顺序解析：

1. 使用上游单张图片结果中的 `width`、`height`。
2. 兼容数字字符串形式的 `width`、`height`。
3. 兼容上游单张结果或响应公共字段中的 `size: "1024x1536"`。
4. 上述元数据缺失时，加载上游最终图片 URL 或图片数据并读取真实像素宽高。
5. 无法取得有效结果时返回“未知尺寸”。

请求中的 `size`、`width`、`height` 和比例参数不参与结果尺寸兜底，避免把“想要的尺寸”误报为“实际生成尺寸”。

## 数据流

1. GPT Image 或 Tuzi GPT Image 适配器接收上游响应。
2. 响应解析器逐张读取图片 URL、Base64 数据及可用尺寸元数据。
3. 元数据缺失时，在有界时间内读取最终图片的真实像素尺寸。
4. `generation-api-service` 或降级执行链把宽高写入任务结果。
5. 任务持久化保留 `result.width` 和 `result.height`。
6. 任务列表只格式化结果宽高；缺失时显示“未知尺寸”。

## 性能与安全边界

- 优先读取轻量响应元数据，存在有效宽高时不再加载图片解析尺寸。
- 元数据缺失时复用浏览器图片加载能力，不创建 Canvas、不重编码图片、不复制完整像素缓冲区。
- 最终图片尺寸读取有 15 秒上限，并响应任务取消信号，避免长期挂起。
- 每张批量图片独立解析，不共享或覆盖其他任务的尺寸。
- 不新增持久化实体，不保存完整上游响应、API Key 或图片二进制副本。
- 尺寸解析失败只影响尺寸文案，不修改图片内容、任务图片 URL 或插入行为。

## 一句话结论

任务栏展示的是上游最终图片真实像素尺寸，而不是请求比例、请求预设或缩略图容器尺寸。
