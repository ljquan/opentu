# 模型分类优先级经验

更新日期：2026-10-19

## 背景

模型列表接口新增了 `category` 字段，但它不是必填项。同时，很多图片模型也会暴露 `openai-video`、`video-generation` 之类的异步或兼容端点。

如果仍然只按 `supported_endpoint_types` 或 `id` 猜类型，就很容易把图片模型误判成视频模型。

## 问题表现

- `gpt-4o-image-async`、`gpt-image-*` 这类图片模型，因为带了 `openai-video`，被错分到视频。
- 旧的静态模型配置命中后，运行时接口返回的 `category` 没有机会修正类型。
- `category` 出现 `生图`、`文本`、`研究` 这类业务值时，如果不做归一化，分类会漂。

## 修复思路

- `category` 存在时优先使用。
- 归一化常见值：
  - `生图`、`图片`、`图像`、`绘图`、`image` -> `image`
  - `视频`、`video` -> `video`
  - `文本`、`研究`、`chat`、`text` -> `text`
  - `音频`、`音乐`、`voice`、`audio` -> `audio`
- 原样分别保存模型广场的 `category` 与 `tags`，不要再使用 `category || tags` 混填。`category` 缺失时，先读取原始标签；两者都缺少时才回退到 `id`、endpoint hint、vendor 的旧推断逻辑。
- 模型广场的 `tags` 按分隔符拆分并精确匹配。“生图”用于图片生成，“图片”“图像”“多模态”不授予生图能力；“非生图”也不能通过子串匹配误中。
- 混合标签先识别明确生成标签，再识别文本、推理、代码等标签，最后识别独立的视频、音频标签。未识别的非空标签保守归为文本，不因模型名字含 `image` 就授予生图能力。原有 GPT Image / Nano Banana 静态保护规则不变。
- `文本,图像,代码,推理` 按文本处理；`文本,生图` 仍按图片处理。不要仅凭支持图片输入就将模型加入生图列表。
- 只要 `id` 命中 `image`，就应先保住图片归类，不要被视频端点抢走。
- 静态配置如果被接口 `category` 明确覆盖，要同步清理不匹配的默认参数，避免图片模型挂着视频默认值。

## 经验规则

- 有 `category`，先信 `category`。
- 模型 ID 中有 `image` 时保留原有图片回退规则；能力标签中的 `image` 不代表具备生图输出。
- 图片模型同时支持视频端点，不等于视频模型。
- `category` 是分类信号，不是装饰字段；接口给了就该进判定链路。
- 标签与分类是不同字段，先保留源数据语义，不要只调整判定顺序或新增模型 ID 特例。
- 已标记为模型广场来源的自动目录，重新加载时可使用同一供应商已有价格缓存中的分类元数据纠错，不发起网络请求、不重选模型。手工模型和其他来源目录不受此纠错影响；缺少缓存时通过“获取模型”更新。
- 旧缓存仍兼容原分类字段，但旧版本混填的字段无法完整还原原始标签。需要精确标签规则时，在设置中获取一次模型更新元数据，后续复用缓存，无需清空数据。
