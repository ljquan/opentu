# AI 生图、批量生图与视频结果无法渲染修复交接文档

**日期**：2026-09-07

**适用范围**：包含本次修复的 `develop` 派生分支

**关联 QA**：[AI 生图、批量生图与视频结果无法渲染人工测试文档](../qa/2026-09-07-AI生图批量生图与视频无法渲染-人工测试文档.md)

## 问题概述

AI 生图、批量生图和视频生成任务可能已经显示“完成”，但结果在任务队列、批量预览、素材库或画布中显示为空白、破图或无法播放。

这不是单一供应商问题，常见触发条件包括：

- 一个任务返回 `result.urls[]`，界面仍只读取 `result.url`。
- 远程签名 URL 过期、缓存失败或历史缓存体实际是 HTML/JSON 错误响应。
- 视频 Service Worker 使用去掉签名参数后的规范化 URL 发起真实请求，导致 CDN 返回 403。
- 缓存失败被当成任务失败，导致已生成结果无法进入完成态。

## 根因与修复

### 1. 批量任务只展示单张结果

批量生图任务的结果模型同时支持 `url` 和 `urls`。旧展示代码只读取单个 `url`，因此多结果任务会出现数量不一致、预览缺图、下载/导出漏图。

当前修复在批量预览、部分完成预览、画廊、Excel 导出和批量下载入口统一展开 `result.urls[]`，并对旧数据回退到 `result.url`。同一任务的多个结果使用 `taskId:resultIndex` 作为 React key，避免节点复用导致的错图。

### 2. 错误响应被当成媒体缓存

部分上游会返回 HTTP `200`，但响应体实际是登录页、网关 HTML 或 JSON 错误对象。仅检查状态码和 Blob 非空会把这些内容写入图片/视频缓存，后续 `<img>` 或 `<video>` 自然无法解码。

当前缓存层在写入前执行有限前缀校验：

- 校验 `Content-Type` 与目标媒体类型是否匹配。
- 图片识别 PNG、JPEG、GIF、WebP、BMP、TIFF、AVIF/HEIC、SVG 等签名。
- 视频识别 MP4/ISO BMFF、WebM、AVI、Ogg、MPEG 等签名。
- 只读取最多 64 字节，不额外复制完整媒体 Blob。
- 历史坏缓存会被跳过并重新拉取源地址。

### 3. 缓存失败阻断任务完成

浏览器缓存受 CORS、opaque response、签名有效期、存储配额和局域网运行环境影响。缓存只是结果的持久化增强层，不应替代生成任务本身的成功状态。

当前采用方案 A：

1. 缓存成功时返回稳定的 `/__aitu_cache__/...` 地址，供任务队列、画布和刷新恢复使用。
2. 缓存失败时保留原始远程 URL，任务仍标记为完成。
3. 同时在任务结果写入 `cacheWarning`，由任务队列或素材库提示用户尽快下载。
4. 不因一次缓存失败自动清理其他媒体缓存。

该逻辑已覆盖图片、多图片、视频主执行、adapter 路径、旧 fallback 路径和恢复轮询路径。

### 4. 视频签名参数被错误移除

Service Worker 可以使用规范化 URL 作为缓存键和并发去重键，但真实下载必须使用包含 `signature`、`token`、`x-amz-*` 等鉴权参数的原始 URL。当前已分离这两个用途，避免签名 CDN 请求被改写为无效地址后返回 403。

## 交互边界

### 2026-09-29 补充：Seedance 2 内容交付与画布回退

Seedance 2 adapter 原先优先返回内联 URL，跳过了绑定配置中的
`resultMode: download-content`。本次复现的 OSS 结果以 attachment 强制下载，
Chrome 原生 video 报 Format error；同一文件从本地普通 MP4 响应加载成功
（1280×720，4.064 秒）。缺少 CORS 响应头也会阻断前端直接 fetch 缓存。

adapter 现在遵守已有下载配置，即使结果含 URL，仍通过当前供应商的
`/videos/{taskId}/content` 下载并写入本地缓存；未配置强制下载且有内联
URL 的绑定保留直链行为。内容下载沿用 `context.fetcher`，未传入时仍使用
全局 fetch；HTTP 失败保留结构化状态码，原错误消息保持兼容。

内容交付单独限为最多 3 次请求（首次加 2 次重试，间隔 1 秒、2 秒），
仅重试 HTTP 408/425/429/5xx、网络 TypeError、NetworkError 和 TimeoutError。
其他 HTTP 错误、空内容或取消立即退出；AbortSignal 同时传递到下载请求和
重试等待。下载耗尽后报错，不返回轮询循环，也不重新提交生成请求。
这避免了成功轮询不断重置错误计数；长期失败仍需找回已完成任务，普通
任务“重试”仍可能重新生成，未在本次调整。不新增代理端点。

画布播放器在虚拟缓存地址加载失败时，按需读取已有本地 Blob 播放，
不发起网络重试。换源重置错误状态，卸载时忽略过期读取并释放 Blob URL。
这只能修复本地仍保存了 Blob 的记录，不能为已有 OSS 直链自动补齐缓存。

历史任务未迁移，用户 7202 页面中的实际任务地址尚未核实；真实带鉴权
内容下载端点未联调。本地仓库中的 Tuzi 实现提供该端点，但不能据此确认
当前线上版本对这条任务的行为。具体验证及限制见关联 QA 的同日补充。

- 本次修复包含多结果展示、缓存有效性、缓存失败降级和视频签名 URL 修复。
- “删除单张结果，最后一张才删除整个任务记录”尚未在本轮实现，现有删除按钮仍按任务记录删除。
- 真实供应商短任务、签名 URL 过期、无 Service Worker 的 LAN 环境仍需按关联 QA 完成人工验收。

## 一句话结论

任务完成状态与缓存状态已解耦，多结果不再漏渲染，坏响应不会进入媒体缓存，视频真实请求保留签名参数；缓存失败时仍保留原始 URL，不再把可交付结果误判为任务失败。
