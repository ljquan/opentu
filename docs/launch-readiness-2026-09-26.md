# FoxVue 上线准备状态（2026-09-26）

目标：面向公网的多用户企业服务。当前状态：代码和发布链路预备中，**尚未达到开放注册和真实生成的上线门槛**。

## 本轮完成

- 发布标签现在分别构建 Web 与 API 镜像；Web 构建固定开启服务端模型目录与托管生成，Nginx 将同源 `/api/` 转发到 API。
- Docker Compose 从同一源码目录构建两个镜像，等待 API 健康后启动 Web，运行时密钥只从服务器环境文件加载。
- 创作中心在托管模式只展示网关支持的 `1:1`、标准质量和无参考图选项；进入画布时将比例转换为服务端要求的 `1024x1024`。
- 画布新建图片任务实际使用的主线程执行器已接入服务端任务网关；托管模式不再要求浏览器供应商 Key。视频、音乐和其它未迁移任务在托管模式阻止浏览器供应商适配器调用。
- 修正启动包校验器，使其识别 Vite 产物的绝对 `/assets/` 路径。
- 补齐旧切换脚本引用的公网反代和维护文件；切换脚本需在实际服务器布局中另行演练。

## 上线阻断项

1. 用真实 PostgreSQL 在隔离环境执行迁移，验证注册、登录、改密、退出、管理员权限和跨用户数据隔离。当前开发机无数据库连接，单元测试不能替代该验收。
2. 配置正式域名、有效 HTTPS 证书与备案/接入要求；设置 `BETTER_AUTH_URL` 为真实公网 origin。当前 IP 证书和旧代理文件不能作为正式域名方案。
3. 在服务器运行 `pnpm check:production-config`，检查 `/etc/opentu/runtime.env`，再构建和启动 Compose；本机无 Docker CLI，镜像未在本轮实构建。
4. 保持 `OPENTU_PUBLIC_GENERATION_ENABLED=false`，直到管理员保存/测试供应商、同步并上架明确模型，配置供应商侧硬预算与白名单，并使用真实账户验证画布新建图片生成、取消、幂等重试、刷新恢复和费用控制。新建任务与恢复任务走不同前端执行路径，必须分别验收。
5. 视频和音乐目前仅能浏览/管理已有内容；需要服务端持久任务执行、结果存储和调用预算后才能开放生成。
6. 完成备份与恢复演练、健康监控和告警、限流/并发压力测试，并收紧生产 CSP 的宽泛外部来源和 `unsafe-eval` 后做兼容性回归。
7. `pnpm audit --prod` 当前报告 23 条告警（1 严重、13 高、7 中、2 低）。多数高危路径经 `better-auth > vitest`，需核实最终 API 镜像是否包含或执行该测试工具；`pptxgenjs > image-size@1.2.1` 的图片解析拒绝服务告警与导出功能相关，需在兼容性测试后升级或限制输入格式。审计未清零前不得把依赖安全标为已验收。

## 最小验收顺序

1. 在测试库迁移和备份恢复演练后，以最小权限应用账号运行 API；`/api/health` 必须为 200。
2. 使用正式 HTTPS origin，在桌面和手机浏览器走完注册、登录、管理员模型配置与普通用户图片任务，检查网络面板没有供应商密钥或浏览器直连生成请求。
3. 验证匿名、普通用户和管理员的权限边界及跨用户访问拒绝；验证任务取消、失败重试和刷新恢复。
4. 完成 Nginx 与 Docker 切换/回滚演练，再决定是否打开公开注册与图片生成；视频、音乐继续关闭。

Compose 文件位于源码树的 `docker/opentu/compose.yml`，默认以源码构建 `opentu-web:local` 和 `opentu-api:local`。使用标签发布的镜像时，分别设置 `OPENTU_WEB_IMAGE`、`OPENTU_API_IMAGE` 为同一版本号的镜像地址，并使用 `docker compose up -d --no-build`；不要混用两个版本。`cutover.sh` / `rollback.sh` 只适用于已存在旧 systemd 服务和旧 Nginx 配置的服务器，首次部署需单独配置公网代理与回滚方案。

本轮本地验证：Web/API 类型检查通过，Web 54 项与 API 94 项测试通过，浏览器导航 smoke 2 项通过，生产 Web 构建与启动包门禁通过。镜像构建、真实账户/模型/数据库联调仍未验证。

## 2026-09-27 增量检查

- 修复 CI 和标签发布流水线的 Nx 项目筛选参数。原 `--projects=api,web` 在本机返回退出码 0，但实际执行 0 个项目；现用 `--projects api web`，已确认实际执行两个项目的类型检查。发布校验的测试和 lint 也使用同一写法。
- 生产配置检查现在要求 `OPENTU_AUTH_MODE=local` 和 `OPENTU_TRUST_PROXY=true`。前者避免意外退回外部账户体系；后者使可信公网反代传递的客户端 IP 可用于账户限流。部署时公网反代必须覆盖 `X-Real-IP`，API 仍只能监听回环地址。
- 写接口同源校验在生产环境要求 HTTPS `Origin`，独立账户模式还会与配置的 `BETTER_AUTH_URL` 完整 origin 对比。
- Docker 构建上下文排除本地旧发布包、视觉验收截图及设计输出；仅旧发布包和设计输出在本机就超过 350 MB，且不应进入镜像构建器。
- 发布流水线新增托管画布生成契约测试（3 项），要求使用与生产构建相同的 `VITE_OPENTU_MANAGED_GENERATION=true`。本机验证：API 95 项、Web 54 项测试通过；API/Web 类型检查和 lint 通过（Web 尚有 101 条存量警告）；6 条 Playwright smoke 通过；托管模式生产 Web 构建、启动包验证及 API bundle 构建通过。生产镜像仍未实构建，本机没有 Docker 和 PostgreSQL 客户端。
- `pnpm audit --prod --registry=https://registry.npmjs.org` 仍有 23 条告警。当前 API 单文件 bundle 不包含 `vitest`、`rollup`、`image-size` 或 `pptxgenjs` 字符串，不能因此断言 Web 导出功能没有风险；`image-size` 的 PPTX 依赖路径仍需升级与导出回归。

新增上线门槛：公开注册前实现并验收邮箱归属验证、找回密码、滥用防护和相应邮件服务。当前独立账户仅覆盖邮箱密码注册、登录、登出和改密，不应把它描述为完整的公网账户生命周期。服务器环境仍需完成真实数据库迁移、跨用户隔离、供应商任务、备份恢复及 Docker 切换演练；在此之前保持公开生成关闭。
