# 默认模型目录与 Seedance 2.0 接入交接文档

更新日期：2026-08-05

## 背景

默认模型入口需要与模型广场当前已开放的模型保持一致：补充 GPT-5.6、DeepSeek V4 与 Seedance 2.0 系列，同时将 GPT-5.4 及以下旧 GPT 入口从默认列表隐藏。旧模型只隐藏，不删除配置、价格、渠道或历史引用。

Seedance 2.0 使用统一 `/v1/videos` JSON 异步任务接口，不能复用 Seedance 1.x 的表单请求和旧模型名转换，因此本次单独增加 2.0 适配器、参数控件和后端透传。

## 目标行为与当前范围

- 默认入口新增 9 个模型，按统一推荐分和版本规则优先展示，并显示 `NEW`。
- GPT-5.4 及以下 18 个旧 GPT 入口只从 `default` 展示列表隐藏。
- `gpt-5.5` 保留在默认列表。
- 隐藏模型仍可解析历史会话、已保存模型和固定选择；保留对应能力的非 `default` 分组或供应商 Profile 仍可显式调用。
- 非默认供应商 Profile 的模型目录不套用默认隐藏规则。
- 新模型立即进入 `default` 可选目录，不增加灰度或额外权限开关；实际调用仍取决于 Token 分组、可用渠道、价格配置和上游能力。
- 模型名称、内部调用 ID、价格和可用路由以模型广场数据为准。

## 目录与价格数据流

1. tuzi-api 读取模型广场当前的根级 `data`、`group_info`、`vendors` 和 `group_model_pricing`。
2. 对 9 个新增模型补充 `default` 展示归属；缺少 `default` 价格时，按 `原价分组`、`官方优惠`、`Codex`、其它可用分组字典序的优先级复制对应 endpoint 价格。
3. 旧 GPT 的模型元数据、底层价格配置和非 `default` 渠道能力继续保留，只从 `default` 可见/可调用分组视图移除。
4. OpenTu 将静态展示元数据与运行时模型发现结果合并，并按模型 ID 去重、按统一排序规则展示。
5. 默认 Profile 过滤旧入口；固定模型和历史选择仍通过静态模型解析恢复。

默认组没有直接渠道时，路由按以下顺序回退：

| 模型系列     | 路由来源顺序                        |
| ------------ | ----------------------------------- |
| GPT-5.6      | `原价分组` -> `官方优惠` -> `Codex` |
| DeepSeek V4  | `原价分组`                          |
| Seedance 2.0 | `原价分组`                          |

路由回退只选择执行渠道，用户仍以 `default` 分组的权限和价格语义调用。

## Seedance 2.0 前端参数边界

| 参数     | 支持范围                                                | 默认值 |
| -------- | ------------------------------------------------------- | ------ |
| 时长     | 4-12 秒，整数                                           | 5 秒   |
| 分辨率   | `480p`、`720p`、`1080p`                                 | `720p` |
| 宽高比   | `16:9`、`4:3`、`1:1`、`3:4`、`9:16`、`21:9`、`adaptive` | `16:9` |
| 生成音频 | 开启、关闭                                              | 开启   |
| 水印     | 开启、关闭                                              | 关闭   |
| 随机种子 | 整数                                                    | 不传   |
| 固定镜头 | 开启、关闭                                              | 不传   |

以下为 OpenTu 控件和请求组装约束，tuzi-api Seedance Proxy 负责透传，最终仍由上游接口校验。

参考媒体限制：

- Seedance 2.0 标准版和 Fast 在前端最多选择 9 张参考图。
- Seedance 2.0 Mini 在前端最多选择 4 张参考图。
- 支持参考视频，通过 `content[].video_url` 和 `role: reference_video` 提交。
- 视频生成弹窗提供参考音频 URL 输入、任务参数保存和编辑恢复，并按 `content[].audio_url`、`role: reference_audio` 组装请求。
- AI 输入框选中的视频可写入 Seedance 2.0 的 `input_video`；参考音频地址输入位于独立视频生成弹窗。
- 参考视频只接受官方声明的公网 HTTP(S) 地址；`asset://`、Data URL 和 Blob URL 会在请求前被拒绝。
- 参考音频接受 HTTP(S)、兼容的 `asset://`、`data:audio/*;base64` 和素材 ID。Data URL 必须使用小写 MIME、有效 Base64，最长 16 MiB，且只允许单任务提交；批量或更大音频使用 URL 或素材 ID。
- 官方页面未定义素材 ID 格式、音频大小或模型档位参数子集；本地不臆造素材 ID 前缀，资源上限属于 OpenTu/tuzi-api 的保护边界。

## Seedance 2.0 接口与状态流转

提交接口：

```http
POST /v1/videos
Content-Type: application/json
```

主要请求字段：

```json
{
  "model": "doubao-seedance-2-0-260128",
  "content": [],
  "resolution": "720p",
  "ratio": "16:9",
  "duration": 5,
  "generate_audio": true,
  "watermark": false,
  "seed": 0,
  "camera_fixed": false
}
```

轮询接口：

```http
GET /v1/videos/{taskId}
```

状态处理规则：

- `queued`、`processing` 等中间状态继续轮询并上报进度。
- `completed`、`succeeded` 读取内联视频 URL；没有 URL 时回退 `/videos/{taskId}/content` 下载结果。
- `failed`、`error` 立即结束并展示上游业务错误。
- 网络错误、HTTP 408、425、429 和 5xx 使用有界指数退避，最多连续 10 次错误。
- 其它确定性 4xx 立即失败，不做无意义重试。
- 正常轮询基础间隔为 5 秒，最多 1080 次，约 90 分钟；同时响应任务取消信号。

Seedance Proxy 会继续透传 `content`、`resolution`、`ratio`、`duration`、`generate_audio`、`watermark`、`seed` 和 `camera_fixed`，避免分辨率或可选控制字段在后端丢失。

若上游不支持新版路径，Proxy 会在 404/405 时回退旧 `/api/v1/doubao/create` 和 `/api/v1/doubao/get_result`，对外仍保持 `/v1/videos` 接口。

## 性能与安全边界

- 不新增数据库实体，不迁移或删除历史模型、任务和价格数据；仅将可精确识别的旧内置 Seedance 计费配置规范化为官方三档分辨率，自定义 `rule_version` 规则保持原样。
- 默认目录策略使用小型静态集合，展示过滤和路由回退不引入无界缓存。
- 异步轮询具有最大次数、连续错误上限、退避上限和取消信号，避免无限请求。
- 参考图片沿用现有 URL/Data URL 兼容路径；参考音频允许官方音频 Data URL，但 UI 不读取本地音频文件转码，并限制 Data URL 长度和批量复制，优先使用服务端可访问地址或素材 ID。
- 文档、日志和测试数据不得包含 API Key、完整鉴权头或用户敏感信息。

## 审查修复状态与剩余验证

1. **官方参数契约已修正**：分辨率与比例独立选择，范围改为 480p/720p/1080p、7 种比例和 4-12 秒，并补齐 `seed`、`camera_fixed`。
2. **参考媒体边界已修正**：参考视频只接受公网 HTTP(S)；参考音频支持官方 HTTP(S)、有效且有界的音频 Data URL 与素材 ID，Blob URL 会被拒绝。URL 字面量会拒绝 `localhost`、`.localhost`、`.local`、私网、链路本地和 IANA 保留 IPv4/IPv6 地址，并保留 IANA 明确标记为全局可达的例外；DNS 解析与重绑定防护仍由服务端请求出口负责。
3. **跨系列模型排序已修复**：`flash`、`pro`、`preview` 统一作为名称修饰词，归一后按主版本比较；Gemini 3.1、3、2.5 和同版本 Pro 优先级用例均通过。
4. **浏览器 QA 已完成**：桌面 1440x1000 与移动 390x844 均完整展示 9 个时长、3 个分辨率和 7 个比例，无横向越界或控件重叠；移动端可滚动访问全部参数。
5. **请求体已拦截验证**：实际 POST 请求包含 `resolution: "1080p"`、`ratio: "9:16"`、`duration: 12`、`seed: 424242`、`camera_fixed: true`，字段类型正确。请求由浏览器测试拦截，未使用真实密钥调用上游。

## 回滚思路

1. OpenTu 回滚新增静态模型、默认隐藏过滤和 Seedance 2.0 适配器注册。
2. tuzi-api 回滚默认目录策略与来源分组路由回退。
3. 保留旧模型、价格、渠道和历史数据，无需数据库恢复。
4. Seedance 2.0 异常时只移除新入口；Seedance 1.x 继续沿用原有 `seedance.task` 路径。
