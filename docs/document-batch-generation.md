# 文档批量生成（本地实施版）

入口：工作流模式顶部「批量生成」，路径 `/workflow/batch-generation`。

## 使用

1. 新建批次，导入 XLSX/XLS 或 PDF。导入本身不会提交生图。
   导入选项中可下载 Excel 模板：第一行为表头，提示词必填，一行一个任务。参考图允许为空，多张链接在「图片」列用换行分隔，内嵌图片须完整放在对应行内。先替换或删除模板示例，再导入；其他格式通过列映射和逐行诊断核对。
2. 核对任务提示词、来源和参考图；外链图片须手动加载。PDF 可查看原页、手动框选裁图，或单独确认发送当前页给识别模型。
3. 选择图片模型、批次默认参数及每行数量，需要时开启单行覆盖；将已核对行标记为可生成。
4. 勾选行并确认生成。暂停只阻止后续提交，不撤销供应商已受理请求。刷新后须点击继续恢复剩余队列。
   结果区域的「本轮进度」按已结束工作项/本轮总数更新，并分别显示处理中、排队、成功、失败、待确认和取消数量；不是单张图片的生成百分比。
5. 在当前轮次或历史中选择结果下载 ZIP；失败清单单独导出。可保存单张到资产，再从画布资产选择器插入。
   结果图片优先读取本地缓存，点击缩略图可放大预览；图片资源无法读取时会单独提示，不会因此重新生图。

批量入口只列出已关联 OpenTu 原生渠道、有参数契约且可用的图片模型，不支持自定义渠道/脚本模型。修改供应商配置后可点「刷新 OpenTu 模型」。历史批次保存的渠道失效时须重新选择，不会按同名模型自动切换供应商；其他工作流页面仍保留自定义渠道。

## 存储与恢复

批次使用独立 IndexedDB `opentu-document-batches`；内含批次、轮次、工作项和调度控制。Tuzi 环境按用户 ID 隔离；独立运行按当前浏览器本地工作区隔离，不是跨设备同步。

提交前冻结输入快照。工作项使用持久唯一 ticket，网络结果未知时保持待确认，不自动重新 POST。已核实的 Request ID 和受支持的异步 remoteId 通路只查询原任务；查询失败或协议不支持时显示待确认及原因，不自动重发。更换供应商或凭据后不会转用新路由重发。

关闭浏览器后不会继续提交。请勿把清理浏览器数据当成暂停操作；这会失去本地快照和去重依据。

## 配置、依赖与回滚

- `VITE_DOCUMENT_BATCH_SUBMISSION=false` 在构建/开发启动时关闭新批次提交；历史、查询及下载代码保留。恢复需移除该值并重新启动或构建。
- PDF 依赖 `pdfjs-dist` 6.3.289，标准 XLSX XML 解析使用 `fast-xml-parser` 5.10.1，结果 ZIP 使用现有 `fflate` 流式打包，逐张释放源缓冲；其他模块仍可使用 `jszip`。
- 删除批次前阻止在途/不确定任务；删除后保留 tombstone，释放该批次草稿和历史快照。不删除共享图片缓存。
- 回滚前暂停队列并导出结果；保留独立数据库，不用旧版本盲目重试未知受理任务。

## 当前限制

部分提案条目仍待实现/验证，详见 [任务清单](../openspec/changes/add-document-batch-image-generation/tasks.md)。包括完整导入 checkpoint、完整租约/故障窗口验证、真实渠道远端恢复验收、大预算压力测试。PDF 自动配对不能替代人工核对；WPS/公式图片、XLS 内嵌图片并非完整支持。供应商收费、模型最终能力及真实出图均未在本轮进行付费验证。

本地预算包括 500 行、每轮 1000 工作项、单图 25 MiB、单张远程图片下载 60 秒、PDF 每页 50,000 个文本项和 ZIP 分包（100 张/200 MiB），不是供应商限制，也不是已通过的最大压力容量。

验收可先导入少量合成文档并检查编辑、保存及来源，确认输入正确后再自行选择是否发送识别或生图请求。

单张远程图片下载超时会写入失败清单，继续下载后续图片。PDF 文本项超限后停止提取该页文字，保留页面图并要求人工核对。含未支持的 cellimages/richData 图片扩展的表格行也必须核对补图后确认。

外链检查拒绝本机、私网字面地址及常见本地别名，禁止重定向并省略凭据；浏览器前端无法可靠解析并锁定 DNS，因此不构成完整 DNS rebinding 防护。流式 ZIP 仍会保留当前分包的 Blob，最大预算下的浏览器内存压力尚未验证。
