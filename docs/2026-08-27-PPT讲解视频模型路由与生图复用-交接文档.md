# PPT 讲解视频模型路由与生图复用交接文档

**日期**：2026-08-27

**适用范围**：包含本修复的 `develop` 及其后续版本

**关联 QA**：[PPT 讲解视频模型路由与生图复用人工测试文档](../qa/2026-08-27-PPT讲解视频模型路由与生图复用-人工测试文档.md)

**关联规格**：[PPT 讲解视频 OpenSpec](../openspec/changes/add-ppt-explainer-video-agent/specs/ppt-explainer-video/spec.md)

## 问题与结论

旧页面只显示视频模型，但任务创建仍会在主题生成或当前 PPT 缺图时预检图片模型。局域网本地配置存在可执行图片路由时可以运行，发布环境缺少对应路由时则报「PPT 页面图片模型没有可执行路由」。删除图片依赖会破坏已经可用的 PPT 生成能力，也不符合产品需要。

本次保留原 PPT 生成和生图链路，并把缺失的选择与路由契约补齐：

- 配置同时选择图片、视频模型。
- 主题生成继续调用既有 `generatePPT()`，不新建 PPT provider。
- 页面生图继续复用已有 PPT prompt、参考图、16:9 和图片任务能力。
- 页面图先写回可见 PPT，编排器再冻结同一页面并逐页生成讲解音轨。
- 候选和提交均绑定 `profileId + modelId`，避免发布环境跨供应商误路由。
- 没有真实可执行候选时明确禁用，不用静态目录模型掩盖配置错误。

## 最终功能流程

```text
选择 PPT讲解视频 Skill
  → 选择文本、图片、视频模型及各自 ModelRef
  → 创建前检查当前画板、来源和三类所需路由
  → 主题来源复用 generatePPT() / 当前 PPT 读取既有 Frames
  → 仅为缺图页串行调用图片模型
  → 将新图缓存并写回用户可见 PPT
  → 冻结当前页面快照
  → 文本模型生成页级 speaker turns
  → 视频模型逐页生成带音轨片段
  → 丢弃生成式画面，以 PPT 快照、音轨和字幕本地合成
  → 最终 VIDEO 幂等写入素材库和创建任务时的画板
```

完整当前 PPT 不调用图片模型。主题来源和存在可补全缺图的当前 PPT 才要求图片路由通过预检；文本与视频路由始终必须可执行。

## 关键实现

### 1. 双模型选择与严格候选

[AIInputBar.tsx](../packages/drawnix/src/components/ai-input-bar/AIInputBar.tsx) 从运行时模型目录分别获取已配置图片、视频实例，并通过既有 provider route planner 检查 URL 和 API Key。PPT Skill 不追加静态目录回退模型。

[PptExplainerDialog.tsx](../packages/drawnix/src/components/ai-input-bar/PptExplainerDialog.tsx) 在底栏同时提供图片、视频选择器。主题来源必须选中当前候选中的精确图片实例；视频模型在所有来源下都必须精确匹配。

[model-selection.ts](../packages/drawnix/src/utils/model-selection.ts) 集中提供选择键、`ModelRef` 转换和精确匹配。PPT 路径使用 `findExactSelectableModel`；其他既有入口仍可使用兼容匹配，避免扩大行为变更。

### 2. 创建前零副作用预检

[creation-service.ts](../packages/drawnix/src/services/ppt-explainer/creation-service.ts) 先解析当前画板和页面缺图状态，再预检实际需要的文本、图片、视频 route。路由不存在、URL 为空或 API Key 为空时，在大纲生成、模型调用、缓存和根任务持久化前失败。

初始任务继续保存原始模型 ID、`ModelRef` 和适用的路由快照。刷新恢复和内部任务必须沿原供应商执行，不能只凭模型 ID 重新选择。

### 3. 复用 PPT 生图并写回

[orchestrator.ts](../packages/drawnix/src/services/ppt-explainer/orchestrator.ts) 的主题路径继续调用 `generatePPT()`。快照阶段调用已有 `prepareMissingPptSlideImages()`，仅生成缺失页面；之后调用 `materializePptExplainerSlideImages()` 写回画布，最后才冻结页面。

[source-resolver.ts](../packages/drawnix/src/services/ppt-explainer/source-resolver.ts) 保持逐页串行生图和事件循环让步，避免多页大图同时占用内存。生成结果先进入同源缓存，再替换对应 Frame 的页面图片并移除占位符。

### 4. 讲解视频与交付

后续仍由原编排器生成页级讲稿、按模型合法时长拆分逐页视频请求，并用本地 composer 固定 PPT 画面、播放音轨和字幕。内部生成式视频不直接展示；最终成片沿既有任务队列、素材库和原画板交付锁幂等写入。

## 冗余代码清理

本次只移除能够由现有公共能力承载的重复代码：

- 删除 `AIInputBar` 内重复的 selection key、`ModelRef` 和模型匹配 helper，统一复用 `model-selection.ts`。
- 删除 PPT 视频模型专用同步 Effect，图片和视频共用现有模型自动纠偏流程。
- `use-runtime-models.ts` 改用 `useSyncExternalStore` 订阅运行时目录 revision，并用稳定依赖缓存模型列表，减少输入热路径的重复扫描和重复渲染。
- 路由可执行性过滤只对 PPT Skill 的已配置候选执行，并使用 `useMemo`；普通生成入口行为不变。

以下功能性代码必须保留，不能作为“冗余”删除：

- `generatePPT()`：主题到大纲和 PPT Frames 的原入口。
- `prepareMissingPptSlideImages()`：仅补缺图、复用 PPT 页面提示词与图片模型。
- `materializePptExplainerSlideImages()`：在冻结前将图片写回用户可见 PPT。
- `imageRoute`、`imageModel`、`imageModelRef`：发布环境恢复和供应商路由隔离所需。
- 文本/图片/视频模型预检、内部任务所有权、逐页视频和最终本地合成。

## 性能与安全边界

- 运行时目录通过单一 external store revision 通知，不为每个 hook 建立一套易漂移状态。
- 图片和视频候选数组仅在模型发现、凭据或绑定变化时重算；输入文字不会触发路由目录全量扫描。
- 页面图逐页生成、逐页缓存并让出事件循环，不新增整份 PPT 二进制并发驻留。
- 任务状态只持久化脱敏路由元数据；API Key、Authorization、File/Blob/base64 和完整供应商响应不得写入任务或日志。
- 对象 URL、媒体解码器、音频节点和内部缓存沿原清理路径释放；取消和失败也必须完成清理。

## 发布配置与排障

遇到「PPT 页面图片模型没有可执行路由」时，按以下顺序检查，不要删除图片模型字段：

1. 供应商是否启用，模型是否已从供应商获取并勾选。
2. 当前选择保存的 `profileId + modelId` 是否与候选实例一致。
3. provider binding 是否存在，Base URL 和 API Key 是否非空。
4. 发布环境配置是否与局域网本地配置一致，是否错误地只迁移了模型 ID。
5. 当前来源是否真的需要生图：完整当前 PPT 不应调用图片模型；主题和有提示词的缺图页应调用。
6. 请求是否命中所选供应商，是否被 401/403/429/5xx 或跨域媒体读取阻断。

模型出现在静态常量、名称相同或 HTTP 服务返回 `200`，都不能证明该模型具有可执行路由。

## 待人工验收与剩余风险

- 用受控账号完成主题生成、当前 PPT 完整页图和缺图补全三条真实链路。
- 验证同 ID 双供应商不会串路由，供应商禁用或取消勾选后旧选择立即失效。
- 视频模型必须实际返回可解码音轨；模型名称或描述不能作为音轨能力保证。
- 对 10 页任务做输入响应、目录扫描、堆内存和资源释放检查。
- 在另一台 LAN 设备和发布环境分别完成一次短任务；不能只检查 HTTP `200`。
- Firefox/WebKit 的创建、恢复、取消和本地媒体合成尚未完成专项验收。

## 一句话结论

PPT 讲解视频现在显式选择可执行的图片与视频模型：先复用原 PPT 能力生成并写回页面图，再冻结同一 PPT、逐页生成音轨并本地合成；发布环境不再依赖只有模型 ID 的隐式回退。
