# 默认模型目录与 Seedance 2.0 接入测试清单

**创建日期**：2026-08-04

**测试范围**：仅验证默认模型目录刷新、旧模型隐藏兼容、模型广场价格/路由和 Seedance 2.0 新调用链

**关联交接文档**：[2026-08-04-默认模型目录与 Seedance2.0 接入-交接文档](../docs/2026-08-04-默认模型目录与Seedance2.0接入-交接文档.md)

## 前置条件

1. 使用包含本功能的 OpenTu 与 tuzi-api 环境。
2. 模型广场价格接口可用，tuzi-api 已完成一次最新价格同步。
3. 准备具有 `default` 分组权限的普通用户 Token。
4. 准备可执行 GPT-5.6、DeepSeek V4 和 Seedance 2.0 的上游渠道。
5. Seedance 媒体测试准备 9 张小尺寸参考图、1 个参考视频和 1 个小于 25MB 的参考音频文件。
6. 测试记录、截图和日志不得包含 API Key、完整 Token 或鉴权头。

## 测试范围

- 9 个新增模型的名称、内部 ID、`NEW` 标记与排序。
- 18 个旧 GPT 从 `default` 可见/可调用分组视图移除，历史选择和非 `default` 显式 API 调用继续兼容。
- 模型广场价格继承、默认组展示和来源分组路由。
- Seedance 2.0 参数控件、多模态输入、异步状态流转和错误退避。
- Seedance 1.x 原调用链回归。

不测试模型生成内容质量、远程部署、历史数据批量迁移或旧功能改造。

## 当前阻塞项

1. **参考音频上传端到端失败**：OpenTu 当前提交 `data:audio/...;base64`，tuzi-api 仅接受 `asset://` 或 HTTP(S) 媒体 URL，实际会返回 `400 invalid audio_url: unsupported media url`。
2. **跨系列模型排序回归**：当前会把 `gemini-2.5-flash-image` 排在 Gemini 3.x 前，对应自动化用例稳定失败。

以上问题修复前，本功能不能判定人工验收通过。

- [ ] 后端保留旧模型元数据、底层价格配置和非 `default` 分组渠道能力。

## 场景 4：历史选择与显式调用兼容

1. 打开保存了 `gpt-5.4` 或其它隐藏模型的历史会话、预设或固定模型。
2. 使用仍保留该模型能力的非 `default` 分组 Token 或供应商 Profile 显式请求旧模型 ID。

**预期结果**：

- [ ] 历史选择仍能解析模型名称，不变为空模型或自动删除记录。
- [ ] 非 `default` 分组或供应商 Profile 的显式 API 调用仍按原渠道策略执行。
- [ ] 不要求已从 `default` 移除的旧模型继续被 `default` 分组 Token 调用。
- [ ] 新建选择器不会重新向用户推荐隐藏模型。

## 场景 5：新增文本模型调用与工具能力

分别调用 GPT-5.6 三个模型和 DeepSeek V4 三个模型：

1. 提交普通文本对话。
2. 提交一个支持的工具调用请求。
3. 检查实际请求模型 ID、响应模型和使用日志。

**预期结果**：

- [ ] 六个正式 ID 均立即进入 `default` 可选目录，无灰度限制；具备相应 Token 分组、渠道和价格配置时可调用。
- [ ] 工具调用请求不会因前端静态能力声明被错误拦截。
- [ ] 实际上游能力和参数限制仍由 endpoint 元数据及服务端校验。
- [ ] 使用日志记录真实模型 ID，不改写为旧模型。

## 场景 6：模型广场价格与默认组

1. 完成一次模型广场价格同步。
2. 查看 9 个新增模型的默认组价格和模型广场展示。

**预期结果**：

- [ ] 9 个新增模型具有 `default` 展示归属和可用价格。
- [ ] 缺少直接 `default` 价格时，按 `原价分组`、`官方优惠`、`Codex`、其它可用分组字典序复制同一 endpoint 价格。
- [ ] Seedance 动态计费表达式进入分组计费配置，不污染全局固定价格。
- [ ] 旧隐藏模型价格在同步后仍保留。

## 场景 7：默认组路由回退

分别让 `default` 没有直接渠道、来源分组存在可用渠道：

- DeepSeek V4：验证 `原价分组`。
- Seedance 2.0：验证 `原价分组`。

**预期结果**：

- [ ] 只在默认组没有候选渠道时进入来源分组回退。
- [ ] 按规定顺序选择第一个可用来源分组。
- [ ] Seedance 2.0 不回退到未配置的测试分组。
- [ ] 用户仍按 `default` 分组权限和价格调用。

## 场景 8：Seedance 2.0 参数控件

1. 依次选择 Seedance 2.0、Fast 和 Mini。
2. 展开生成参数面板。

**预期结果**：

- [ ] 时长完整显示 4-15 秒的全部整数选项，默认 5 秒。
- [ ] 分辨率只显示 `720p · 横屏 16:9` 和 `480p · 横屏 16:9`。
- [ ] 不出现 1080p、4K、9:16 或其它未开放选项。
- [ ] 生成音频默认开启，水印默认关闭，且均可切换。

## 场景 9：时长、分辨率与比例透传

分别提交以下边界组合：

- 4 秒、`480p@16:9`。
- 15 秒、`720p@16:9`。

**预期结果**：

- [ ] OpenTu JSON 分别包含 `duration: 4/15`、`resolution: 480p/720p`、`ratio: 16:9`。
- [ ] tuzi-api Seedance Proxy 保留 `resolution`，不会把 480p 改回 720p。
- [ ] 请求使用 `POST /v1/videos`，不是 Seedance 1.x 表单接口。

## 场景 10：参考图片数量边界

1. Seedance 2.0 标准版和 Fast 分别添加 9 张参考图，再尝试第 10 张。
2. Mini 添加 4 张参考图，再尝试第 5 张。
3. 提交任务并检查 `content`。

**预期结果**：

- [ ] 标准版和 Fast 最多保留 9 张，Mini 最多保留 4 张。
- [ ] 每张图片使用 `type: image_url` 和 `role: reference_image`。
- [ ] 切换模型时超出新模型上限的图片不会被错误提交。

## 场景 11：参考视频与参考音频

1. 在视频生成弹窗选择任一 Seedance 2.0 模型。
2. 添加参考视频和小于 25MB 的合法音频文件，提交任务。
3. 从任务列表进入编辑，检查媒体参数恢复。
4. 使用 AI 输入框选择一个视频后提交 Seedance 2.0。
5. 分别尝试非音频文件和大于 25MB 的音频文件。
6. 移除参考音频后再次提交并检查请求体。

**预期结果**：

- [ ] 参考视频提交为 `video_url`、`role: reference_video`。
- [ ] 参考音频提交为服务端可接受的 URL、`type: audio_url`、`role: reference_audio`，并返回 2xx 与任务 ID；当前实现会提交 Data URL 并稳定返回 400，此项阻塞。
- [ ] 任务保存、编辑和重试时参考音频参数不会丢失。
- [ ] AI 输入框选中视频写入 `input_video`。
- [ ] AI 输入框不显示未实现的参考音频上传入口；参考音频从视频弹窗添加。
- [ ] 非音频文件和大于 25MB 的文件在前端被拦截。
- [ ] 移除参考音频后，请求不包含 `audio_url`。
- [ ] 记录音频转码后的请求体和内存占用；25MB 文件转 Base64 后约为 33MB，不得造成不可接受的内存峰值。

## 场景 12：音频和水印开关

分别提交以下组合：

- 生成音频开启、水印关闭。
- 生成音频关闭、水印开启。

**预期结果**：

- [ ] JSON 中 `generate_audio` 和 `watermark` 为布尔值。
- [ ] 服务端完整透传显式 `false`，不被默认值覆盖。
- [ ] 编辑历史任务时开关状态正确恢复。

## 场景 13：异步提交、轮询与结果读取

1. 提交 Seedance 2.0 任务，记录返回的 `id` 或 `task_id`。
2. 观察 `queued`、`processing` 到 `completed/succeeded`。
3. 分别测试响应内联视频 URL 和无内联 URL 两种完成结果。

**预期结果**：

- [ ] 使用 `GET /v1/videos/{taskId}` 轮询。
- [ ] 任务 ID、进度和最终状态进入任务队列。
- [ ] 内联 URL 可直接读取；缺少 URL 时从 `/videos/{taskId}/content` 获取结果。
- [ ] 完成结果格式为 MP4，任务取消可终止等待。

## 场景 14：轮询错误策略

分别模拟：网络错误、408、425、429、500、普通 400、401、403、404 和业务 `failed`。确定性 400 覆盖缺少文本、非法 `role/type`、非法媒体 URL、时长或分辨率类型错误，并对同一请求连续提交两次。

**预期结果**：

- [ ] 网络错误、408、425、429 和 5xx 使用有界退避后可恢复。
- [ ] 连续临时错误达到上限后停止，不无限轮询。
- [ ] 普通 400、401、403、404 立即失败，不重试、不跨渠道创建新任务。
- [ ] 业务 `failed/error` 立即展示上游错误。
- [ ] 相同确定性错误重复提交时返回稳定的错误码和信息。
- [ ] 3 秒和 16 秒属于上游时长边界，不声称由本地确定性校验拦截。

- [ ] 原有参数、任务轮询和结果读取行为不变。
