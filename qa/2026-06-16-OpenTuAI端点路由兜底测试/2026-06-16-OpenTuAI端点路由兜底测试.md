## 网页版快速验证步骤

### 方法 1: 设置页端点来源

1. 打开网页版测试地址。
2. 点击左上角应用菜单。
3. 进入“设置”。
4. 打开“供应商”页签。
5. 选择 tuzi-api 相关供应商。
6. 查看“API 地址”下方端点面板。

**结果判断**:

- ✅ 端点面板显示在设置页中。
- ✅ 面板显示“来源: tuzi-api”。
- ✅ 端点列表只包含 tuzi-api 上游站点和用户自定义站点。
- ✅ 底部 AI 输入栏没有端点选择控件。

### 方法 2: 自动最优与手动选择

1. 保持“自动选择”勾选。
2. 点击“测速”。
3. 等待测速结束。
4. 点击任意站点手动选择。
5. 保存设置后刷新页面。

**结果判断**:

- ✅ 测速期间有加载状态，页面不卡死。
- ✅ 自动模式下可选择延迟最低的可用端点。
- ✅ 手动点击端点后 API 地址同步更新。
- ✅ 刷新后 API 地址保持为用户选择的端点。

### 方法 3: 模型列表兜底

1. 在设置页将 API 地址切换为深圳地址 `https://apisz.ourzhishi.top`。
2. 输入有效 API Key。
3. 点击模型发现或刷新模型列表。
4. 观察是否能从其它 tuzi-api 站点获取模型。

**结果判断**:

- ✅ 主端点浏览器网络失败时，不直接终止模型发现。
- ✅ 后续候选站点请求成功时，模型列表正常展示。
- ✅ HTTP 鉴权失败仍显示鉴权错误，不被静默切换掩盖。

### 方法 4: 实际生成请求兜底

1. 使用 tuzi-api 供应商选择图片或文本模型。
2. 将 API 地址设置为当前网络环境下可能 `Failed to fetch` 的 tuzi-api 站点。
3. 提交一次生成任务。
4. 查看任务状态和浏览器网络请求。

**结果判断**:

- ✅ 浏览器网络错误时，会尝试其它 tuzi-api 站点。
- ✅ 请求路径保持一致，例如 `/v1/chat/completions` 或对应图片生成路径。
- ✅ 业务错误、参数错误、401 错误不会被误判为站点网络失败。

## 常见问题排查

### 问题 1: 深圳地址获取模型显示 Failed to fetch

**原因**: 当前浏览器或本机网络到该站点可能在 TLS、CORS 或网络层失败。

**处理**:

1. 确认供应商 API 地址属于 tuzi-api 上游站点。
2. 确认设置页端点面板能看到其它 tuzi-api 站点。
3. 重新触发模型发现，观察是否继续请求其它候选站点。

### 问题 2: 端点列表为空或数量异常

**原因**: `https://api.tu-zi.com/api/status` 加载失败，或返回结构变化。

**处理**:

1. 直接访问状态接口确认是否可用。
2. 检查浏览器控制台网络错误。
3. 确认页面已回退显示内置 6 个 tuzi-api 站点。

### 问题 3: 底部输入栏出现端点选择

**原因**: 访问了旧构建或浏览器缓存未刷新。

**处理**:

1. 强制刷新页面。
2. 确认当前环境部署的是本次 PR 构建。
3. 确认端点管理入口只在设置页 API 地址下方。
