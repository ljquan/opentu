# AI 任务栏图片 LAN 专项测试

> [!IMPORTANT]
> 本文件只验证图片任务栏在局域网 HTTP 环境中的布局、图片提示词候选、Tuzi 图片请求代理和无 Service Worker 图片插入。图片、视频、文本和音频的现行目标行为统一见主 QA。

- **日期**：2026-08-04
- **地址模板**：`http://${LAN_HOST}:${PORT}/`
- **启动要求**：开发服务监听 `0.0.0.0`，将 `${LAN_HOST}` 替换为开发机局域网 IP，将 `${PORT}` 替换为实际端口。
- **主 QA**：[AI 任务栏跨媒体目标测试清单](../2026-07-15-AI任务栏跟随目标测试/2026-07-15-AI任务栏跟随目标测试.md)
- **关联 Docs**：[AI 任务栏提示词复用、跟随尺寸与局域网图片插入交接文档](../../docs/2026-08-04-AI任务栏跟随尺寸与局域网图片插入-交接文档.md)

## 验收范围

- 本清单的目标类型仅为图片；视频、文本和音频不在此重复验收。
- 跟随图片时任务栏保持原有尺寸。
- 下方模型、参数、数量和发送操作不被挤压或裁切。
- 生成图片的历史提示词只作为淡化候选，空格或回车才填入输入框。
- 手写输入或点击任务栏按钮后候选消失，同一目标刷新不重新显示。
- 局域网 HTTP 无 Service Worker 时，缓存图片仍可插入画板并正常显示。
- 局域网生成请求通过固定同源代理，响应不能回退为 SPA HTML。
- 临时 Blob URL 仅用于渲染，不污染画板持久化数据。

跨媒体提示词、位置跟随开关、参考视频、文本上下文、音频边界和同类型替换只在主 QA 维护。本文件中的 Tuzi 同源代理与 IndexedDB Blob 降级均为图片链路，不表示其他媒体复用图片代理。

## 浏览器实测结果

以下历史结果中的服务地址统一记为 `http://${LAN_HOST}:${PORT}/`；端口和局域网 IP 可按每次运行环境变化。

### 场景 0：历史提示词候选

步骤：

1. 单选一张带 `generationPrompt` 的生成图片。
2. 检查 textarea 的真实值和 placeholder。
3. 分别使用空格、回车复用；重新选择后直接输入；再次选择后点击模型或参数按钮。

结果：

- textarea 真实值初始为空，placeholder 淡化显示“按空格或回车复用：历史提示词”。
- 第一次空格或回车只填入历史提示词，不触发生成；填入后再次回车才提交。
- 直接输入时只保留新内容；点击其他任务栏按钮后候选消失，均不粘贴历史提示词。
- 同一元素异步更新 URL、任务 ID 或 anchor ID 时，不覆盖当前输入，也不恢复已经取消的候选。
- 无历史提示词时不显示复用提示；方向键不会清除候选。
- `isSecureContext = false`，无 Service Worker controller；控制台无错误。

### 场景 1：跟随态保持任务栏原尺寸

环境：Chrome，`1440 x 900`，局域网 HTTP。

步骤：

1. 打开空白画板并记录普通任务栏宽度。
2. 插入一张图片并写入生成提示词元数据。
3. 单选该图片，等待任务栏进入跟随态。
4. 检查任务栏边界、内联样式和底部选项。

结果：

- 普通态宽度：`720px`。
- 跟随态宽度：`720px`。
- 跟随态 `style.width`：空。
- 跟随态 `style.maxWidth`：空。
- 图片类型、模型、参数和数量控件均在任务栏可视边界内。
- 浏览器控制台无错误。

### 场景 2：局域网 HTTP 无 Service Worker 单图插入

环境检测：

- `isSecureContext = false`
- `serviceWorker in navigator = false`

步骤：

1. 通过统一缓存写入一张 PNG。
2. 使用画布插入服务插入该稳定虚拟 URL。
3. 检查画板节点与页面实际图片地址。

结果：

- 画板元素数量从 `0` 增至 `1`。
- 插入结果 `success = true`。
- 画板数据保存 `/__aitu_cache__/image/content-*.png`。
- 页面渲染使用临时 `blob:http://${LAN_HOST}:${PORT}/...`。
- 图片可见，浏览器控制台无错误。

### 场景 3：连续六张图片插入

步骤：

1. 使用 OpenTu 自带 PNG 资源写入统一缓存。
2. 连续六次调用任务列表同类的 `insertImageFromUrl` 路径。
3. 检查每次结果、画板节点和图片可见状态。

结果：

- `6/6` 次插入成功。
- 画板新增 `6` 个图片元素。
- `6/6` 张图片可见。
- `6/6` 张图片在无 Service Worker 时使用 Blob URL 渲染。
- 未出现“插入失败: 未知错误”。
- 浏览器控制台无错误。

### 场景 4：固定同源代理

步骤：

1. 分别请求 `api`、`apius`、`apicdn`、`sydney`、`ourzhishi`、`ourzhishi-sz` 的 `/v1/models`。
2. 检查 HTTP 状态、`Content-Type` 和响应体类型。

结果：

- 六个路由均到达真实上游并返回 `401 application/json`。
- 未返回 `text/html`，未被 Vite SPA fallback 伪装为成功。
- 未携带 API 密钥，因此本轮未执行真实付费生成；生成成功后的插入链路由场景 2、3 验证。

## 结论

图片专项代码、定向自动化和 LAN Chrome 实测通过：生成图片历史提示词只在空格/回车时复用，直接输入、按钮和同目标刷新不会误回填；任务栏保持原尺寸；六个图片生成代理均到达 JSON 上游；无 Service Worker 时连续六张缓存图片均可通过 IndexedDB Blob 回退插入和显示。跨媒体交互结果以主 QA 为准；本专项剩余人工项为图片按钮矩阵、真实输入法组合、移动端及携带有效密钥的图片生成。
