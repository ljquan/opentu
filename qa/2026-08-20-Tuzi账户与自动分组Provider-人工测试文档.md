## 前置条件

1. 启动 Tuzi API，监听 `0.0.0.0:3100`。
2. 启动 OpenTu，监听 `0.0.0.0:5173`。
3. OpenTu 开启嵌入模式，并配置 Tuzi API 的本地或局域网基础地址。
4. Tuzi API 的 `TUZI_CORS_ALLOWED_ORIGINS` 包含实际访问的 OpenTu Origin。
5. 准备一个状态正常、具有至少一个授权分组和可用额度的 Tuzi 测试账户。
6. 准备至少一个低成本文本模型和一个低成本图片模型；执行真实生成前确认模型价格已经配置。
7. 测试记录、截图、控制台和网络日志不得包含完整 API Key、Session Cookie、access token 或 Authorization 请求头。

## 重要地址规则

同一次测试必须使用相同主机名访问 OpenTu 和 Tuzi API，不能混用登录态：

| OpenTu 地址                  | 对应 Tuzi API 登录地址       |
| ---------------------------- | ---------------------------- |
| `http://localhost:5173`      | `http://localhost:3100`      |
| `http://127.0.0.1:5173`      | `http://127.0.0.1:3100`      |
| `http://192.168.50.218:5173` | `http://192.168.50.218:3100` |

开发环境会在 `localhost`、回环地址和私有内网 IP 之间自动跟随 OpenTu 当前页面主机，并保留 Tuzi API 端口。公开 API 域名不会被自动改写。

## 当前已知限制

1. `localhost`、`127.0.0.1`、内网 IP 和正式域名的 Session Cookie 相互隔离，必须在当前 Tuzi API 主机登录。
2. 当前采用浏览器端托管 Provider 凭据方案，满足用户无需手动管理 Key，但不能保证 Key 对浏览器用户不可见。
3. 视频在尚未取得远端任务 ID 时发生网络中断，当前不保证按请求 ID 自动恢复，也不应自动重复提交。
4. 当前阶段不新增模型提交幂等表、统一 jobs DTO、云端画板数据或支付能力。
5. 模型未配置价格时，Tuzi API 会拒绝调用；测试不得把该错误归因于 Session 或托管 Key。
