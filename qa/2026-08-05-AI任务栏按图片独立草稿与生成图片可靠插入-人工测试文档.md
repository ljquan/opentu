## 验收目标

1. 每张图片只恢复自己的提示词、上传内容和知识引用，不串稿。
2. 未选图片时只显示独立未绑定草稿，不显示上一张图片提示词。
3. 主动关闭跟随与普通取消选择具有不同且可预期的行为。
4. 提交、切换画板、删除图片和异步回调不会错误覆盖当前输入。
5. 生成图片在首次生成、重试、恢复和手动插入时使用正确缓存与尺寸，不插入空白节点。

## 范围边界

- 草稿仅在当前页面内有效；刷新或重新打开页面后的恢复不在本次验收范围。
- 按图片保存的字段仅包括提示词、手动上传/素材库参考内容、知识引用。
- 模型、参数、数量、生成类型和动态画布选区不按图片保存。
- 不应期待所有图片共用提示词；每张图片以自己的来源提示词作为初始值。
- 缓存失败时允许继续使用可访问的远程 URL，不要求所有远程图片必然离线可用。

## 前置条件

1. 使用包含本功能的 OpenTu 页面，并登录可执行图片生成的账号。
2. 准备同一画板内两张可单独选中的图片 A、B，最好带不同来源提示词。
3. 准备第二个画板，用于跨画板隔离测试。
4. 准备至少一个知识库条目、一张本地参考图和一项素材库内容。
5. 配置可用图片模型，并准备单图、多图、重试和失败场景。
6. 测试截图和日志不得包含 API Key、Cookie 或完整鉴权头。

## 待人工回归

### 场景 1：单张图片误触后的恢复

1. 选择图片 A，确认任务栏显示 A 自己的来源提示词。
2. 在原提示词后追加一段文字，不发送。
3. 点击不会改变画布选区的任务栏外区域，再回到输入框。
4. 点击画布空白取消选择。
5. 再次选择图片 A。

**预期结果**：

- [ ] 仅失焦时输入内容保持可见且完整。
- [ ] 点击画布空白后切换为未绑定草稿，不显示 A 的提示词。
- [ ] 重新选择 A 后恢复完整追加内容，字符顺序和换行不变。

### 场景 2：图片 A/B 独立草稿

1. 在图片 A 输入 `A-草稿`。
2. 选择图片 B，确认没有出现 `A-草稿`，再输入 `B-草稿`。
3. 按 A → B → A → B 的顺序切换两轮。

**预期结果**：

- [ ] A 始终恢复 `A-草稿`。
- [ ] B 始终恢复 `B-草稿`。
- [ ] 任一图片都不显示另一张图片的来源提示词或手工追加内容。

### 场景 3：未绑定草稿与主动关闭

1. 未选图片时输入 `未绑定草稿`。
2. 选择图片 A 并修改为 `A-关闭前草稿`。
3. 点击画布空白，再观察输入框。
4. 重新选择 A，点击任务栏的“关闭跟随”。

**预期结果**：

- [ ] 普通点击空白后仍显示原来的 `未绑定草稿`，不会复制 A。
- [ ] 主动关闭跟随后，未绑定输入变为 `A-关闭前草稿`。
- [ ] 图片保持选中时不会立即重新跟随；切换选择后可再次正常绑定。

### 场景 4：上传内容和知识引用隔离

1. 图片 A 添加本地参考图和知识引用 A。
2. 图片 B 从素材库添加另一张参考图和知识引用 B。
3. 在 A、B 和画布空白之间反复切换。
4. 分别删除一项附件或知识引用后再切换回来。

**预期结果**：

- [ ] A 只恢复 A 的参考内容和知识引用。
- [ ] B 只恢复 B 的参考内容和知识引用。
- [ ] 未绑定输入只显示自己的附件和知识引用。
- [ ] 删除结果属于当前草稿，不会因切换而复原或影响其他草稿。

### 场景 5：提交期间继续编辑

1. 选择图片 A，填写提示词并提交图片生成。
2. 在任务仍处于提交或生成阶段时，继续在任务栏输入新内容。
3. 等待旧提交进入已接收、完成或失败状态。

**预期结果**：

- [ ] 旧提交回调不会清掉提交后新增的内容。
- [ ] 单张图片生成执行目标替换，多图生成保留原图并创建新图片。
- [ ] 生成失败时原图片保留，并显示可理解的错误信息。
- [ ] 切换到视频、文本或 Agent 模式提交时，不对绑定图片执行原位替换。

### 场景 6：跨画板隔离

1. 在画板 1 的图片 A 输入草稿，同时保留一份未绑定草稿。
2. 快速切换到画板 2，并立即选择图片或编辑未绑定输入。
3. 等待画板 1 的选区解析和提交回调结束。
4. 返回画板 1，再选择原图片 A。

**预期结果**：

- [ ] 画板 1 的图片绑定草稿不会进入画板 2。
- [ ] 未绑定草稿在切板时保留。
- [ ] 旧画板异步结果不会覆盖画板 2 的选择和输入。
- [ ] 返回画板 1 后不要求恢复旧图片绑定草稿。

### 场景 7：删除与嵌套图片

1. 为顶层图片 A 和 Frame 内嵌套图片 B 分别创建草稿。
2. 删除顶层图片 A，继续操作画板触发草稿清理。
3. 保留 Frame 和图片 B，切换选择后再次选择 B。

**预期结果**：

- [ ] 已删除图片 A 不再恢复旧草稿。
- [ ] 嵌套图片 B 仍恢复自己的草稿。
- [ ] 连续删除和切换时控制台无异常、页面无明显内存持续增长。

### 场景 8：重试与缓存隔离

1. 创建图片任务并记录首次结果。
2. 对同一任务执行重试，让第二次返回可识别的不同图片。
3. 刷新任务列表并分别预览、插入重试后的结果。

**预期结果**：

- [ ] 重试结果使用新的 submission 缓存地址。
- [ ] 不会显示或插入第一次提交的旧图片。
- [ ] 缓存可用时任务结果使用稳定 `/__aitu_cache__/...` 地址。
- [ ] 缓存失败但远程 URL 可用时，仍可使用远程结果。

### 场景 9：加载失败与空白节点防护

1. 从任务列表插入一张缓存已删除或 URL 不可访问的图片。
2. 再插入一张加载较慢但最终可访问的图片。

**预期结果**：

- [ ] 不可用图片提示“图片缓存不可用”或“图片加载失败，请检查图片地址或缓存”。
- [ ] 失败后画布不新增空白图片节点，任务不误标记为已插入。
- [ ] 慢图片在确认加载后只插入一次，不出现重复节点。
- [ ] 错误提示不重复出现“插入失败: 插入失败”。

### 场景 10：单图、多图和极端比例

1. 分别插入竖图、横图、方图。
2. 创建至少 3 张不同比例的批量结果并一次插入。
3. 测试接近 `1:1000` 或 `1000:1` 的极端比例。
4. 测试结果没有真实宽高、但请求 `size` 有效和无效的情况。

**预期结果**：

- [ ] 有真实宽高时按真实比例展示。
- [ ] 无真实宽高时按有效请求比例展示；无有效比例时为 `400 × 400`。
- [ ] 长边不超过 `600`，短边至少为 `1`。
- [ ] 批量图片顺序正确、尺寸独立且互不重叠。
- [ ] 多图缓存过程中没有明显瞬时内存峰值或页面卡死。

### 场景 11：任务恢复

1. 在可恢复的异步图片任务处理中刷新页面。
2. 等待恢复任务返回结果并插入。
3. 在恢复期间再次重试同一任务，制造旧结果晚于新尝试返回的情况。

**预期结果**：

- [ ] 有远程任务 ID 的图片任务可继续恢复。
- [ ] 没有可恢复依据的普通图片任务不被错误恢复。
- [ ] 旧尝试结果不会覆盖或注册到新尝试。
- [ ] 恢复结果缓存失败时，可用远程 URL 仍被保留。

### 场景 12：局域网访问

1. 从同一局域网另一台设备打开 `http://192.168.50.225:7211/`。
2. 完成 A/B/空白切换和单图插入。
3. 检查浏览器控制台与网络响应。

**预期结果**：

- [ ] 页面可访问，任务栏交互与本机一致。
- [ ] 未登录接口返回 JSON 鉴权错误，而不是 SPA HTML。
- [ ] 图片插入成功，或在资源不可用时给出明确错误且不留空白节点。
- [ ] 控制台没有与本功能相关的未处理异常。

## 通过标准

以下条件全部满足才可判定人工验收通过：

1. A/B 图片草稿互不串内容，未选图片不显示上一张图片提示词。
2. 普通取消选择与主动关闭跟随符合各自的数据迁移规则。
3. 附件、知识引用、提交期间新编辑和跨画板状态均不会被错误覆盖。
4. 重试和恢复不复用旧提交结果，加载失败不创建空白图片节点。
5. 单图、多图和极端比例均按受控尺寸插入且不重叠。
6. 局域网真实画布流程可用，错误反馈清晰且无未处理异常。
