# PPT 讲解视频模型路由与生图复用人工测试文档

**日期**：2026-08-27

**测试对象**：包含本修复的 `develop` 派生分支

**局域网地址**：`http://192.168.50.225:7202/?sw=0`

**关联 Docs**：[PPT 讲解视频模型路由与生图复用交接文档](../docs/2026-08-27-PPT讲解视频模型路由与生图复用-交接文档.md)

## 验收目标

1. 「PPT 讲解视频」同时提供图片模型和视频模型选择，不再只有视频模型。
2. 主题来源复用已有 PPT 大纲与页面生图链路；页面图先写回可见 PPT，再冻结并逐页生成讲解视频。
3. 模型候选只包含当前启用、已获取、已勾选且具有有效 URL/API Key 路由的实例。
4. 同一模型 ID 存在于不同供应商时，严格按 `profileId + modelId` 使用所选路由，不跨供应商回退。
5. 模型失效时在产生模型费用、缓存写入或任务持久化前失败。
6. 页面输入、切换 Skill 和切换模型无明显卡顿，长任务按页串行处理且完成后内存不持续增长。
7. 局域网设备可以使用工作台完成真实功能，不以 HTTP `200` 代替功能验收。

## 问题基线

旧页面底栏只有「视频模型」，发布环境创建任务时出现「PPT 页面图片模型没有可执行路由」类错误。局域网本地配置可用时不一定复现，因此必须同时验证候选来源、所选 `ModelRef` 和发布环境供应商配置，不能仅复测本地默认模型 ID。

## 范围边界

- 本文验证现有 PPT 生成能力的复用、模型路由、逐页讲解编排、恢复/取消和性能，不评价模型生成内容的审美质量。
- 不新增 PPTX 上传、专用 TTS、声音克隆、数字人或独立 PPT provider。
- 普通图片、视频和其他 Agent Skill 的宽松模型回退行为不在本次修改范围。
- 真实图片/视频调用可能产生费用，须由发布负责人使用受控测试账号执行。
- HTTP `200` 只证明服务可达；真实任务、页面图、音轨和最终成片均通过后才可发布。

## 前置条件

1. 从测试分支启动服务并监听 `0.0.0.0:7202`。
2. 准备一个可执行文本模型、一个可执行图片模型和一个能返回可解码音轨的视频模型。
3. 至少准备两个供应商配置，并让它们存在一个相同模型 ID，用于验证路由隔离。
4. 准备三组当前 PPT：页面图完整、部分页面缺图但有 `slidePrompt`、页面既缺图又无提示词。
5. 使用短小主题和 2 ～ 3 页 PPT 控制真实调用成本；打开任务队列、浏览器控制台和网络面板。
6. 记录供应商 `profileId`、模型 ID、任务 ID 和页面数；证据中隐藏 API Key、Cookie、完整鉴权头和用户数据。

## 人工测试场景

### 场景 1：入口与双模型选择

1. 在 AI 输入栏切换为「Agent」，选择「PPT 讲解视频」。
2. 分别打开图片模型、视频模型选择器和「生成 PPT 讲解视频」配置弹窗。
3. 切换不同图片和视频模型后再次打开配置。

**预期结果**：

- [ ] 输入栏和配置弹窗都能看到图片、视频两个模型入口。
- [ ] 配置弹窗保留当前选中的两个模型及其供应商来源。
- [ ] 下拉列表不混入未获取、未勾选或无可执行路由的静态模型。
- [ ] 没有候选时显示「暂无已配置图片模型」或「暂无已配置视频模型」，不会继续使用隐藏旧值。

### 场景 2：主题生成复用现有 PPT 生图

1. 选择「主题生成」，输入一个 2 ～ 3 页主题。
2. 选择图片模型和视频模型，先走「确认大纲」。
3. 确认大纲后观察画布、任务队列、网络请求和最终成片。

**预期结果**：

- [ ] 复用原 `generatePPT()` 生成大纲与 PPT Frames，不替换画布已有 PPT。
- [ ] 页面图使用所选图片模型逐页生成，并先写回用户可见 PPT。
- [ ] 讲解任务冻结的是写回后的同一组页面，不使用后台隐藏图片或模型生成的视频画面。
- [ ] 视频模型逐页生成有声片段，最终固定原 PPT 页面并在本地合成为一个视频。
- [ ] 内部页图/视频任务不重复进入素材库或画布，最终成片只交付一次。

### 场景 3：跳过大纲确认

1. 选择主题来源和「跳过大纲」。
2. 点击创建，先取消二次确认，再重新创建并确认。

**预期结果**：

- [ ] 取消二次确认时零模型调用、零缓存写入、零任务持久化。
- [ ] 确认后才开始生成，后续生图、写回、冻结和讲解顺序与场景 2 一致。

### 场景 4：当前 PPT 页面图完整

1. 选择页面图完整的当前 PPT。
2. 创建讲解任务并观察网络请求。

**预期结果**：

- [ ] 不重复调用图片模型，不改写现有页面图。
- [ ] 使用当前页面的不可变快照规划讲稿、逐页生成音轨并合成。
- [ ] 文本与视频模型仍须通过创建前预检。

### 场景 5：当前 PPT 缺图补全

1. 使用部分页面缺图、但保留 `slidePrompt` 的当前 PPT 创建任务。
2. 观察缺图页面与已有页面的处理。

**预期结果**：

- [ ] 只为缺图页调用所选图片模型，已有页面不重复生成。
- [ ] 新图逐页写回对应 Frame，全部写回完成后才冻结 PPT。
- [ ] 生图失败时显示具体页码和真实错误，不进入视频生成或最终合成。
- [ ] 缺图且无可用提示词/无法冻结时明确失败，不生成空白成片。

### 场景 6：同 ID 跨供应商路由隔离

1. 配置供应商 A、B，使其都提供模型 ID `shared-model`。
2. 依次选择 A、B 的图片模型和视频模型，分别创建受控任务。
3. 检查请求目标与任务保存的 `ModelRef`。

**预期结果**：

- [ ] UI 能区分同 ID 的供应商实例。
- [ ] 每次请求只命中所选 `profileId + modelId` 对应的 URL 和凭据。
- [ ] 所选供应商失效后不会按相同模型 ID 静默切换到另一供应商。

### 场景 7：候选失效与零副作用保护

分别验证供应商禁用、模型取消勾选、URL 为空、API Key 为空、凭据过期和路由被删除。

**预期结果**：

- [ ] 禁用、取消勾选、缺 URL/API Key 的模型从候选中移除，当前旧选择被清空或禁止创建。
- [ ] 创建前预检返回准确错误，不生成大纲、不创建内部任务、不写缓存、不产生模型费用。
- [ ] 401/403/429/5xx 保留供应商真实语义，修复配置后可重新创建。

### 场景 8：逐页音轨与本地合成

1. 分别创建单人、双人任务，并设置每页 7 秒和 30 秒。
2. 检查片段数量、字幕、页面切换和最终时长。

**预期结果**：

- [ ] 请求时长只使用视频模型真实支持的选项；长页面可拆为多个片段。
- [ ] 双人 turns 按角色拆分请求，最终画面始终为 PPT 页面。
- [ ] 无音轨、缓存缺失或解码失败时明确失败，不把静音视频标记成功。
- [ ] 最终视频可播放，页面顺序、字幕和音轨同步，素材库与原画板各只出现一次。

### 场景 9：刷新、取消、跨标签与切板

1. 在生图、讲稿、逐页视频和合成阶段分别刷新或取消。
2. 两个标签打开同一工作区；任务执行时切换到另一画板。

**预期结果**：

- [ ] 刷新后从已持久化阶段恢复，不重复计费或重复交付。
- [ ] 取消后停止后续页面；迟到回调不能覆盖取消状态或生成最终结果。
- [ ] 跨标签只有一个有效执行尝试；最终结果回到创建任务时所属画板。

### 场景 10：页面响应与内存

1. 连续 30 次切换图片/视频模型和其他 Skill，持续在输入框输入 200 ～ 500 字。
2. 创建一个 10 页受控任务，观察 Performance、Network 和 Memory。
3. 任务完成或取消后等待 2 分钟，再取一次堆快照。

**预期结果**：

- [ ] 输入和模型切换无肉眼可见长时间卡顿，控件不跳动或重复刷新。
- [ ] 切换模型不会持续重复扫描目录或发起无关模型请求。
- [ ] 页面图和视频按页串行/受背压处理，不同时持有整套大媒体 Blob。
- [ ] 任务结束后对象 URL、解码资源和订阅可释放，内存不持续单调增长，不触发交换分区异常增加。

### 场景 11：局域网和发布环境

1. 从同一局域网另一台设备打开 `http://192.168.50.225:7202/?sw=0`。
2. 完整执行场景 1、2、5、6、7 和 8。
3. 在发布环境用同一供应商配置和同一模型重新执行一次短任务。

**预期结果**：

- [ ] 工作台、模型选择、任务队列和最终媒体均可用，不只是入口返回 `200`。
- [ ] LAN 下 Cache Storage 不可用时按既有降级路径工作或显示明确错误。
- [ ] 跨域媒体通过既有同源缓存/代理读取，不把 SPA HTML 当媒体。
- [ ] 发布环境候选与真实可执行路由一致，不再出现截图中的图片模型路由错误。

## 发布通过标准

1. 主题生成完成「大纲 → 原链路生图 → 写回 PPT → 冻结 → 逐页视频 → 本地合成」，最终成片可播放。
2. 当前 PPT 完整页图不重复生图，缺图仅补对应页面且写回后再冻结。
3. 图片和视频模型均严格按 `profileId + modelId` 路由；失效配置在任何副作用前失败。
4. 至少完成一次刷新恢复、一次取消、一次同 ID 跨供应商和一次无音轨失败验收。
5. 10 页受控任务无明显页面冻结、持续内存增长或资源泄漏。
6. LAN 与发布环境都通过真实短任务，不能以自动化或 HTTP `200` 单独代替。
