## 验收目标

1. 单选图片进入任务栏跟随态后，`Delete` 和 `Backspace` 均可删除图片。
2. 跟随任务栏仍正常显示并恢复图片提示词，但不会自动抢占输入焦点。
3. 用户主动编辑输入框时，删除键只编辑文字，不误删画布图片。
4. 其他元素、输入态、只读态和历史画板的既有删除语义不回归。

## 范围边界

- 本次仅调整“绑定图片时是否自动聚焦任务栏输入框”。
- 不调整全局键盘事件、Plait 删除逻辑、撤销恢复、草稿存储或图片数据结构。
- 自动化通过不等于全部人工场景通过；下方未实际执行的项目统一标记为“待测试”。

## 前置条件

1. 使用包含本修复的 OpenTu 页面，确保画布可编辑。
2. 准备普通本地图片、带来源提示词的生成图片、空提示词图片各一张。
3. 准备包含多选图片和 Frame 内嵌图片的测试画板。
4. 如验证历史数据，使用升级前已保存且可正常打开的画板副本。
5. 测试截图、日志和录屏不得包含 API Key、Cookie 或完整鉴权头。

## 待人工回归

### 场景 1：普通图片分别使用两种删除键

1. 插入普通本地图片 A 并单选，确认任务栏进入跟随态。
2. 确认输入框没有自动获得焦点，按 `Delete`。
3. 撤销并重新选中图片 A，按 `Backspace`。

**预期结果**：

- [ ] 两种按键都能删除图片，且任务栏随目标消失或解除绑定。
- [ ] 撤销、重新选择后仍可再次删除，不是仅首次有效。
- [ ] 控制台没有本功能相关异常。

### 场景 2：带提示词和空提示词图片

1. 单选带来源提示词的生成图片，确认任务栏恢复正确提示词后按 `Delete`。
2. 单选空提示词图片，按 `Backspace`。

**预期结果**：

- [ ] 两类图片均可删除，提示词是否为空不影响按键路由。
- [ ] 任务栏显示或恢复提示词时不自动抢焦点。

### 场景 3：主动文本编辑保护

1. 单选图片并主动点击任务栏输入框。
2. 在提示词中间分别按 `Backspace` 和 `Delete`。
3. 按 `Escape` 或点击图片退出文本编辑焦点，再按删除键。

**预期结果**：

- [ ] 输入框聚焦时只修改文字，图片保持存在。
- [ ] 退出输入焦点后，删除键恢复删除所选图片。
- [ ] 中文输入法组合输入期间不误删图片。

### 场景 4：删除后的解绑、草稿与撤销

1. 为图片 A 修改未发送提示词，然后退出输入焦点并删除图片。
2. 观察任务栏状态，再执行撤销并重新选择 A。
3. 重复 A → B → 空白 → A 的选择与删除流程。

**预期结果**：

- [ ] 删除后不继续显示已删除图片的绑定态，草稿不会串到图片 B 或未绑定输入。
- [ ] 撤销后图片可重新选中并再次使用两种删除键。
- [ ] 快速切换或异步绑定完成时，不会有晚到回调重新抢占焦点。

### 场景 5：多选与 Frame 内嵌图片

1. 多选两张图片，分别用 `Delete` 和 `Backspace` 删除并撤销。
2. 选择 Frame 内嵌图片，重复两种按键。
3. 选择 Frame 本身，确认其既有删除行为。

**预期结果**：

- [ ] 多选删除数量和撤销结果与修复前既有语义一致。
- [ ] 内嵌图片与 Frame 不因任务栏焦点变化出现误删、漏删或残留选区。
