# 图片请求 Request ID 测试清单

创建日期：2026-07-27
测试范围：仅验证图片提交请求新增的 `X-Request-Id`
关联经验文档：[图片请求 Request ID 经验](../../docs/IMAGE_REQUEST_ID_LESSONS.md)

## 前置条件

- 使用可访问的 OpenTu 网页环境。
- 浏览器开发者工具可查看 Network 请求头。
- 配置至少一个可信 Tuzi 图片模型，并准备一个非可信自定义供应商用于边界验证。
- 分别从 `opentu.ai` / `pr.opentu.ai` 官方公网与一个第三方公网 OpenTu 部署执行。
- 测试时不要在截图或报告中暴露 API Key。

## 用例 1：普通图片生成

1. 在公网 OpenTu 页面选择可信 Tuzi 模型，并提交一次任务。
2. 在 Network 面板找到 `/images/generations` 请求。

预期结果：

- [ ] 请求中存在 `X-Request-Id`。
- [ ] 标头值与当前本地图片任务 ID 一致。
- [ ] Request URL 直连可信 Tuzi API，CORS 预检通过且正式 `POST` 实际到达 API。
- [ ] 即使配置中曾保存小写或大写变体，最终也只有一个 `X-Request-Id`，值为当前任务 ID。

## 用例 2：图片编辑

1. 选择参考图片并提交图片编辑。
2. 在 Network 面板找到 `/images/edits` 请求。

预期结果：

- [ ] multipart 图片编辑请求包含 `X-Request-Id`。
- [ ] Request ID 不包含文件名、提示词、API Key 或图片数据。

## 用例 3：Google 原生图片协议

1. 选择使用 Google `generateContent` 协议的图片模型并提交任务。
2. 查看对应 `generateContent` 请求头。

预期结果：

- [ ] 统一传输层收到的 Request ID 与当前图片任务 ID 一致。
- [ ] 可信 Tuzi 提交包含 `X-Request-Id`，不受 OpenTu 公网页面域名影响。

## 用例 4：异步提交与轮询

1. 选择异步图片模型并提交任务。
2. 分别检查首次提交请求和后续状态轮询请求。

预期结果：

- [ ] 首次非 `GET` 提交请求包含 `X-Request-Id`。
- [ ] 后续轮询 `GET` 不包含 `X-Request-Id`。
- [ ] 轮询不会生成新的 Request ID。

## 用例 5：同一任务重试

1. 记录一次图片任务的 `X-Request-Id`。
2. 让该任务进入可重试状态并执行重试。

预期结果：

- [ ] 重试请求复用原任务 ID。
- [ ] 不会为同一任务生成另一个 Request ID。

## 用例 6：并发图片任务

1. 连续或并行提交两个不同图片任务。
2. 分别记录两个请求的 `X-Request-Id`。

预期结果：

- [ ] 两个任务的 Request ID 不同。
- [ ] 每个 Request ID 只关联各自任务。

## 用例 7：非可信自定义供应商

1. 选择非内置可信 Tuzi 地址的自定义图片供应商。
2. 提交图片生成请求并检查 Request Headers。

预期结果：

- [ ] 请求不自动附加 `X-Request-Id`。
- [ ] 不因额外自定义头触发供应商 CORS 失败。
- [ ] 在任意公网 OpenTu 页面中仍直连原 Base URL。
