# 图片 Request ID 与刷新恢复测试清单

更新日期：2026-07-30
测试范围：公网 Request ID 请求头、页面刷新后的只读恢复与卡片渲染

## 前置条件

- 使用可访问的公网 OpenTu 页面和可信 Tuzi 图片模型。
- 浏览器开发者工具保留 Network 日志。
- 不在截图或报告中暴露 API Key、图片原始数据或完整认证头。

## 用例 1：公网正式图片提交

1. 提交普通图片生成或图片编辑。
2. 检查正式 `POST /images/generations` 或 `POST /images/edits`。

预期：

- [ ] Request URL 位于 `bus`、`bus2`、`bus3` 或 `business.tu-zi.com`。
- [ ] 请求头存在唯一的 `X-Request-Id`。
- [ ] 首次提交的值等于任务 ID。
- [ ] OPTIONS 明确放行 `x-request-id`。
- [ ] 正常请求期间没有 `/images/generations/result` GET。
- [ ] 网络失败或 404 后没有第二个图片 POST。

## 用例 2：兼容节点保持

1. 将供应商 Base URL 配置为四个兼容节点之一。
2. 分别提交图片任务。

预期：

- [ ] 正式 POST 保持当前兼容节点。
- [ ] 四个节点均携带正确 Request ID。
- [ ] 不跨节点自动重提。

## 用例 3：GET 与第三方边界

预期：

- [ ] 异步状态 GET 和恢复结果 GET 不包含 `X-Request-Id`。
- [ ] 非可信自定义供应商不被自动附加该头。
- [ ] 第三方绝对 URL 不接收 Tuzi Token 或任务 Request ID。

## 用例 4：刷新后恢复成功

1. 提交同步图片任务并确认正式 POST 已发出。
2. 在图片完成前刷新页面。
3. 保留 Network 并等待上游结果。

预期：

- [ ] 页面恢复后只发送 `GET /images/generations/result?request_id=...`。
- [ ] GET 使用刷新前的提交 Request ID。
- [ ] 不重新发送图片 POST。
- [ ] 返回 `processing_or_not_found` 时任务继续等待，但不会同轮扫完所有节点。
- [ ] 返回 `succeeded` 后原任务变为完成。
- [ ] 原卡片与批量预览显示图片，不再永久卡在生成中。

## 用例 5：缓存失败降级

模拟或观察恢复结果缓存失败。

预期：

- [ ] 任务仍使用有效远程 URL 完成。
- [ ] 卡片仍能显示图片。
- [ ] 不重复下载或重复写入无界图片数据。

## 用例 6：取消、删除与重试竞态

预期：

- [ ] 取消或删除后旧轮询停止。
- [ ] 重试保持任务 ID，但生成新的提交 Request ID。
- [ ] 旧 Request ID 的迟到结果不能覆盖新重试。
- [ ] 已完成或失败的首个合法终态不会被后续写入覆盖。

## 用例 7：不恢复旧任务

准备缺少 `submissionRequestId` 或 `imageSubmissionAttempted` 的旧处理中任务。

预期：

- [ ] 不使用任务 ID 猜测查询。
- [ ] 不发送结果查询或图片重提。
- [ ] 按原有刷新中断行为明确失败。

## 用例 8：超时与资源清理

预期：

- [ ] 使用现有图片任务 15 分钟总时限。
- [ ] 到期明确失败，不进入 24 小时补偿。
- [ ] 完成、失败、取消、删除、重试和卸载后无残留轮询定时器或请求。
