# AI 生图、批量生图与视频结果无法渲染人工测试文档

**日期**：2026-09-07

**测试对象**：包含本次修复的 `develop` 派生分支

**局域网地址模板**：`http://${LAN_HOST}:${PORT}/`

**关联 Docs**：[AI 生图、批量生图与视频结果无法渲染修复交接文档](../docs/2026-09-07-AI生图批量生图与视频无法渲染-交接文档.md)

## 验收目标

1. 单图 AI 生图完成后，任务队列、画布和素材库可以正常显示。
2. 一个批量任务含多个 `result.urls` 时，预览、画廊、下载和 Excel 导出包含全部结果。
3. 视频任务完成后可以加载和播放，不因签名参数丢失返回 403。
4. HTTP `200` 的 HTML/JSON 错误响应不会被当成图片或视频缓存。
5. 缓存失败不阻断任务完成，原始 URL 保留且出现 `cacheWarning` 提示。
6. 历史坏缓存会重新获取有效源内容，不继续复用错误缓存体。

## 前置条件

1. 使用 `pnpm start:lan` 启动前端并监听 `0.0.0.0`。
2. 准备一个单图图片任务、一个含 2～4 个结果的批量图片任务和一个短视频任务。
3. 至少准备一个带签名参数的远程图片或视频 URL；测试记录不得包含完整签名 URL、API Key、Cookie 或鉴权头。
4. 打开任务队列、批量生图面板、浏览器控制台和 Network 面板。
5. 记录测试前任务数量、画布元素数量和素材数量。

## 人工测试场景

### 场景 1：单图 AI 生图

1. 提交一个单图生图任务并等待完成。
2. 依次查看任务队列缩略图、放大预览、画布插入和素材库。

**预期结果**：

- [ ] 任务进入完成态，图片可见且可放大。
- [ ] 画布插入后图片可见，刷新后仍能恢复。
- [ ] 不出现空白、破图、`clientWidth` 或解码错误。

### 场景 2：批量任务多结果展示

1. 提交一个返回 2～4 个结果 URL 的批量图片任务。
2. 检查行内预览、“查看全部”、下载和 Excel 导出。

**预期结果**：

- [ ] 所有 `result.urls` 均显示，顺序与任务结果一致。
- [ ] “更多”数量按实际图片数计算。
- [ ] 下载和 Excel 导出不漏结果。
- [ ] 同一任务多张图片不会互相串图或闪烁。

### 场景 3：视频生成与播放

1. 提交一个短视频生成任务，等待任务完成。
2. 在任务队列和画布中打开视频并播放。
3. 在 Network 中检查真实请求是否仍包含必要签名参数，但报告中只记录域名和状态码。

**预期结果**：

- [ ] 视频任务进入完成态并可播放、暂停和拖动进度。
- [ ] Service Worker 的真实下载没有因移除签名参数返回 403。
- [ ] 刷新页面后视频仍能恢复，或显示明确缓存告警。

### 场景 4：HTTP 200 错误体防护

1. 使用代理、Mock 或可控响应让媒体地址返回 HTTP `200` 的 HTML 或 JSON。
2. 观察任务状态、缓存和控制台。

**预期结果**：

- [ ] HTML/JSON 不会写入图片或视频缓存。
- [ ] 任务不被误判为媒体渲染成功。
- [ ] 原始 URL 被保留，并记录 `cacheWarning.reasonCode=response_unreadable` 或等价提示。

### 场景 5：缓存失败降级

1. 在 CORS、签名过期、Cache Storage 不可用或存储异常的环境执行图片和视频任务。
2. 查看任务队列的告警提示。

**预期结果**：

- [ ] 任务仍保持完成，不因缓存写入失败变成失败。
- [ ] 结果保留原始远程 URL，可在链接有效期内打开或下载。
- [ ] 任务队列/素材库提示资源可能过期并建议下载。
- [ ] 不自动删除其他缓存媒体。

### 场景 6：历史坏缓存恢复

1. 预置一个与目标缓存键相同但内容为 HTML/JSON 的旧缓存。
2. 重新打开任务或触发结果恢复。

**预期结果**：

- [ ] 历史坏缓存不会直接作为完成结果返回。
- [ ] 系统尝试重新获取源地址并校验媒体签名。
- [ ] 源地址也不可用时保留原始 URL并显示缓存告警。

### 场景 7：局域网 HTTP

1. 从同一局域网另一台设备打开 `http://${LAN_HOST}:${PORT}/`。
2. 重复场景 1、2、3 和 5，重点检查真实媒体是否可见。

**预期结果**：

- [ ] 工作台、任务队列和批量面板可正常使用。
- [ ] 无 Service Worker 或 Cache Storage 能力时，不出现 SPA HTML 冒充媒体。
- [ ] 图片和视频加载失败时有明确重试/告警，不静默变成空白。

## 通过标准

1. 单图、批量多图和视频结果均可完成并渲染。
2. 不缓存 HTML/JSON 等伪媒体响应。
3. 缓存失败时任务仍完成，原始 URL 和告警均保留。
4. 视频真实请求保留签名参数，LAN 环境不出现静默空白。
5. 不以首页 HTTP `200` 代替真实媒体功能验收。
