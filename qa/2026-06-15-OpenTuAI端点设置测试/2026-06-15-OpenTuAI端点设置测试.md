## 网页版快速验证步骤

### 方法 1: 设置页端点面板展示

1. 打开网页版测试地址。
2. 点击左上角应用菜单。
3. 进入“设置”。
4. 打开“供应商”页签。
5. 选择一个可编辑供应商，查看“API 地址”下方。

**结果判断**:

- ✅ API 地址下方显示端点管理面板。
- ✅ 面板显示“来源: tuzi-api”。
- ✅ 面板显示端点数量，且至少包含当前供应商 API 地址。
- ✅ 画布底部输入栏保持模型和参数选择，不出现额外端点管理控件。

### 方法 2: 自动选择与测速

1. 在端点面板中保持“自动选择”勾选。
2. 点击“测速”。
3. 等待测速结束。
4. 查看被选中的端点和 API 地址输入框。

**结果判断**:

- ✅ 测速期间有加载状态，不阻塞页面其他操作。
- ✅ 成功测速的端点显示 `ms` 延迟。
- ✅ 自动模式下会选择延迟最低的可用端点。
- ✅ API 地址输入框同步为被选中的端点。
- ✅ 测速失败的端点显示“失败”，不导致页面崩溃。

### 方法 3: 手动选择端点

1. 点击端点列表中的任意端点。
2. 观察“自动选择”勾选状态。
3. 保存设置后刷新页面。
4. 重新进入设置页查看 API 地址。

**结果判断**:

- ✅ 点击端点后切换为手动选择。
- ✅ 被点击的端点高亮。
- ✅ API 地址输入框同步更新。
- ✅ 保存并刷新后，供应商 API 地址仍为手动选择的端点。

### 方法 4: 自定义端点

1. 在自定义输入框中输入一个合法地址，例如 `https://api.example.com`。
2. 点击添加按钮。
3. 选择新端点。
4. 删除新端点。

**结果判断**:

- ✅ 合法端点能添加到列表。
- ✅ 重复端点会提示“端点已存在”。
- ✅ 非法地址会提示“请输入有效的端点地址”。
- ✅ 自定义端点可删除。
- ✅ 删除当前选中的自定义端点后，会回到自动可用端点。

## 开发回归参考

以下命令仅供开发回归使用，网页版 QA 主流程不要求在本地启动服务：

```bash
pnpm nx run web:typecheck
git diff --check
curl -L --max-time 8 -sS \
  https://api.tu-zi.com/api/status | node -e "
let s='';
process.stdin.on('data', d => s += d);
process.stdin.on('end', () => {
  const data = JSON.parse(s)?.data?.api_address_list || '';
  if (!data.includes('api.tu-zi.com')) process.exit(1);
});
"
```

**开发回归通过标准**:

- `web:typecheck` 无类型错误。
- `git diff --check` 无尾随空白或冲突标记。
- `tuzi-api` 状态接口可访问，返回 2xx。

## 常见问题排查

### 问题 1: 端点数量为 1

**原因**: `tuzi-api` 状态接口加载失败，页面使用内置的 6 个 tuzi-api 站点兜底。

**处理**:

1. 打开浏览器控制台查看网络错误。
2. 确认 `raw.githubusercontent.com` 可访问。
3. 确认当前供应商 API 地址仍可手动编辑和保存。

### 问题 2: 测速全部失败

**原因**: 端点可能不允许浏览器直接跨域读取，或网络环境阻断。

**处理**:

1. 确认页面没有崩溃。
2. 手动选择已知可用端点。
3. 保存设置后用一次文本或图片生成验证真实调用。

### 问题 3: 底部出现额外端点管理控件

**原因**: 浏览器缓存或旧构建未更新。

**处理**:

1. 强制刷新页面。
2. 确认当前访问的是本次 PR 构建。
3. 检查底部输入栏 DOM 中是否还有额外端点管理入口。
