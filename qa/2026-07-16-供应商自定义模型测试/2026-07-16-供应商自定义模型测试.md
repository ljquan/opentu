# 供应商自定义模型测试清单

**目的**: 验证用户可在供应商下添加未被自动发现的模型，并通过 OpenTu 原有文本、图片、视频和音频调用流程正确使用。
**创建日期**: 2026-07-16
**功能**: 手动模型目录、内置调用预设、自定义 HTTP、供应商路由、刷新保留和删除清理
**关联经验文档**: [docs/MANUAL_PROVIDER_MODELS_LESSONS.md](../../docs/MANUAL_PROVIDER_MODELS_LESSONS.md)

## 测试范围

- 在当前供应商下添加文本、图片、视频和音频模型。
- 添加后的模型立即进入已添加列表和对应模型选择器。
- 使用站内已有调用方式执行模型。
- 配置并执行受控的自定义 HTTP 请求。
- 同 ID 更新、跨类型冲突、远端刷新保留和删除清理。
- 使用正确供应商的 Base URL、API Key 和鉴权配置。

不测试端点管理、AI 任务栏、生图巡检等其他功能。

## 前置条件

1. 准备一个可用的供应商档案，并配置测试用 Base URL、API Key 和鉴权方式。
2. 准备文本、图片、视频、音频模型各一个，或准备可验证请求参数的本地兼容 HTTP 服务。
3. 记录测试供应商 ID、模型 ID 和调用地址，确保可判断请求实际命中的供应商。
4. 不在截图、日志或失败记录中暴露完整 API Key。

## 核心场景

### 场景 1：添加四类自定义模型

1. 进入供应商的模型设置区域。
2. 分别添加文本、图片、视频和音频模型。
3. 为每个模型填写模型 ID、调用方式，并按需填写显示名称和描述。

**结果判断**:

- ✅ 添加成功后模型立即出现在当前供应商的已添加列表。
- ✅ 模型只出现在对应类型的选择器中。
- ✅ 模型显示名称和描述保存正确。
- ✅ 刷新页面后模型仍然存在。

### 场景 2：必填字段与无效配置校验

1. 使用空模型 ID、仅空格模型 ID 提交。
2. 自定义 HTTP 模式下填写无效 JSON、无效 Header 模板或缺少请求地址。
3. FormData 模式下填写无法解析的字段配置。

**结果判断**:

- ✅ 空模型 ID 不会被保存。
- ✅ 无效模板在保存前显示明确错误。
- ✅ 保存失败不会产生半成品模型或残留 binding。
- ✅ API Key 不会被复制到错误提示或模型描述中。

### 场景 3：同 ID 更新和跨类型冲突

1. 添加一个图片模型。
2. 使用相同 ID、相同类型重新添加，并修改显示名称或调用方式。
3. 再使用相同 ID、不同类型提交。

**结果判断**:

- ✅ 相同 ID、相同类型更新现有条目，不产生重复模型。
- ✅ 新的显示信息和调用绑定生效。
- ✅ 相同 ID、不同类型不会静默覆盖原条目。
- ✅ 界面提示更换 ID 或先移除原模型。

### 场景 4：远端模型刷新保留手动模型

1. 添加一个远端 `/models` 不返回的自定义模型。
2. 执行供应商模型刷新。
3. 检查已添加模型和选择器。

**结果判断**:

- ✅ 自定义模型不会被远端发现结果删除。
- ✅ 自动发现模型与手动模型正常合并，无重复条目。
- ✅ 自定义模型原有调用绑定保持不变。

### 场景 5：移除模型并清理绑定

1. 移除一个已添加的自定义模型。
2. 刷新页面并重新进入设置。
3. 检查模型选择器和调用路由。

**结果判断**:

- ✅ 模型从当前供应商已添加列表中消失。
- ✅ 模型不再出现在对应选择器中。
- ✅ 对应 `manualBindings` 被同步清理。
- ✅ 其他模型及其绑定不受影响。

### 场景 6：使用站内已有调用预设

1. 为不同类型模型选择对应的站内调用方式。
2. 分别从原有文本、图片、视频和音频入口发起任务。
3. 观察请求路径、请求格式和结果解析。

**结果判断**:

- ✅ 系统自动使用预设的提交路径、请求体和响应格式。
- ✅ 异步任务按预设轮询路径获取结果。
- ✅ 提示词、参考图、尺寸、时长等参数由原生成入口正常传入。
- ✅ 返回结果继续进入原有任务状态和媒体结果处理流程。

### 场景 7：自定义 HTTP 同步请求

1. 分别配置 JSON、FormData 和 Raw 请求体。
2. 使用 `model`、`prompt`、`messages`、`image(s)`、`size`、`duration` 或 `params` 等所需变量。
3. 配置额外 Headers 和同步结果字段路径。
4. 发起对应类型任务。

**结果判断**:

- ✅ 请求命中用户配置的地址，Method 正确。
- ✅ 请求体变量替换正确，不包含未解析模板文本。
- ✅ Headers 正确合并，供应商鉴权仍然生效。
- ✅ 系统从配置字段提取文本或媒体结果。
- ✅ 自定义请求地址不被内置协议规则重写。

### 场景 8：自定义 HTTP 异步轮询

1. 配置提交路径、任务 ID 字段、轮询路径、状态字段、结果字段和错误字段。
2. 发起视频、图片或音频异步任务。
3. 模拟处理中、成功和失败响应。

**结果判断**:

- ✅ 首次响应中的任务 ID 被正确提取。
- ✅ 轮询路径中的任务 ID 替换正确。
- ✅ 处理中状态不会提前结束任务。
- ✅ 成功时提取并归一化最终结果。
- ✅ 失败时停止轮询并展示接口返回的错误。

### 场景 9：供应商归属与默认模型预设

1. 在两个供应商下添加相同 ID 的模型，并配置不同接口或凭据。
2. 分别选择两个模型发起调用。
3. 将其中一个模型设为对应类型的默认模型，刷新页面后再次调用。

**结果判断**:

- ✅ `ModelRef` 保留正确的 `profileId + modelId`。
- ✅ 每次请求使用所选供应商的 Base URL、API Key 和鉴权方式。
- ✅ 相同模型 ID 不会串用另一个供应商的绑定。
- ✅ 默认模型预设刷新后仍指向正确供应商。

### 场景 10：显式绑定优先于自动推断

1. 添加一个名称可被系统识别为内置协议的模型。
2. 为该模型保存不同的自定义 HTTP 地址和请求格式。
3. 发起任务并检查实际请求。

**结果判断**:

- ✅ 使用用户保存的手动绑定。
- ✅ 不因模型名称、异步偏好或 schema 偏好切换到推断 binding。
- ✅ 请求地址、Method、请求体和响应路径均与显式配置一致。

## 安全与性能检查

- [ ] 设置页不能输入或执行任意 JavaScript。
- [ ] 模板仅替换受支持变量，未知变量不会触发表达式执行。
- [ ] 模型目录和 binding 不保存媒体 Base64、完整响应历史或完整 API Key。
- [ ] 多次刷新和添加模型不会重复注册长期轮询或监听。
- [ ] 异步任务完成、失败或取消后停止轮询。
- [ ] 大请求体和媒体输入继续沿用现有传输限制，不产生无界字符串副本。

## 通过标准

以下条件全部满足才可判定通过：

1. 四类模型均可在指定供应商下添加、保存、选择和移除。
2. 远端模型刷新不会删除手动模型，删除模型会同步清理绑定。
3. 站内调用预设和自定义 HTTP 均能进入原有任务执行流程。
4. 显式手动绑定优先于自动协议推断。
5. 相同模型 ID 在不同供应商间不会串用接口或凭据。
6. 自定义 HTTP 不执行任意脚本，且异步任务能正确结束轮询。
