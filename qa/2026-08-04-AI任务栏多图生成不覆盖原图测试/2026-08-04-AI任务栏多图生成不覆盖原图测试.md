# AI 任务栏多图生成不覆盖原图测试清单

**创建日期**：2026-08-04

**测试范围**：仅验证选中生成图片后，按数量生成多张独立新图且不覆盖原图；单张生成继续原位替换。

**关联交接文档**：[2026-08-04-AI 任务栏多图生成不覆盖原图-交接文档](../../docs/2026-08-04-AI任务栏多图生成不覆盖原图-交接文档.md)

## 前置条件

1. 使用包含本功能的 OpenTu 网页环境。
2. 配置可用的图片生成模型和供应商。
3. 画布中准备一张已生成图片，能够让 AI 任务栏进入图片跟随状态。
4. 测试过程中不要记录 API Key、完整请求头或其他鉴权信息。

## 场景 1：单张生成保持原位替换

1. 单选一张已生成图片，使任务栏跟随该图片。
2. 将生成数量设为 `1个`，提交新的提示词。
3. 等待任务完成并检查画布。

**预期结果**：

- [ ] 只创建 1 个图片任务。
- [ ] 原图片元素 ID、位置、尺寸和层级保持不变。
- [ ] 图片内容被新结果替换，原位替换逻辑正常。

## 场景 2：多张生成不覆盖原图

1. 单选一张已生成图片，使任务栏跟随该图片。
2. 将生成数量设为 `3个`、`5个` 或 `10个`。
3. 提交新的提示词并等待全部任务完成。

**预期结果**：

- [ ] 创建的图片任务数量与选择数量一致。
- [ ] 原图片内容、元素 ID、位置、尺寸和元数据保持不变。
- [ ] 所有生成结果作为独立新图片插入画布。
- [ ] 多张结果不会互相覆盖，也不会堆叠在同一个替换目标上。

## 场景 3：多张生成仍使用当前图片作为参考

1. 选中一张生成图片。
2. 将数量设为 `5个`，修改提示词后提交。
3. 检查生成任务的参考图和最终结果。

**预期结果**：

- [ ] 每个新任务仍可使用当前图片作为参考图。
- [ ] 多图任务不携带当前目标的 `replaceElementId`、`targetElementId`、`anchorId`、`sourceTaskId` 或 `sourcePrompt`。
- [ ] 任务使用独立的批次序号和 anchor，不发生目标绑定串扰。

## 场景 4：数量切换与重复提交

1. 分别选择 `1个`、`2个`、`5个`，检查每次提交的任务数量。
2. 连续生成两批相同提示词的多图任务。

**预期结果**：

- [ ] 数量选择不会被绑定图片状态重置为 `1个`。
- [ ] 每批任务数量独立准确，不会跨批次累加或减少。
- [ ] 相同提示词的重复提交仍按用户选择创建新任务。

## 场景 5：失败与目标变化

1. 多图任务生成期间取消或让其中一个任务失败。
2. 生成期间取消选中原图片，或删除原图片。

**预期结果**：

- [ ] 已完成的新图仍可独立插入，不回写或覆盖原图。
- [ ] 失败任务只影响自身，不导致其他批次任务重复替换。
- [ ] 原图被删除时，不产生针对已删除目标的替换写回。

## 通过标准

1. `count=1` 保持原位替换。
2. `count>1` 生成数量准确，原图不变，结果全部为独立新图。
3. 多图任务不携带目标替换字段，且批次任务互不串扰。
4. 自动化回归通过，人工场景无阻断性问题。
