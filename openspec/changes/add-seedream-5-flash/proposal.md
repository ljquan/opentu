# Change: 接入 Seedream 5.0 Flash 图片生成

## Why

用户提供了 2026-10-26 版 Seedream 5.0 Flash Tuzi v3 调用文档，并要求开始接入。当前项目没有精确模型 `doubao-seedream-5-0-flash-260915` 的专属合同；按现有 Seedream 标签推断会使用旧 `/images/generations` 路由和 2K/3K/4K 尺寸映射，无法满足 Flash 的接口限制。

项目已有图片任务、Provider 鉴权、参考图、图片缓存和自动分层链路，应在这些入口内增加精确模型支持。

## What Changes

- 在现有图片模型选择中增加 Seedream 5.0 Flash，保留完整请求 ID 和 Provider 身份。
- 为该模型增加独立请求 schema 和适配器，使用当前所选服务的 `POST /api/v3/images/generations`，同步读取结果。
- 支持文生图、最多十张参考图生成，以及恰好一张带透明通道参考图的透明背景生成。
- 尺寸菜单提供 `1K`、`1.5K`、`2K`；程序调用也接受满足文档像素数和宽高比限制的精确宽高。Flash 不继承旧 Seedream 的尺寸和质量控件。
- 支持 PNG/JPEG、背景、水印、标准提示词优化；默认显式使用 `1K`、URL 返回、PNG、关闭水印、不透明背景。这些是本项目的默认设置，不宣称是服务默认值。
- 按白名单组装请求，保留布尔值 `false`，省略未设置字段；非法组合在发出生成请求前报错。
- 复用现有图片结果和缓存路径，支持 URL/Base64，保留原始响应及服务报告的实际尺寸；实测像素以图片解码结果为准。

## 图层拆分边界

本次先接入普通生成及透明背景。Flash 的图层自动定位暂不开放，也不替换现有本地分层和 Pro 兜底路径。

原因：现有分层合同要求 `[x1,y1,x2,y2]`、0～1000 归一化坐标、`z_index=0` 底图及层级升序；用户提供的 Flash 文档没有明确这些语义。新增普通图片适配器不得将拆图产物当作独立生图结果自动插入画布。

后续开放原生拆图前，需确认以下四项并补充验收样例：

1. 边界框四个值的顺序，以及坐标相对于输入原图还是输出底图。
2. `normalized` 的尺度及与 `absolute` 的换算关系。
3. 底图的可靠识别方式和 `z_index` 的前后顺序。
4. 元数据缺失时的服务行为与客户端处理约定。

## Impact

- Affected specs: `image-generation`、`provider-routing`。
- Affected code: 模型配置及参数、适配器注册和选择、Provider binding 推断与旧 binding 兼容、参考图及工作流参数传递、相关单元测试。
- 复用现有鉴权和传输，不新增服务、依赖、数据库迁移或独立执行器。
- 后续实现需要新增 `docs/seedream-5-flash.md` 和 `docs/qa-seedream-5-flash.md`，记录最终行为及实际验证。

## Validation

- 覆盖正确路径与旧 `/v1` 配置的路径拼接、精确模型匹配、旧绑定更新和相邻 Seedream 模型回归。
- 覆盖尺寸边界、参考图数量、透明背景组合、透明通道保留、字段类型和未知字段隔离。
- 覆盖 URL/Base64、JPEG MIME、实际尺寸元数据、无效结果、HTTP 错误和提交结果不确定场景。
- 验证原生图片调用、任务/工作流入口的参数一致性、类型、定向 lint 和 Web 构建。
- 默认不执行页面测试或真实付费生成。真实服务、浏览器 CORS、图片透明效果和计费不以 mock 测试代替。
