# Change: 主画布吸收差异能力并移除工作流模式

状态：用户已确认；本地实现及适用自动验证完成。CLI strict 与人工页面/真实数据验收未执行，见 QA。

## Why

OpenTu 主画布与工作流模式同时包含生成、素材、提示词、参考输入、图片编辑和任务能力，形成两套界面、数据和维护路径。目标是以主画布为唯一创作入口，保留其已有能力，吸收工作流真正有用的差异，随后删除工作流模式，而非只隐藏入口。

当前代码已将工作流并入同一 React/Vite 运行时。旧变更 `merge-workflow-into-opentu` 保留独立工作流页面，不能用作本次删除模式的实施批准。

## What Changes

### 最终用户效果和能力取舍

| 能力 | 本次处理 |
| --- | --- |
| 提示词历史、分类搜索、置顶、素材库、模型配置 | 沿用主画布已有实现，不复制第二套 |
| 图片提示词回填、再次生成、逐目标输入草稿、参考图与蒙版 | 沿用主画布已有实现，补充移除工作流后的回归验证 |
| 多媒体画布引用、来源到结果的关联线 | 沿用主画布已有实现，保留其任务和画布归属 |
| 图片快捷工具配置 | 吸收工作流中选择常用工具、显示或隐藏文字的交互；只配置当前选择对象适用的工具，未固定的工具仍可从更多菜单访问 |
| 手动拆图 | 在已有智能拆图之外补充可调整横纵分割线的手动拆分，预览后确认；不因未检测到自动分割线而阻止手动拆分 |
| 本地图片放大 | 补充按目标尺寸及插值方式放大，显示实际输出宽高，保持比例；明确为本地处理，不能宣称增加真实细节 |
| 视角编辑 | 吸收角度参数生成提示词的能力，带原图回填主画布现有生成输入，由用户手动发送；预览仅示意，不代表模型输出 |
| 独立节点配置、独立编排画布 | 不保留第二套编辑器和执行系统；旧配置节点内容可保留为可查看的迁移资料，连接能否转为主画布关联线须逐种验证 |
| 独立生图/视频工作台、批量生成、提示词和资产页面 | 删除独立页面，功能统一使用主画布已有输入、批量生成工具、提示词工具和素材库；并非把页面改名后继续保留 |
| 工作流专属插件和本地 Canvas Agent | 删除该模式的专属运行代码，不将其外部插件协议默认移植到主画布；保留主画布自身工具、Agent、Skill 和插件系统 |

上表的差异能力是建议的本次完整范围，需随本方案一并确认。正式实施前仍须检查调用链，发现主画布已有等价能力时复用，发现无法等价承接的关键行为时记录并重新确认，不靠增加平行系统规避问题。

### 历史数据

- 删除代码不清空浏览器数据库，也不读取用户当前浏览器数据作为开发测试样本。
- 在主画布设置/数据管理中提供按需加载的旧数据兼容入口；兼容代码放在普通数据导入模块，不依赖被删除的工作流目录和运行时。
- 先提供旧项目、素材、提示词及其本地媒体的可恢复导出，再支持可转换内容导入主画布；导入由用户触发，创建新内容，保留源记录。
- 图片、文本、视频、音频尽量保留内容、位置、尺寸和生成提示词；不支持的节点、配置、聊天或插件数据进入备份及转换报告，不默默丢弃，也不承诺原样继续执行。
- 配置中的 API Key 不写入普通导出包、转换报告或日志；渠道与模型映射必须显式确认，不以同名模型猜测原路由。
- 旧在途任务不自动重发生成请求；仍可由共享任务系统查询的任务保留查询能力，不能恢复的任务标明结果待确认。
- 旧 `/workflow` 及其深层链接转到主画布并提供历史数据入口，不再挂载工作流编辑器。

### 删除边界

- 在承接能力与数据兼容完成后，删除 `packages/drawnix/src/workflow-mode/` 全目录。
- 删除模式专用导航、路由挂载、样式隔离脚本、静态资源插件、测试入口、别名和无用配置。
- 按实际引用删除独占依赖，并更新锁文件；被主画布或其他工具使用的依赖继续保留。
- 保留主画布的 `WorkflowEngine`、`WorkflowContext`、工作流提交/完成服务、SW 通信、任务恢复和影音创作流程。名称包含 workflow 不等于属于工作流模式。
- 历史规格、提交记录和历史 QA 不因出现工作流字样批量删除；当前说明更新为新行为，并明确旧记录的适用边界。

## Impact

- Affected specs: 新增 `canvas-consolidation`；沿用现有图片生成、输入、备份恢复和工具能力契约。
- Affected code: 主画布图片工具栏与编辑辅助函数、数据导入/备份、`drawnix.tsx`、工作流模式目录、Vite/PostCSS/TypeScript 配置、依赖与测试配置。
- BREAKING：删除独立工作流 UI、配置节点执行及其专属插件/本地 Agent；不能把只保留原数据库称为完整数据兼容。
- 不涉及推送、创建 PR、部署、收费 API 测试或操作用户已运行服务。

## Acceptance

1. 主画布覆盖上表确认的差异能力，原有生成、逐目标草稿、引用、蒙版、批量生成和任务恢复无本次引入的回归。
2. 工作流模式目录和运行依赖移除，生产构建不再产生该模式及其资源；旧链接可安全到达主画布。
3. 使用合成旧数据验证导出和导入：源数据不改写，媒体可读，失败有报告，重复导入不静默覆盖，普通导出无密钥。
4. 不支持的旧执行能力明确列出；旧在途任务不会因进入主画布、导出或导入而重复提交。
5. 受影响单元/组件逻辑测试、类型、静态检查和构建执行并记录；基线失败与本次失败分开。
6. 默认不做浏览器、页面点击、截图和真实供应商调用；这些未覆盖项写入最终 QA。
7. 更新已有工作流 QA 的适用状态，新增本次整合的 QA 与使用/维护说明，更新文档索引。

## Approval boundary

本方案包含真实功能退役、历史数据转换和跨模块删除，按 `openspec/AGENTS.md` 的 “Do not start implementation until the proposal is reviewed and approved” 要求，用户已明确确认本方案并要求开始修改。该审批节点已通过，不重复询问删除工作流模式的授权。
