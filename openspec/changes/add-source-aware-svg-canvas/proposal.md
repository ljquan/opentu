# Change: 按 2.6 实际输出适配 SVG 编辑与自带动画

## Why

用户希望 SVG 在画布里既能编辑内部元素，也能显示动画，并进一步明确：必须是 2.6 实际具有、实际返回的能力，不能由前端强制补出。

当前画布通过图片节点和 RetryImage 显示 SVG；没有将 SVG 内部形状转换为可编辑画布元素的通路。SVG 格式本身支持某些动画，不能因此宣称渠道提供“SVG 动画生成”。

## 已核对的证据（2026-11-08）

- 当前渠道公开目录 `https://api.tu-zi.com/api/pricing` 明确说明：Flare / Sunburst 支持 GIF，指定官方分组支持 SVG，并注明 SVG 适合继续编辑形状、路径和颜色。
- 同一目录明确 `gpt-image-2.6-1k` 不支持 SVG。无后缀型号的公共描述仍为通用文本家族，不足以确认它的完整 SVG 契约。
- 当前上述型号说明未提供 SVG 动画生成、图层命名、可编辑节点数量或动画时间轴的保证。通用 Apifox 生图页面也没有补足 2.6 专属的这部分契约。
- 本次没有发起生图请求、读取生成凭据或验证截图对应的原 SVG 内容；不能从截图判断其是否带动画。

## 用户可见效果（已确认）

用户于 2026-11-08 确认“按源文件实际能力适配两项”。以下能力在本地实现，实际验证范围见 `validation.md`。

1. 读取实际返回的 SVG，先判断它包含可独立编辑的矢量图形、已有动画，还是只嵌入了一张位图。判断依据来自文件内容，不依赖型号名称或扩展名猜测。
2. 对可转换的静态矢量 SVG 提供“转为可编辑副本”：按文件中已有的形状、路径、文字和必要分组创建独立 SVG 部件，支持单独选择、移动、缩放、适用颜色和简单文字修改，保留原始 SVG 供恢复/下载。路径继续保持矢量，不提供原生路径锚点编辑，也不通过 AI 重新分层。
3. 对文件中确有受支持自带动画的 SVG 提供播放/暂停；静态 SVG 保持静态，不出现可用播放操作，不增加任何动画代码或生成请求。该入口表示“这个文件有动画”，不表示全部 2.6 型号支持 SVG 动画生成。
4. GIF 继续按实际 GIF 文件播放，SVG 与 GIF 保留各自格式。不会把静态 SVG 转为 GIF 来声称它本来会动。
5. 遇到不能保真转换的复杂效果时，保留完整原图并明确说明限制。转换失败时不替换原图、不只留下部分元素；嵌入位图不能被标为可编辑矢量。
6. 编辑与动画分别依据源文件判断。转换为静态画布图形时不宣称动画仍然存在；原始带动画 SVG 继续保留。若不能同时保留两种表现，先说明具体限制。

## 范围与边界

- 本次为客户端对既有产物的适配，不修改 2.6 请求参数、提示词、分组、供应商、默认模型或帧数，不增加自动收费调用。
- 不为静态文件合成动画，不为位图生成不存在的矢量路径，不执行返回 SVG 的任意 JavaScript。支持边界见 `design.md`。
- 复用已有图片缓存、任务关联、画布历史和恢复方式；保留本地尚未提交的 2.6 多结果排版修复。
- SVG 新解析、显示或存储字段涉及多个模块。实现采用现有图片节点加可选元数据；外部引用、复杂样式及不可转换效果保留原图，旧数据无需迁移。

## 验收方向

- 使用静态矢量、嵌入位图、原生动画、混合结构和复杂效果文件分别验证能力识别，静态图不能误判为会动、位图不能误判为可编辑矢量。
- 验证转换后位置、比例、层次、分组、颜色及适用文字编辑；转换失败、资源缺失和画板切换保留完整原文件；覆盖撤销/重做及刷新恢复。
- 验证已有动画不会被静态缩略图替换；未支持的动画明确回退，不伪装播放成功。具体播放表现仍需真实浏览器证据，jsdom 断言不能代替。
- 遵循项目默认规则：先做单元/组件逻辑、类型与构建检查，不自动进行页面测试或新增收费调用。真实浏览器动画验收、供应商真实产物补测需要对应的明确授权或已有用户文件。

## Impact

- Affected specs: 新增 `svg-canvas`，与现有 `image-generation`、`media-preview` 的行为兼容。
- 涉及：SVG 内容识别/解析，画布图片工具栏，SVG/图片显示，原文件缓存与恢复，转换后的元素及历史记录。
- 实现、测试和交付边界见 `design.md`、`tasks.md`、`validation.md`。本地实现不等同于渠道动画生成能力或线上部署证明。
