# Change: 补齐六个 Tuzi 视频型号的高级参数与素材输入

状态：2026-11-14 用户以“可以”批准，已完成本地实施和验证；未提交或部署。用户在参数审查后明确要求全部接入，并要求核实本地图片转公网 URL 的能力。

## Why

当前六个型号已经支持基础生成，但缺少 Gemini 多模态与编辑/延展、Wan 混合参考素材及生成选项、Kling 素材角色/主体/音色；HappyHorse I2V 的可选提示词也未贯通上层校验。只补请求构造函数不足以让用户实际使用这些能力。

## What Changes

- Gemini Omni 1.2：补图片/视频多模态输入、生成/编辑/延展动作及本站前序任务选择；本地图片读取为带 MIME 的原始 Base64 内容，公网素材使用 URI。输出分辨率与比例分别选择。
- Wan 3.0：补参考图/视频/音频、首尾帧模式、音轨、提示词改写、随机种子、文档/网页辅助输入及智能时长。完整校验互斥模式、数量、范围及依赖。
- Kling 4.0：补首帧/中间帧/尾帧/参考图、参考视频/待编辑视频、主体 ID、音色 ID，以及素材 ID 和数量校验。复用现有尺寸、比例、水印控件。
- HappyHorse 1.1 三型号：保留各自图片语义；贯通 I2V 无提示词提交；补本地图片可验证的像素、比例、格式和大小检查。
- 普通素材由输入栏自动引用，无需高级素材表单；工作流、MCP、主线程和共享路径使用相同请求合同。复杂角色、主体和音色支持程序调用；其余生成选项通过参数菜单提供。
- 保留既有任务 ID、轮询、下载、画布插入和错误详情，不通过重复创建任务恢复结果。

## 已核实的转换边界

本地 Tuzi 源码提供内部图片暂存/URL 转换，但暂未确认普通模型密钥可用的通用图片上传接口。`/api/content-assets` 是管理员接口；`/suno/api/file-*-upload` 属于 Suno 渠道；`/v1/media/video` 是 MiniMax 视频暂存接口，均不能直接视作通用图片转换 API。

Gemini 当前公开说明已声明 `input[].mime_type` 与原始 Base64 `data`，因此本地图片可以通过该合同接入，不必先得到公网 URL。如果随后核实到普通调用凭据可用的 Tuzi 图片上传合同，再复用该合同；不猜地址、不借用管理员身份、不自动上传到第三方图床。

## Impact

- Affected specs: 新增 `tuzi-video-inputs`。既有 `update-kling-capability-version-routing` 处理旧标准 Kling 能力入口，本变更只处理精确 ID `kling-4.0`，不合并两种协议。
- Affected code: `tuzi-video-models.ts`、模型参数目录、输入栏/视频素材控件、输入解析与工作流、MCP/任务校验、生成偏好、`tuzi-video-request.ts`、视频提交适配器及测试。
- 更新现有 `docs/tuzi-video-model-parameters.md` 和对应 QA，实施后以实际结果标记范围，不提前记为通过。
- 无新依赖、数据库迁移或后端修改；本次授权限本地实施与非收费测试，提交/推送/PR 和真实生成另按用户授权执行。

## 服务与验收边界

Tuzi 公开 Wan/Kling 通用参数表与专属模型说明存在差异；按专属合同和已验证请求结构实施。本地 Gemini 后端源码仍仅识别 1.1，当前 1.2 公开页面也标记尚未开放，因此客户端参数适配不能等同于线上模型可用。

验收要求是普通参考素材从输入栏自动提交，高级角色通过程序调用接入、正确请求映射和失败边界；服务未开放或渠道未启用时保留明确错误，不换模型、不丢参数、不重试创建生成。默认执行本地逻辑、组件、请求模拟、类型和静态检查，不进行页面测试或收费请求。
