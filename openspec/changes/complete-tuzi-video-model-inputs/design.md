## Decisions

1. **统一结构与提交前准备分开。** 用可序列化的型号专属素材描述贯通偏好/工作流；由当前调用入口读取缓存/本地文件，统一构造函数完成白名单、类型、范围、互斥和请求映射。保留既有简单参考图行为和顺序。
2. **本地 Gemini 图片优先走明确的多模态合同。** Data URI 去掉前缀后发送原始 Base64，保留真实 MIME；不把 Data URI 误写为 input_reference。公网图片地址没有可靠后缀时也使用显式 MIME 的 input。若未来启用上传合同，凭据只交给当前所选 Tuzi 服务，失败不得触发生成。
3. **提示词校验按能力判断。** I2V 图片完整时允许无文本；Gemini 显式媒体输入不被通用 prompt 校验阻断。修改 MCP、任务与实际提交的全部校验层，其他型号的必需提示词继续严格校验。
4. **恢复不会重发任务。** 新参数随原 profile/model 保存和恢复；既有 Kling 组合尺寸迁移保留。编辑/延展只使用本人可访问且已完成的本站任务，后端再次执行路由与权限检查。
5. **已知限制提前校验，服务权限留在服务端。** 本地 HappyHorse 图像检查 I2V 最小 300 像素和宽高比 1:2.5–2.5:1，R2V 短边至少 400，每张不超过 20 MB；远程无法读取时不伪称已完成图像校验。Wan 首尾帧与混合素材互斥、file/link 互斥且依赖改写，Kling 检查 ID 和可判定的数量/时长。远程媒体和主体实际属性由渠道最终验证。
6. **渠道限制明确呈现。** Wan 智能时长与参考视频可能受计费用量能力开关限制；客户端不修改开关，不降级为另一模式。Gemini 1.2 尚未开放时正确展示接口错误，不退回 1.1。不同请求形式属于同一功能的序列化选择，不额外暴露多套互斥开关。

## 测试与风险

- 纯逻辑/模拟请求：每个型号成功、失败、范围边界、空值、0/false、互斥、ID 重复、超数量、媒体类型、URL/Base64 两种输入；断言实际请求正文而非仅构造函数内部结果。
- 组件/工作流：菜单与请求枚举一致、输入栏素材自动映射、空提示词、切换型号不串参数、恢复旧任务和偏好、MCP 与主/共享线程一致。
- 回归：旧 HappyHorse、旧 Kling、Veo、现有普通视频提交/轮询/content 下载和结果插入；类型与受影响 lint。
- 不新增页面自动化或收费请求；未来需要真实验证时先列具体型号、参数、次数并单独取得授权。
- 主要剩余风险：Gemini 1.2 服务未开放、旧参考源码与生产不一致、远程媒体缺少 CORS/元数据、渠道未启用参考视频或智能时长；均不得记录为已通过实测。
