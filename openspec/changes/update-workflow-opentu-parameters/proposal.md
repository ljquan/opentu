# Change: 工作流全面对齐 OpenTu 全部模型参数

Status: implemented, local validation complete; supplier verification pending

用户已明确要求覆盖全部 OpenTu 模型，并以“开始”批准实施本方案。

## Why

工作流已经通过宿主调用 OpenTu 原生模型，但模型目录只包含名称与能力，参数面板仍使用工作流自己的通用选项。用户选择 MiniMax-H3 时仍看到 480p / 720p / 1080p、自定义像素和通用首尾帧模式；OpenTu 实际定义的是 768P / 2K、4-15 秒、独立比例与 V1 / V2 接口版本。当前原生请求也没有完整携带模型专属参数，导致界面配置与执行语义不一致。

此前 `.codex/specs/workflow-opentu-model-defaults/spec.md` 批准的是模型目录与原生调用接入，并明确将红框控件排除在范围外。本提案承接用户本次“全面适配”请求，补齐参数配置到实际请求的完整链路。

## What Changes

- 宿主从现有模型参数表、视频配置与实际调用适配器提取不含凭据的参数描述，按渠道和模型标识提供给工作流。
- 视频、图片、文字、音频设置按模型显示真实选项、默认值、数值范围和条件字段；优先完成截图中的视频设置与模型切换。
- 区分尺寸、清晰度、画质、比例、时长及生成模式的供应商语义，保留模型参数原始值，不统一转换成像素或追加 `p`。
- 将节点参数、模型切换、参数摘要、刷新恢复、重试及生成配置节点接入同一套参数解析逻辑。
- 扩展原生请求桥接、宿主校验与适配器映射，保证可编辑参数到达实际消费者；不支持的选项明确禁用并给出原因。
- 将参考素材的首帧、尾帧、参考图、参考视频和参考音频按现有适配器的能力传递；不支持的输入在提交前报错，不能静默忽略。
- 补齐音频与歌词的结果类型，以及文字上下文所需字段，避免模型参数已选但结果或执行链路无法承接。

## Scope And Acceptance

用户已明确范围为 **全部 OpenTu 模型**。覆盖集合由 OpenTu 完整内置模型目录、启用渠道的运行时发现模型、手工绑定模型和默认路由模型共同确定，按 `(profileId, modelId, capability)` 去重；不以当前默认模型、已勾选模型或截图模型缩小范围。MiniMax-H3 仅作为一个差异示例，不是单独交付范围。

必须逐模型建立覆盖记录：模型身份、参数来源、全部可配置字段、参考输入、调用适配器、最终请求映射、结果类型和验证证据。所有条目都必须有明确状态；宿主已有能力但工作流尚未接通的条目属于未完成，不能通过隐藏模型或禁用字段算作完成。宿主本身没有的能力单独列为上游限制。

| 范围 | 目标行为 |
| --- | --- |
| 视频 | MiniMax-H3、Seedance、Kling、Veo、Sora 及现有目录中的其他视频模型使用各自参数；专属字段只在适用模型出现 |
| 图片 | 尺寸/比例、分辨率、画质、数量、背景及模型专属参数按现有适配器区分；不以图片像素尺寸代替所有模型的 `size` |
| 文字 | 系统提示词、上下文、采样参数、输出长度及已支持的推理配置到达文字执行器；不能只携带最后一条提示词 |
| 音频 | TTS 音色/格式/语速与 Suno 标题/风格/版本/纯音乐/歌词等分开配置；结果按音频或文字写入对应节点 |
| 保存 | 参数按渠道、模型和能力隔离；刷新与重试保持配置，切换模型不会把其他模型的无效参数发出去 |
| 自定义渠道 | 保留独立调用和脚本行为；未知原生模型不套用另一个模型的参数，不假定其支持通用视频设置 |

完成标准是覆盖集合内每一个模型的现有 OpenTu 能力都得到工作流承接，每一个启用的控件都有经过验证的请求映射、持久化和结果处理。仅让模型出现在下拉框、通过少数代表模型或完成某一个模型均不算全面适配。目录可选不代表供应商已开通该模型；模拟验证与真实供应商验收分开记录。

## Impact

- Affected specs: `workflow-opentu-parameters`（新增参数对齐能力），承接现有 `workflow-canvas-mode` 和模型接入设计。
- Primary code: `packages/drawnix/src/workflow-mode/shared/`、`host/`、`web/src/components/*-settings-panel.tsx`、`web/src/components/canvas/`、`web/src/stores/`、`web/src/services/api/`、节点类型与生成执行逻辑。
- Reused sources: `constants/model-config.ts` 的 `getCompatibleParams()`、`constants/video-model-config.ts`、`services/model-adapters/`、文字执行器与供应商绑定解析。
- 宿主公用执行器仅在已有能力无法通过当前接口表达时做必要扩展，并对普通画布执行回归；不新增供应商引擎。

## Boundaries

- 不修改模型账号、密钥、收费配置或发布状态；本地验收不发起付费生成。
- 不调整主题、工作流布局、普通画布数据，也不引入新的超时、重试或并发策略。
- 不自动修改历史业务数据；若持久化结构需要破坏性升级，应保留原记录并单独说明迁移方案。
- 此次只新增提案文档与待办，尚未修改运行代码，也未将任务标记完成。
