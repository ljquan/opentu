# 工作流 OpenTu 参数适配设计

## Context

已核对的实现证据：

- `host/native-models.ts` 的 `mapNativeModels()` 仅输出模型名称与 capability，没有参数描述。
- `web/src/components/video-settings-panel.tsx` 固定使用 480 / 720 / 1080、通用比例、数值时长与 frames / reference 两种模式。
- `web/src/services/api/video.ts` 的原生分支仍调用通用尺寸、时长和分辨率归一化函数，且未发送 `videoMode`；参考视频和音频直接拒绝。
- `shared/generation-bridge.ts` 只有有限的顶层通用字段；`host/native-generation.ts` 的视频分支只传 aspect_ratio / resolution / generate_audio / watermark，并对一个 Seedance adapter 做特判。
- `web/src/services/api/image.ts` 的原生文字分支仅传 prompt 与 images；宿主音频分支遇到 lyrics 结果直接抛错。
- `constants/model-config.ts` 已有 `ParamConfig` 和 `getCompatibleParams()`，视频、图片、音频参数有兼容模型、默认值、枚举或数值边界；视频配置另有参考图片模式与数量约束。

## Goals

1. 配置面板显示的参数与实际发送的参数一致。
2. 复用宿主的当前模型定义与适配器，工作流不复制一份供应商参数清单。
3. 每个节点独立保存配置，覆盖模型切换、重新进入、重试、配置节点和直接生成入口。
4. 全面覆盖现有参数消费者；没有消费者的字段明确标注不可用，不能以泛型透传声称已经适配。
5. 覆盖 OpenTu 完整内置目录、启用渠道发现模型、手工绑定模型与默认路由模型。图片、视频、文字、音频是同一交付范围，视频先做只代表实施顺序。

## Approaches

| 方案 | 优点 | 代价与判断 |
| --- | --- | --- |
| 宿主导出参数描述，工作流动态渲染并通过宿主执行 | 单一来源，可校验渠道归属，沿用现有 iframe 边界 | 需要扩展桥接契约；推荐 |
| 工作流直接 import 宿主模型表 | 初始改动较少 | 独立构建耦合宿主依赖，难以准确表达运行时渠道绑定；不采用 |
| 按模型在工作流逐个硬编码表单 | 可快速处理单个 MiniMax-H3 面板 | 参数表重复维护，无法满足全面适配；不采用 |

## Decisions

### 1. 参数来源与快照

以完整内置目录与当前渠道目录的并集建立覆盖清单，按 `(profileId, modelId, capability)` 保留每个身份。同系列模型可以共享适配代码，但每个模型仍需要枚举其参数差异并有覆盖记录。内置模型没有可用渠道时记录为未配置路由，不能为完成清单擅自绑定渠道。

验收清单包含参数定义、默认值、条件字段、参考素材角色、适配器、最终请求消费者、结果处理和本地验证证据。宿主已支持但工作流缺少桥接或控件的项必须补齐，不能把这种缺口归为模型不支持。真正缺少宿主契约的动态模型记录缺失的具体信息，不猜测供应商能力。

宿主为每个 `(profileId, modelId, capability)` 构造可序列化参数描述：字段 ID、标签、类型、默认值、枚举、数值约束、适用条件、参考素材能力、可用状态及原因。以现有 `getCompatibleParams()` 和视频配置为基础，并核对实际绑定所选适配器的消费者。

模型标识与参数描述不包含密钥、请求头或函数。不同渠道的同名模型必须保留独立身份。重新同步时刷新原生元数据，不覆盖用户脚本和节点参数；删除或停用的原生模型在当前目录中不可继续提交。未知模型只提供已确认的能力，不能继承任意内置模型的表单。

### 2. 控件与交互

视频面板首先对齐截图：清晰度、比例、时长、模式和专属字段跟随当前节点的模型。枚举使用选择控件，布尔使用开关，数值使用带宿主边界的输入控件；固定时长集合不能用连续滑块制造不存在的选项。像素宽高只对确实接受像素尺寸的模型出现。

MiniMax-H3 的具体期望来自当前仓库定义：分辨率 768P / 2K，时长 4-15 秒、默认 5 秒，比例独立配置、默认 16:9，接口版本 V1 / V2、默认 V1。首尾帧模式必须由模型能力确认后再显示，不能套用默认 `frames`。

图片、文字与音频复用同一描述渲染规则，并保留适合业务的专用控件。参数摘要由当前有效值生成，与提交时使用相同解析结果。禁用原因贴近具体控件或错误提示，不在界面放实现原理说明。

### 3. 状态与持久化

为每个节点保存按渠道、模型和能力区分的参数值。首次选择采用宿主默认值；切回已配置模型恢复该模型的有效值。模型描述更新后无效值在界面明确指出，并阻止提交直到修正或用户采用默认值，不静默改写后发起生成。

全局偏好只给新节点提供初值。修改节点参数不能修改其他节点或宿主偏好。节点直接生成、配置节点、工作台、重试和重新运行共用参数解析函数，避免各入口拼装不同的请求。

### 4. 请求、类型与校验

桥接请求显式区分模型参数、素材引用和文字消息，参数值只允许协议支持的可序列化类型。宿主重新读取当前目录，执行身份、字段白名单、类型、枚举、范围、必填依赖和素材角色校验；不能信任子页面携带的参数描述。

通过校验后，按照现有消费者映射到 `size`、`duration`、`params`、图片输出配置、Suno 顶层字段或文字执行器参数。`768P`、`2K`、`720p@16:9`、`adaptive` 等值保持各自语义；清晰度、画质和比例不相互替代。未知键不得覆盖路由、模型、鉴权或回调。

每个声明支持的参数都要追踪到最终请求构造代码。若宿主已有能力在当前 adapter 中丢失，补齐该 adapter 的必要映射并覆盖回归；宿主完全没有的能力明确不可用，不在此次实现供应商新引擎。

### 5. 素材与结果

参考图顺序和角色在连接、面板显示、持久化、请求中保持一致。只有现有适配器支持的模式才接收对应首尾帧、参考图、视频或音频；数量、必填项和组合约束来自已有模型定义。未知约束不能用经验值替代。

结果使用明确类型区分图片、视频、音频、歌词和文字。Suno 歌词写为文本节点，音频结果保留返回的各有效片段；无法处理的结果类型显式报错。异步结果仍归属请求发起的工作流与节点，不写入普通画布。

## Verification

- 全目录覆盖：从当前内置目录、发现目录、手工绑定与默认路由生成覆盖集合，核对没有缺失或重复身份；每个模型都必须覆盖默认值、全部支持字段和实际请求映射。
- 完整性回归：新增模型或模型专属参数后，缺失适配记录或字段消费者应使覆盖检查失败；不能只用几个代表模型的测试替代全量检查。

- 参数契约：已知模型、动态模型、同名不同渠道、手工绑定、元数据更新与禁用模型。
- MiniMax-H3：768P / 2K、4 与 15 秒边界、各合法比例、V1/V2 路径，以及非法 720p、非法时长被拒绝。
- 视频模型矩阵：Seedance 1.x / 2.x / 2.5、Kling、Veo、Sora 的尺寸/时长/参考素材模式不互串；其他已配置模型纳入参数消费者清单。
- 图片/文字/音频：分别捕获最终请求，验证每个启用字段；验证歌词与多段音频结果。
- 保存与入口：模型 A -> B -> A、同名模型跨渠道、刷新、重试、生成配置节点与直接生成的一致性。
- UI：桌面和手机、浅深主题、长模型名、参数弹层滚动、没有遮挡和横向溢出。
- 普通画布与自定义脚本回归；如扩展宿主 adapter，执行对应已有测试。

## Risks And Limits

- 宿主参数表不等于供应商实时能力。实际请求构造和已有测试是本地适配依据，真实供应商结果另行验收。
- 相同参数 ID 可能有不同模型语义，必须在模型上下文中查找，不能使用只按 ID 返回第一条定义的接口。
- 现有静态参数定义与适配器若不一致，需要记录具体冲突并修正必要映射，不能让 UI 掩盖执行缺口。
- 不新增经验性超时、重试、并发或素材大小上限。本地验证不能证明外部计费取消、供应商额度或所有线上模型可用。
