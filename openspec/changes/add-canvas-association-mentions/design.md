# Design: 画布联想引用与结果连线

## Goals

- 在原光标位置显示可识别、可删除且有序的内联画布引用
- 允许当前画板中有稳定 ID 且可计算边界的业务元素被拾取
- 让引用内容实际进入生成请求，而不只完成视觉展示
- 发布确认后在新任务节点与引用来源之间显示关系线，并在完成后把同一条线迁移到最终结果
- 保持现有 `#` 模型菜单、提示词候选、逐图草稿、粘贴、历史回填和提交锁行为
- 引用解析和连线创建在并发提交、切换画板及元素删除时保持确定性

## Decisions

### 1. 有序提示词模型保持文本与引用语义一致

任务栏维护纯文本 prompt 与有序引用范围。拾取成功后在触发 `@` 的原光标位置写入可见 `@标签`，并记录该引用在 prompt 中的有界范围；提交时按正文顺序保留标签语义，同时用独立引用元数据解析真实内容。媒体二进制不写入 prompt、草稿或 `localStorage`。

普通文本编辑复用现有输入行为。编辑发生在引用范围之前时平移范围；编辑与引用范围相交时整项删除该引用元数据，避免标签文本与对象身份错配。Backspace/Delete 在引用边界按整项删除；粘贴外部纯文本不会伪造对象级引用。历史回填只恢复纯文本，任务栏草稿同时保存本页轻量引用范围。

逐图绑定草稿与普通草稿各自保存轻量、有序引用数组，切换目标或画板时不得把引用带到另一份草稿。媒体内容不进入草稿或 `localStorage`。

### 2. 引用状态与媒体内容分离

`CanvasAssociationRef` 只包含：

- `referenceId`: 当前任务栏草稿内的稳定 ID
- `boardId`: 拾取时的画板 ID
- `elementId`: 画布元素 ID
- `kind`: `image | video | audio | text | graphics | frame | card | other`
- `label`: 长度不超过 64 的显示名称

提交瞬间按 `boardId + elementId` 去重并限制为 20 个。提交解析按顺序串行处理，避免多个大画框同时栅格化造成内存峰值。映射规则：

- image -> 现有参考图片链路
- graphics/frame/card/可渲染 other -> 复用画布栅格化链路
- text -> 现有文本选择链路
- video -> 现有视频选择链路
- audio -> 类型化 `selection.audios`

Seedance 2.0 可消费最多 3 个视频与 3 个音频引用；其它模型按既有能力校验。元素不存在、换板、转换失败、URL 非法或模型不兼容时保留输入并停止请求，禁止部分提交。

### 3. `@` 拾取优先于普通选择语义

联想开关开启时，仅当光标紧邻刚输入的独立 `@` 时进入拾取状态：`@` 必须位于行首或空白之后，并且后面不能紧跟非空白字符。该边界使 `a@`、`@foo` 等既有正文保持普通文本语义。拾取状态通过 `SelectionWatcher` 复用当前 board、mouseup 监听、异步 run ID 和画板切换保护。

拾取分支先于图片目标跟随分支执行，避免点击图片时意外写入 `replaceElementId` / `targetElementId`。成功拾取后把触发字符替换为内联引用并把光标放在 token 之后；Escape、删除触发字符、关闭联想或切换画板会取消拾取。

空画板、临时元素、`workzone`、`generation-anchor` 和关系线自身不可引用。

### 4. 发布时连接任务节点，完成时迁移到首个最终结果

`generation-anchor` 和 `workzone` 是提交阶段立即可见的画布任务节点。服务确认发布成功时，用其稳定元素 ID 作为临时关系端点，让用户在任务开始执行前就能看到引用关系。它们仍不允许作为后续提示词的引用来源。

轻量引用随队列任务持久化；最终媒体或文本结果插入后，按 `workflowId` / `taskId` / 临时端点 ID 找到已有关系线，把 `resultElementId` 原位迁移为真实最终元素 ID 并重算几何。迁移失败时才允许按幂等键补建缺失关系线。任务节点随后按现有生命周期移除，不新增永久任务实体。

批量生成只把来源连接到第一个任务节点，并最终迁移到 `batchIndex` 为 1 的结果，避免产生来源数乘结果数的连线。关系线保存：

```ts
interface CanvasAssociationLinkMeta {
  version: 1;
  boardId: string;
  workflowId?: string;
  taskId?: string;
  sourceElementId: string;
  resultElementId: string;
}
```

插件在画板变更后按微任务合并同步：双方存在时按矩形相向边中心更新端点；任一端不存在时删除线；只有几何发生变化才写回，避免 `afterChange` 递归。

创建键为 `boardId + sourceElementId + resultElementId`，重试、恢复和重复完成通知保持幂等。当前画板与任务引用画板不一致时不创建连线。

如果 Service Worker 已接单，但确认返回前用户切换了画板，不向复用后的 board 写入。系统只保留 `boardId`、来源 ID、任务端点 ID 和工作流 ID 组成的延迟补线意图；队列最多 256 条并按最早项淘汰。来源画板再次加载且任务端点仍存在时幂等补线，端点已不存在时消费并丢弃该意图。最终结果在非来源画板完成时同样不写入当前画板，而是沿用现有任务恢复队列，回到来源画板后再插入并迁移关系线。

### 5. 持久化、权限和性能边界

- 联想开关用容错 `localStorage` 布尔值，默认关闭；存储失败只影响跨刷新保持
- 引用只能解析当前已加载、当前用户可编辑的画板，不新增跨画板读取接口
- 引用随现有工作流/任务上下文持久化，关系线随现有 board children 持久化，不新增数据库表
- 单次提示词最多 20 个唯一画布引用；单个栅格引用最多处理 200 个子元素
- 延迟补线意图最多保留 256 条，只含轻量 ID，不含媒体内容
- 引用解析顺序执行并复用现有图像压缩与缓存逻辑，不持久化媒体二进制或 base64
- 发布前失败时不建线；发布后的任务失败或取消时沿用现有终态节点以支持重试，关系线保持绑定；任务节点被删除时同步清理关系线；后续输入编辑不改变已提交任务的引用快照

## Compatibility

- 联想关闭时 `@` 仍是普通字符
- `#` 模型触发和 Enter/Shift+Enter/Alt+Enter 规则保持不变
- 旧纯文本草稿和历史无需迁移；缺少范围字段的旧引用按无序附件兼容读取但不伪装成内联 token
- 不支持结构化引用的聊天抽屉仍接收纯文本 prompt 与已解析内容
- 触屏设备可以通过开启联想、输入 `@`、再点击画布完成相同流程；控件不得遮挡现有工具

## Failure Handling

- 元素不存在或无法转换：保留输入和引用，指出失效胶囊并阻止提交
- 模型不支持引用类型：保留输入，显示不兼容类型，不发送部分请求
- 发布前失败：不创建关系线，引用输入保持可重试
- 发布后任务失败或取消：任务节点保留现有失败或取消状态，关系线保持绑定以支持重试和追溯；节点删除后同步移除关系线
- 结果插入失败或没有稳定结果 ID：关系线继续绑定现有任务节点，并沿用现有任务错误状态
- 接单或完成回执到达时已切换画板：不修改当前画板；任务连线或结果插入等待来源画板恢复后幂等补齐
- 存储不可用：当前页开关仍可工作，不抛出未处理异常
