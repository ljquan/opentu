# Change: 优化网页打开卡顿与浏览器内存占用

## Why

用户反馈“网页使用打开会卡”，并有浏览器内存占用偏高的反馈。基于当前 `647e378d`（1.1.23）的只读代码检查，普通画布全量创建媒体组件、原图 eager/sync 解码、启动资产扫描、工作流全量原媒体恢复及缺少预算的运行时缓存均是具体优化点。实际瓶颈占比和节省量尚未通过浏览器采样确认。

## What Changes

- 第一批针对打开体验：优先显示当前视口内容；画布图片使用匹配显示大小的预览图，放大/预览/编辑时加载原图；视频默认封面，播放时加载媒体。
- 首屏只加载当前画布必要数据及任务恢复必需数据；素材全量扫描、缺失大小补全、非当前工作流页面改为按需加载。
- 第二批补齐画布销毁链、临时媒体释放及运行时缓存所有权，缓存按字节预算而非仅按条数控制。
- 第三批按测量结果决定是否将工作流全项目快照、任务大字段和历史对象进一步改为摘要加按需读取。
- 复用已有缩略图、视口裁剪、懒加载、持久化及任务恢复机制；补充资源计数和可重复的性能验收。
- 将旧功能回归、已有数据兼容、新旧页面/Service Worker 并存及回滚验证作为每批交付门槛；性能提升不能替代兼容验收。

## User Outcome

打开有大量图片或视频的画布时，画布操作先可用，当前可见内容随后渐进清晰；画布外的媒体不集中加载。放大和查看原图保留原始质量，下载/编辑/生成参考图继续使用原始数据。关闭预览和切换画布后回收不再使用的临时资源。记录、素材与账号数据不因内存优化被删除。

## Scope And Approval

本轮仅制定方案与代码检查，未修改实现、未测量浏览器、未启动/停止服务、未提交/推送。
实施前确认本提案的效果、预算建议及专项性能测量范围。默认不执行页面测试的项目规则仍适用；浏览器性能采样需明确授权，不能用类型或组件测试代替真实内存验收。

## Impact

- Affected specs: 新增 `browser-resource-efficiency`，与已有 `refactor-startup-shell-loading` 衔接。
- Affected code: `packages/react-board`、画布图片/视频组件、资产初始化、任务读取/队列、Service Worker 媒体缓存、工作流资源服务与路由。
- 主要风险：离屏释放与撤销/导出竞争、临时 URL 被仍活跃的消费者使用、预览替代原图导致尺寸/质量错误、恢复付费任务被延迟或重复执行。
- 第一、二批不调整持久化格式、不删除记录、不新增依赖；第三批如确需存储结构变化，另行确认兼容与迁移设计。
- 用户补充明确要求旧功能和版本更新适配；此要求适用于普通画布及已集成的工作流，优先于工作流局部规范中“无需兼容旧数据”的默认假设。需要迁移时必须提供完整、可恢复且经验证的兼容方案。

## Recommendation

先完成基线采样和第一批首屏优化，再按相同数据集验证；资源生命周期明确遗漏可作为小型独立修补。暂不重写画布引擎、不增加通用状态框架、不默认降低原图品质。详细证据、阶段依赖和验收见 `design.md`，执行清单见 `tasks.md`。
