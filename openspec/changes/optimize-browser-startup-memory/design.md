# 网页打开卡顿与内存优化技术方案

## 1. 检查边界与结论

代码基线：`647e378d`，版本 1.1.23。当前工作区实现文件没有修改；本地分支名与远程 PR 分支的差异来自此前用户要求用官方 develop 替换本地，不属于本方案。

用户已明确主要感受为“打开网页就卡”。因此优先减少启动时集中解码、全量读取与长任务，其次控制连续使用时的资源滞留。高内存可能来自解码图片、媒体缓冲、JS 对象、Worker 或浏览器自身缓存；当前没有真实 trace/heap 快照，不能确定各项占比或宣称已定位唯一根因。

只读检查涵盖普通画布、图片/视频组件、素材 Provider、任务读写与恢复、Service Worker 缓存和缩略图、工作流路由/媒体存储/项目状态/撤销及内存监控。已检查现有 OpenSpec，无独立的浏览器资源预算方案；启动壳层拆分已存在，本方案复用它。

本轮没有浏览器页面操作、真实生成调用、构建或测试运行。下述“确认”指代码行为已确认，不代表已测量内存泄漏或用户端收益。

实施阶段更新：用户随后授权开始开发，当前分支 `dev/browser-startup-memory`。第一批实现普通画布视口媒体加载、已有小图复用与原图导出、按需素材扫描、工作流路由 lazy、普通视频加载/释放、ReactBoard 销毁链及 SW 视频预算；没有改数据格式/升级协议。任务清单区分已完成和部分完成。方案阶段上段“本轮没有构建或测试运行”仅描述最初排查，后续实际验证以 QA 为准。

预览档位保守调整：当前普通画布已有 large 缩略图为 400px，本批复用而不新增 512/1024px 档位或预览格式；仅在显示长边×缩放×DPR 不超过 400px 且缓存原图 MIME 为 PNG/JPEG 时使用，未知格式、GIF/WebP/SVG 和 3D 保持原图。预览不存在或缓存读取失败直接走已有原图回退，避免扁平化动画或改变原图质量。

导出兼容调整：Plait toImage 克隆 live DOM 并复制计算样式，因此本批不卸载 img DOM，而在离屏时替换成共享透明像素并保留原始 source 标识；观察 foreignObject 固定几何。导出临时恢复原图与 eager，等待 decode 后再克隆，完成后恢复 source/loading，支持并发导出引用保护。实际 SVG/canvas 像素和升级页面验收仍待执行。

## 3. 已有能力与不能误判的点

- 主画布工作区启动已只加载画板元数据，switchBoard 缓存目标为 3 个画板；reload/update/patch 路径是否统一执行预算仍需补查，不必重新实现整个工作区。
- 任务队列有 100 条保留目标，大参数已部分剥离；素材网格已虚拟滚动，任务/提示词已有轻量摘要接口。
- 工作流画布已有视口裁剪与 768px WebP 预览，preview 生成串行化，优先改恢复和缓存生命周期。
- 普通图片/视频组件已在卸载和换源时回收自己持有的 fallback Blob URL；问题之一是父级是否真正触发卸载，不能说全项目都不回收。
- 普通画布撤销使用最多 100 批操作，工作流最多 50 个快照且主要保留不可变引用；不能按“50 次完整深拷贝”估算。预算淘汰必须保护仍被撤销引用的资源。
- 工作流退出会卸载 WorkflowApp、取消 native 请求和卸载插件；不能说两个模式始终一起挂载。模块级资源 Map/全局状态可能继续保留。
- Cache Storage/IndexedDB 中的数据主要是持久化存储。清空它们会影响离线数据和恢复，并不是本方案的内存优化手段。

## 4. 最终体验与约束

普通画布及工作流保持原数据、布局、比例、缩放、工具栏和详情行为。离屏媒体使用轻量占位，滚入视口后恢复；拖动/缩放中的短暂移出采用滞后回收，避免反复请求和闪烁。图片在小显示尺寸使用预览，近原始尺寸和编辑/下载时使用原图。视频保持可见封面与播放入口，点击播放后提供原有控制。

后台生成和恢复是关键业务：页面隐藏只降低非关键预取/扫描/预览解码，不能取消正在生成或错误重提收费请求。任务 ID、原路由、参考图、历史、撤销、导出、同步、编辑、动画媒体和 SVG 行为均需回归。

不引入默认“清空缓存”按钮，不自动删除历史或原素材，不通过降级下载品质换取内存，不在本次改造 AI 请求的并发或超时。

## 5. 分阶段实施

### 阶段 0：建立真实基线

依赖：确认专项浏览器性能测量授权。采用当前提交的生产构建、独立测试 origin/profile 和合成数据，保留用户现有浏览器/本地存储。旧 dist 和 Vite 开发服务不能代表该版本生产性能。区分首次冷访问、暖缓存、已有数据恢复和普通/工作流入口。

记录 navigation-to-interactive、首 10 秒主线程长任务、首次选择/拖拽响应、JS heap、页面 DOM/React root/活跃 media/Blob URL 数量、SW video bytes 和请求数量。浏览器进程/GPU/Worker 指标有共享及归因限制，分别记录。JS heap 不能作为总内存替代；仅测试环境可用 CDP GC 前后检查可回收对象，生产不要求强制 GC。不可用的指标标记 unavailable。

测试矩阵：空白；普通画布 20 张 2480×3312 图；100 张中仅 10 张可见；10 个 20–40MiB 视频仅播放一个；工作流相同媒体；大量历史任务/100 个项目仅打开一个；20 次预览与模式/项目切换。每组至少 3 次，预热后比较中位值，并固定视口、DPR、浏览器版本和机器。

产出：基线 trace/计数及瓶颈排名，确认下面预算与验收目标。当前此阶段未执行，不承诺已经节省多少 MB。

### 第一批：打开时先可操作

1. 普通图片按视口加载，沿用现有 SVG/foreignObject 几何，只延迟重媒体部分；选择、命中、组/frame 与导出仍依赖完整数据。结合 preview/原图分级和 async 解码，不能仅把 img.loading 改 lazy。
2. 对同源同版本缓存 Blob 的读取去重、明确 URL 所有权，解决原 URL 与 fallback 的无必要并行加载；保留 SW 不可用、签名 URL 过期和离线情况下的缓存回退。
3. 首屏 AssetProvider 只提供当前元素必要的按 ID 元数据；全量素材扫描和大小补全在打开库时分页触发。目录/列表可虚拟化，但不截断历史；旧业务依赖 global asset store 需逐一补上按需 resolver。
4. 工作流当前路由使用既有 React.lazy/Suspense 模式按需导入；CanvasImages/AssetStore/会话 hydrate 先保留 storageKey 和元数据，在可见节点、预览、生成或导出时才读取原媒体。复用已有 768px preview 和 visibleNodes。
5. 视频默认封面与播放入口，未交互时不下载完整源；无封面允许仅受预算控制的元数据/首帧提取，生成输出优先复用已有封面。播放后离屏是否暂停按播放意图区分；音频后台播放保持可用。

依赖：资源按需解析必须先支持消费者获取/释放，不能在仍使用原 URL 的全局状态中随意 revoke。拆包不表示已加载模块可以从浏览器模块缓存卸载。

### 第二批：资源释放与有界缓存

1. 补齐 ReactBoard/ListRender/独立 React root 销毁链，保证幂等，防止 StrictMode 重挂载和异步 setTimeout 造成 use-after-destroy。覆盖组/frame/plugin、图片 3D 和视频。
2. 工作流 storageKey 同资源并发 resolve 合并；资源按使用者获取/释放，换版本采用代际处理，旧版本在最后使用者退出后 revoke；不能在 setItem 时直接 revoke 仍被 DOM/预览使用的旧 URL。
3. 用运行时 budget 控制冷资源，区分图片/预览与视频；switch/unmount/delete/cancel 走统一释放。cleanupUnusedMedia 复用安全释放，但不要扩大持久化删除范围。
4. SW 视频缓存每次插入/恢复都校验字节和条数上限，TTL 在缓存命中前也检查；处理 video-only 会话无需等待新图片请求。大媒体优先原 Range 透传或持久化 Range 读取，避免为了很小区间加载完整视频；保持 Range、206、签名 URL、CORS 和离线回退兼容。
5. 已完成图片请求仅短期去重且有数量/字节预算；验证未消费 Response.clone 的缓冲行为，优先可重读的缓存引用，不能让错误淘汰影响正在消费的流。
6. 元数据探测和缩略图生成明确 finally 清理 video/audio src、事件、bitmap/canvas 和 URL；超时/取消必须保证解码任务结算，避免串行 preview 队列被永不完成的任务阻塞。
7. 内存监控注册真实可释放的冷缓存清理器及资源计数；压力策略按应用资源预算运行，performance.memory 只作辅助，不依赖生产环境 gc()。

### 第三批：仅在剩余瓶颈证实后实施

任务启动优先摘要+活跃恢复任务，按用途读取完整参数；清理范围包含大 Base64 旧字段及嵌套值，但完整持久化副本先成功保存，失败不能丢掉唯一输入。task-storage-reader 的过期缓存应解除引用或只保留摘要，详情组件不长期保存全任务大对象。

工作流项目列表改为索引元数据，当前项目正文按需读取，保存只写当前变更，避免每次编辑 JSON.stringify 全部项目。该改造涉及存储/同步/导入/导出，单独确认迁移、备份和失败回滚；不与第一批混在一起。撤销仍按既有语义保留，资源引用与其联动；是否引入字节预算先测量。

工作区 3 画板缓存限制统一覆盖 reload/update/patch 等路径并考虑字节占用，仅回收已保存的非活跃画板。批量导出、图像编辑、视频合成的大峰值作为专项优化，不阻塞首屏第一批。

## 6. 建议参数，待确认

以下是起始实验值，不是现有指标或已生效配置。工作流 AGENTS 对新大小/并发/超时边界要求说明并确认，本方案一次性列出适用范围和降级行为。

| 项目 | 建议起点 | 预算不足/失败行为 |
| --- | --- | --- |
| 非交互图片读取/解码 | 并发最多 2 个；当前选中/预览优先 | 排队，可取消离屏工作；不限制 AI 生成并发 |
| 视口预加载 | 外扩 200 CSS px；离屏约 2 秒后释放重资源 | 重新进入时按需恢复；活跃拖拽、编辑、导出资源暂时固定 |
| 图片预览 | 复用工作流 768px；主画布候选 512/1024px 两档 | 确认显示像素/DPR后选择，需求超过档位使用原图；失败走受预算控制的原图回退 |
| 工作流冷 Blob URL | 图片/预览 64MiB、音视频 128MiB，按 blob.size 估算 | 先淘汰无使用者资源；活跃资源不得强制失效，无消费者的超大文件不常驻 |
| SW 视频缓存 | 起点 64MiB 总字节、保持最多 10 条的兼容上限；保留 5 分钟冷项 TTL | 插入即时淘汰冷项；超预算条目采用读取/透传，不删持久化副本 |
| 媒体元数据探测 | 并发 1 个，超时起点 10 秒 | 清理探测资源并显示未知元数据，点击播放仍可重试；不改 AI/API 超时 |
| 后台非关键工作 | 每个主线程执行片最多约 8ms，页面隐藏暂停预览预取 | 下个执行片继续；任务恢复和保存仍执行 |

blob.size 仅表示编码资源量，不是浏览器总 RAM；解码像素另估 width×height×4。使用者固定资源可超预算时记录并停止非必要预取，不取消用户操作。必须先缩减 eager hydrate，单独给当前 Map 加 LRU 并随意 revoke 会破坏持久化 blob URL 消费者。

## 7. 验收与回归

硬性代码验收：离屏媒体不触发全量原图/视频恢复；缓存每次插入后符合已确认的冷项预算；相同版本资源请求去重；最后使用者释放后 URL 回收；关闭/切换后 root/media/订阅计数回到合理稳定水平；未保存、撤销、导出、播放、生成/恢复使用的资源不被回收。

实际性能目标建议在阶段 0 确认：媒体场景首 10 秒长任务总阻塞时间相对基线降低至少 30%；同数据集暖启动可操作时间不退化，重媒体画布目标降低至少 30%；当前仅 10/100 图片可见时，进程内存峰值目标降低至少 30%。这些是待验证目标，不是承诺对所有设备都降低同一数值。空白画布若无媒体仍卡，应按 trace 优先转向模块解析/启动扫描，不生搬媒体结论。

20 次预览/模式/项目切换后比较第 5 次和第 20 次：可回收后的 retained JS heap 建议增长不超过 max(10MiB, 5%)，且无随着次数等比例新增的 detached root/Blob URL；只凭浏览器 RSS 不立即下降不能认定泄漏。图片解码/GPU/浏览器缓存可能滞后释放，需同时看资源计数和保留路径。

回归范围：原图预览/下载/导出/编辑、SVG/动画图片、签名远程图、缓存离线恢复、PPT/frame/3D、视频播放拖动/Range/封面、后台音频、文本/card详情、任务完成自动插入、未知结果不重复提交、重启恢复、撤销/重做、复制粘贴、保存/切项目、多消费者同媒体、同步覆盖和取消后旧响应。

验证分层：单元测试资源引用/字节预算/并发取消；JSDOM/fake-indexeddb 测试组件与持久化；类型、lint、应用+SW 构建和首屏包校验；明确授权后生产构建的专项浏览器 trace/heap/交互验收。截图不是内存验收要求，不默认扩展全面视觉 QA。CI/部署与真实供应商验证另行记录。

## 9. 用户追加的旧功能与版本更新兼容要求

本节是强制实施与交付要求，不是本轮已完成的验证。用户明确要求旧功能及版本更新适配，优先于工作流局部 AGENTS 中“项目尚未上线，不需要兼容旧数据”的默认规则。不能绝对证明所有未覆盖场景无缺陷；交付必须列明验证证据、覆盖的版本/浏览器和剩余风险，已知关键回归不得带入发布。

### 9.1 兼容原则

- 第一、二批保持原媒体 storageKey/URL、持久化数据库/表结构、任务 ID、供应商路由和参数语义；新增预览是可重建衍生数据，不能覆盖原媒体。
- 原图读取与低开销显示分别处理：缩略图只用于展示；下载、编辑、导出、生成参考图及尺寸/详情读取继续使用原始数据。动画图、SVG、透明图和带签名 URL 的媒体需明确保留原行为。
- 缓存预算只作用于运行时冷资源。当前播放、预览、编辑、导出、生成/恢复与撤销引用属于活跃使用，不可强制 revoke；回收后原资源必须能从存储重新解析。不能删除唯一副本或把当前临时 blob URL 当成持久化权威数据。
- 主画布和工作流先通过同一媒体消费者契约落地，再调整加载策略；图片详情、文本/card 详情、跟随/居中设置、播放和模式切换全部回归。
- 首屏延迟工作不改变任务执行语义：完成任务不能重复提交；未知结果继续保留原恢复规则；保存失败不清除唯一输入，未执行任务不因资源预算被标成成功或失败。
- 现有偏好键及开启/关闭值保持含义；如果需要新增偏好，默认行为、旧用户回退及跨标签页行为须明确，不能清空用户设置。

### 9.2 版本与缓存策略

当前 `apps/web/src/sw/index.ts:252` 的 app/static 缓存按 APP_VERSION 命名，`drawnix-images` 使用固定媒体缓存名；`:2735` 更新安装保持 waiting；`:2781` 更新 ready 只依赖首屏必需资源。优化必须保留这些语义：不能为了预取策略变更强制 skipWaiting/刷新，也不能让可选预览/预取失败阻止关键更新完成。

- 区分应用版本、原媒体标识、预览算法版本和可选消息协议版本。预览 key 至少区分源内容版本、预览尺寸和格式；旧预览不可用时重建或回退原图，原媒体不因应用升级失效。
- 新旧前端与 SW 并存时保留旧请求/响应语义。若新增释放或资源统计消息，采用可选能力探测，旧端忽略新字段、新端面对旧端走已有路径；协议重大变化需单独设计，不能一次把旧路径移除。
- 关键 HTML/JS/CSS 与懒加载 chunk 必须来自匹配的版本；沿用 `release-safe-static-loading` 的 CDN 就绪与启动边界校验，HTML/鉴权/错误响应不能当成 JS 成功缓存。
- 已有旧静态缓存清理在 `apps/web/src/sw/index.ts:2936` 附近使用延迟 30 秒。固定等待不证明旧标签页已经退出，尤其此次扩大路由懒加载后，旧页可能更晚请求旧 chunk。列为升级验收风险；如果测试复现旧页丢 chunk，需在发布前修复或保留受影响版本资源，具体修补范围单独说明，不能仅增加一个任意等待时间宣称兼容。
- 冷内存缓存可以随 SW 重启重建；持久化原媒体、用户数据与旧页面仍需要的版本资源不能因此一起删除。CDN 尚未就绪、弱网或离线时保留可用旧版本，避免半升级。

### 9.3 已有数据与迁移

阶段 0 整理实际支持的历史版本和数据样本，至少覆盖当前基线 1.1.23、其上一个可部署版本与升级后的版本；不能只用空白新账号数据。样本包含已有工作区、普通/工作流项目、已生成媒体、原/缩略图缓存、task 参数、旧 Base64/签名 URL、偏好和处理中任务，不含真实凭据。

第一、二批无 schema 迁移，必须验证升级后读取原存储成功。第三批如确需拆分存储，则先确认独立迁移设计：持久化格式版本与应用版本分离；先备份旧数据并完整写入/校验新数据再切读路径；迁移可重试且不重复素材/任务；中途失败继续读可用旧数据；未知较新格式和损坏数据拒绝覆盖或删除。

回滚需要实际验证：第一、二批旧应用能读取优化期间写出的原数据；第三批如果旧应用不能识别新格式，不能仅回退代码或降 IndexedDB version，必须预先保留可读旧格式快照或提供经确认的恢复方案。跨标签页数据库升级 blocked/versionchange 需处理并提示保存/关闭相关旧页，不能静默删库重建。

### 9.4 回归与升级矩阵

以下测试均待实施后执行。逻辑层能自动验证的先写针对性测试；版本切换、实际媒体/画布及性能的页面验证仍须按用户授权范围运行。未执行关键兼容项时，不得将该批标记为完整验收或发布通过。

| 场景 | 必须保留的结果 | 验证层 |
| --- | --- | --- |
| 旧用户升级，有原媒体但无新预览 | 原内容正常打开，预览按需生成/原图回退，尺寸和下载品质不变 | 数据/组件 + 页面 |
| 新应用配旧 SW、旧应用配新 SW | 兼容路径可用，旧协议不会误清理正在使用的资源 | SW/协议 + 页面 |
