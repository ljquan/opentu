# Change: 新增文档驱动的批量生图工作台

## Why

用户已有包含提示词、参考图片的 Excel 或 PDF，需要逐项复制到生图工具，生成后还要手动整理图片与原始需求的对应关系。现有批量生图组件只提供有限的 Excel 文本和图片 URL 导入，缺少内嵌图片、PDF 图文配对、导入核对和可靠的批次排队。

本提案将流程连成「导入文档 → 自动整理任务行 → 核对修改 → 勾选生成 → 对应行查看结果 → 勾选下载」。详细设计见 [技术方案](./design.md)，实施步骤见 [任务清单](./tasks.md)。

## What Changes

- 增加「批量生成」导航入口和独立工作台；提供本地批次历史、批次默认参数和行级覆盖。
- 支持 XLSX 提示词、图片链接、标准绘图内嵌图片；支持 PDF 文本、页面图像区域与来源定位；扫描件可选择使用视觉模型识别。无法可靠配对的内容保留并标记待确认。
- 提供逐行编辑、参考图管理、稳定 ID 勾选、拆分/合并行和校验提示。导入不触发生图；云端识别与生图分别获得用户操作授权。
- 使用不可变输入快照、持久化待提交计划和有界调度，复用既有图片路由、任务执行及恢复能力。网络结果未知时先查询，禁止盲目重新提交。
- 结果按行和生成轮次归档，支持单张选择、重试明确失败项、ZIP 下载、下载失败清单及按需插入画布/存入资产。
- 增加输入预算、资源回收、账号作用域、跨标签页提交保护和针对主要崩溃窗口的验证。

## Impact

- 新增规范：`document-batch-generation`。不修改现有 `image-generation` 和 `provider-routing` 的供应商协议要求。
- 主要影响：批量工作台、文档解析 Worker、本地批次存储、任务队列的可等待持久创建与延迟执行接口、图片任务恢复和下载辅助函数。
- 复用：`xlsx`、`jszip`、模型能力/路由、统一缓存与任务结果。PDF 解析拟引入 `pdfjs-dist`，具体版本、许可证、安全与 Worker 构建兼容性在实施阶段验证。
- 兼容：旧批量生图入口、已有草稿及其自动插入画布行为保持原有语义；新工作台默认仅展示结果。新数据采用独立命名空间，不把新批次混入旧单份草稿。
- 首版不增加服务端批量 API，不保证关闭浏览器后继续提交剩余任务，不提供跨设备批次同步。
