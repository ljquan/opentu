# 工作流生成持久化与刷新恢复

## 当前状态与证据

状态：主要实现已落地，存储/协议/目标校验、类型与构建已完成本地验证；完整故障注入矩阵仍待补齐，见 tasks.md。已检查当前工作区，保留其他功能的未提交改动。

| 入口 | 已确认问题 | 影响 |
| --- | --- | --- |
| 图片工作台 `web/src/pages/image/index.tsx` | `generate` 等全部 Promise 结束后才 `saveLog`；重试也仅在成功后保存 | 请求中、部分成功时刷新，缺少完整历史 |
| 原生桥 `host/native-generation.ts` | 直接调用适配器，无持久任务身份和结果归属 | Promise 随刷新消失 |
| 视频 API `web/src/services/api/video.ts` | 原生路径等最终结果后才返回本地伪任务 ID；结果存于 `pluginVideoResults` | 原生视频生成中无可恢复任务，Map 刷新丢失 |
| 视频工作台 `web/src/pages/video/index.tsx` | 所有查询异常均写为 failed | 配置未恢复、网络异常也会终止后续恢复 |
| 画布 `web/src/pages/canvas/project.tsx` | 除已有视频 ID 外，loading 节点通过 `resetInterruptedGeneration` 改为 error；视频恢复只在画布加载时尝试一次 | 图片、文本、音频无任务回填；配置稍后就绪也不恢复视频 |
| 画布 store | 400ms 延迟写入，调用方不等待关键保存 | 任务归属可能晚于提交保存 |
| 文档批量 bridge | `recover` 明确拒绝带 remoteId 的任务；通用执行扫描也跳过 documentBatch | 异步图片恢复存在覆盖缺口；必须以测试确认各路由，不假定所有批次失败原因相同 |

以上路径均相对于 `packages/drawnix/src/workflow-mode`，文档批量 bridge 位于 `packages/drawnix/src/services`。移除刷新取消监听不能恢复被浏览器销毁的请求，不作为解决方案。

## 目标和边界

刷新后，在原工作台/画布/批次中看到原任务、提示词、参考资源及已完成结果。有远端任务 ID 或受支持 Request ID 查询的任务自动恢复查询。没有查询契约的同步文本、音频、第三方图片和脚本任务保留输入和结果待确认状态，不显示永久“生成中”。

已丢失且没有任何持久 ID 的历史请求不能可靠反查。本改动不补造 ID，不自动重新生成，也不保证供应商断开连接后仍继续处理。不使用 Service Worker 作为永不终止的后台进程，不新增后端。

## 关键决定

### 1. 任务状态作为权威，页面只是投影

复用 OpenTu TaskQueue、task storage writer、原路由快照和恢复服务。新增明确的工作流归属元数据，不冒用 documentBatch 的提交资格。保持普通 `createTask` 行为，给工作流使用可等待的 prepare/start 入口。

归属包括 scopeId、workbench logId 或 projectId/nodeId、输出 slotId 和 attemptId。输入快照包括提示词、模型参数和持久资源引用；blob URL 必须在提交前转为可恢复资源。请求与结果记录不复制明文 Key，不进入配置导出。

每个尝试独立写入，输出序号稳定。查询结果先完成原任务的条件写入，再更新视图。页面未打开时结果仍在任务存储中；再次打开按任务 ID 幂等投影。画布移动、删除和撤销不能被旧结果覆盖，用户显式删除目标后不重建节点。

### 2. 先持久化，再提交

顺序：保存输入资源 -> 保存任务和目标归属 -> 取得单次持久提交资格 -> 保存提交标记 -> 发出请求。任一步存储失败均阻止新的付费 POST。

同一 IndexedDB 记录的条件事务负责提交门闩和尝试校验，不能依赖内存 Set 或 localforage 读改写实现跨标签互斥。复用已有 storage writer 的事务方式，避免多套防重逻辑。崩溃发生在提交标记后、网络发送前时也按不确定处理：宁可显式等待确认，不冒重复计费风险。

关键任务保存必须可 await；画布拖动等普通保存可以保留防抖。不能用卸载事件中异步 flush 保证可靠性。目标归属和创建信息先写入任务，画布投影失败可重试；旧画布全量快照不能回写覆盖新结果。

### 3. 原路由和凭据身份

原生渠道沿用 invocationRoute 和 binding 校验。工作流自建渠道、Tuzi 固定渠道保存渠道 ID、协议、端点、凭据 ID 及可验证的凭据版本身份。查询不得改用当前默认模型或当前激活 Key。缺失或被替换的原凭据进入“等待原配置”，不删除任务。

账号、配置和持久 store 全部就绪后才启动恢复；账号切换停止旧作用域查询和写回。账号未就绪时不得暂时归入 standalone。可复用批次作用域来源，但不得改变现有批次 ID 或本地数据键。

### 4. 按实际协议恢复

| 任务 | 恢复方式 |
| --- | --- |
| 可信 Tuzi 同步图片 | 提交前持久保存稳定 submissionRequestId 和路由；复用 `imageGenerationRecoveryService` 只读查询 |
| 有远端 ID 的视频、异步图片、音频 | 在提交响应解析后、开始轮询前持久保存 remoteId；按原适配器查询 |
| 工作流本地渠道的 Responses 文本 | 流式接收时保存 response ID 与文本片段；刷新后以原渠道和原 Key 调用 `GET /responses/{response_id}`，仅 completed 写为成功 |
| 尚未取得远端 ID 且无 Request ID 查询契约 | 结果待确认，不重新 POST |
| 普通同步文本/音频、无恢复契约的自定义脚本 | 保存输入及已获得结果；本地文本流的片段先持久化再显示。Gemini、原生同步文本等没有查询标识时明确无法取回未收到的全文，不虚构查询或自动重发 |
| 已完成但媒体缓存失败 | 保留原结果 URL 和缓存错误，重试缓存不重新生成 |

适配器现有提交/轮询接口不足时，补充明确的受理回调，不能拦截 fetch 猜测各供应商响应。原生视频不再通过内存 Map 伪装成已创建的远端任务。脚本已完成的结果持久保存，脚本执行中的恢复边界保持可见。

工作流本地图片的 Request ID/远端 ID 不因原任务年龄失效，取消按原提交时间计算的 15 分钟恢复硬截止。原生同步图片沿用 OpenTu 的 `IMAGE_GENERATION_TIMEOUT_MS`（15 分钟）作为每次恢复的查询窗口，仅传入恢复器的临时时间变化，不覆盖持久化原提交时间；移除重复的 10 分钟外层停止计时。查询窗口到期返回待确认，下一次扫描继续查询原任务。原生异步图片及已有远端视频 ID 的任务也保留原标识继续查询。其他请求超时和并发限制保持不变，不能把本地等待超时当成上游失败。健康请求不并行启动恢复查询，同一持久任务的并发恢复复用在途 Promise。画布每 10 秒扫描新增待恢复项，不取消上一次仍在执行的恢复回调；只在页面卸载或配置变化时使旧投影失效。

补齐文本/音频恢复时，同样移除本地任务按原开始时间计算的 10 分钟硬截止；原接口的单次轮询窗口、并发上限保持不变。原生视频/音频单轮超时保持 processing，明确的供应商失败才落 failed，恢复歌词时保留文字结果类型。视频持久任务统一走画布恢复扫描，旧记录的独立视频查询也会再次扫描，避免两个恢复入口互相抢占。

Responses 查询协议依据 [OpenAI Get a model response](https://developers.openai.com/api/reference/resources/responses/methods/retrieve)。这里只接入已有响应的读取，不改变请求的 `store` 或 `background` 参数。上游未实现读取、已过保留期、未返回 response ID 或断开连接即取消处理时，不能保证完整全文恢复；保留片段与具体查询原因。对全部同步供应商实现刷新后后台执行，需要另行设计持久后端，本次没有新增服务。

创建接口返回 response ID 不代表渠道实现了 GET 查询。对于明确的 `Invalid URL (GET …/responses/…)` 路由拒绝或 405/501，按任务持久保存 `textRecoveryUnavailable`，后续刷新/扫描不再向该任务发送查询；生成状态仍是 processing，不能推断供应商最终失败。画布以 idle 静态提示“无法自动找回”，保留片段、任务 ID、其他输出和账号隔离；原执行者后来保存的成功/失败仍优先于该标记。普通 404（响应暂时不存在）、网络错误和 503 不作此判定。没有查询标识的文本同样以静态说明显示，不伪装持续生成。

### 5. 状态和页面行为

区分待提交、提交中、查询中、成功、供应商确认失败、结果待确认和等待原配置。视图可使用额外恢复状态，不强行将所有状态添加到共享 TaskStatus。

画布恢复中的占位沿用 loading 绘制动画，但通过查询/结果待确认文案区分实际生成；空查询和临时查询错误不显示失败重试卡。节点和每个输出同时更新等待状态，部分成功保留已有图片。上游明确失败持久化为 failed，才投影为对应输出的 error。旧的本地超时卡在读取仍 processing 的原任务后恢复等待展示。

文本多结果保留原输出槽位、主文本选择和每项已收到的片段；某项完成不能删除未完成兄弟项或把整组标成成功。带内容的未完成文本仍显示状态与等待动画。文本流 EOF 不等于完成，Responses 必须收到终态事件；持久 Gemini 流必须收到结束原因。查询接口的 404/503、网络错误不等于原生成失败，不能据此重新 POST。

图片工作台从提交前就显示同一历史记录，每张结果完成立即保存；刷新后重建进度。视频工作台与画布只在供应商确认失败时终结，不把网络失败永久标为生成失败。刷新、路由切换、取消查询和取消远端生成含义不同，不承诺本地取消能停止扣费。

“继续查询”只 GET；“重新生成”是新的尝试，受理不明时需让用户确认可能重复计费。重复事件、并发输出和旧尝试回调不能覆盖当前结果。

文档批量保留既有排队、暂停、提交门闩和作用域；修复 remoteId 查询缺口及恢复结果投影。刷新后未提交项仍等待用户继续，不自动消费提交资格。

### 6. 图片和视频刷新恢复提示

图片和视频只有在页面恢复阶段已经识别为未完成的持久任务时，才记录本次页面恢复时间并显示“网页已刷新，正在找回生成结果…”。当前页面新提交的任务没有这个计时起点，继续沿用普通“结果待确认”状态，避免把本页内的失败或网络异常误标成刷新恢复。恢复等待达到 5 分钟时，提示用户到日志中查找，同时继续对原任务执行只读查询，不重新提交生成。在途查询尚未返回时，既有 10 秒扫描同样更新提示；后台标签页受浏览器定时器节流影响。查询成功或明确失败后清理对应计时记录；更新提示时校验输出和尝试身份，不覆盖已完成结果、已删除输出或新尝试。文本和音频沿用原有文案，不受本次提示计时影响。

## 验收与测试计划

通过重建服务实例和组件卸载/重挂模拟刷新，不运行浏览器页面测试，不访问付费 API。测试在提交前、标记后响应前、取得远端 ID 后、部分完成后、缓存中、写回中分别中断。

每个入口均断言原任务可见，已保存结果不减少；可恢复项只发查询且写回同一目标；不可恢复项状态明确。额外验证：存储拒绝时零 POST、两标签争抢单次提交、并发结果不互相覆盖、晚到配置恢复查询、换账号隔离、换 Key 不串用、删除目标不复活、旧尝试不能覆盖新尝试、查询超时不自动重发。

实际实施后运行工作流 Vitest、相关 TaskQueue/恢复服务测试、工作流 TypeScript 和 web 构建，并检查完整差异。已完成本地恢复、存储、类型和构建验证；真实浏览器、真实渠道和付费生成仍未执行。

## 兼容、风险和回滚

保留现有历史及存储键；旧记录缺少任务身份时只展示既有内容，不推断请求 ID、不重新提交。新增数据采用可区分的工作流归属。若要改变共享存储 schema，须在落地前补充版本和兼容验证。

浏览器清理存储、隐私模式配额不足、上游查询过期和结果 URL 失效仍可能阻止恢复，必须保留具体原因。回滚不得删除任务、提交门闩或允许旧执行器重发已尝试任务；停用新入口后仍保留记录读取和查询能力。当前没有上线或迁移操作。
