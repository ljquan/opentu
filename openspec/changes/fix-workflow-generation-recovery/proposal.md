# Change: 修复工作流刷新后生成任务丢失

## Why

用户确认生图工作台、视频工作台、画布和文档批量生成均受影响。当前普通图片历史在整批结束后才写入；原生生成直接等待适配器 Promise；原生视频的最终结果暂存在内存 Map；画布只有部分视频路径保存远端任务 ID。刷新会销毁这些执行上下文，部分成功结果也可能未落盘。

文档批量已有持久计划、提交门闩和图片 Request ID 恢复机制，应修正其恢复缺口并复用，不能改为刷新后重发请求。

## What Changes

- 工作流各入口在付费请求前持久保存尝试 ID、输入快照、原路由及结果归属。
- 原生生成复用 OpenTu 任务存储、供应商适配器及恢复服务；工作流渠道保留原渠道和原凭据身份，不能被原生接入遗漏。
- 异步任务拿到远端 ID 后立即保存，再进行轮询；支持 Request ID 查询的同步图片沿用已有查询契约。
- 每个输出独立保存，工作台历史和画布通过持久任务回填；刷新后保留已完成部分和未完成状态。
- 刷新只恢复查询；未提交项等待继续，受理不明或不支持查询的任务保留“结果待确认”，不自动重发。
- 区分供应商失败、查询中断、配置未就绪和本地媒体缓存失败；重试查询不创建付费尝试。

## Impact

- Affected specs: `workflow-generation-recovery`; 保持已有 `document-batch-generation` 的提交和作用域约束。
- Affected code: 工作流 workbench/canvas/API/store、原生生成桥、TaskQueue/task storage、图片及异步媒体恢复逻辑。
- 不新增服务端，不承诺浏览器关闭后前端继续执行；仅对有恢复契约的供应商自动取回结果。
- 不修改并发、超时和保留期限默认值，不修改 Key、不自动切换渠道、不提交或发布代码。
- 这是跨入口执行链路调整，实施前需确认本提案及 [技术方案](design.md)。本提案不代表修复已完成。
