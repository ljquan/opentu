# Design: 主画布生成输入与操作目标分离

## Context

当前 develop 已退役独立工作流画布，并提供图片参考固化、来源关系线、每张结果的任务 ID、向右派生与同来源批次避让。方案基于这些能力扩展。旧工作流的连线到输入实现只可作为历史参考，不恢复其页面或状态存储。

“再次生成”当前只是回填。URL 抑制逻辑只过滤 selectedContent，绑定目标仍可经 boundTargetContent 和提交链路重新混入；预览删除又依赖 uploadedContent 的索引边界。根本问题是操作目标、请求输入与画布选择缺少显式隔离。需通过运行时集成测试确认具体触发序列。

## Decisions

### 1. 操作意图决定输入，选中状态不决定重新抽卡输入

最少增加明确的操作意图：正常创作、原输入重抽、以当前图编辑。输入会话中的原任务 ID 与画布目标 ID 分开保存：目标 ID 可以定位输入栏、结果位置或来源记录，不能默认转成参考。

统一解析一次“有效输入快照”，预览、移除操作、参数校验、工作流构造和实际 adapter 请求都消费它。不能只在显示层隐藏目标图，也不能只在一个入口 clearSelection；异步选区刷新、图像缓存 URL 变化和绑定恢复都可能将目标重新加入。

用户主动从另一个入口选择“以此图修改”时才切换意图。原输入重抽期间普通选中、平移、缩放不能改变输入；显式切换到另一份生成草稿时保存当前编辑状态。

原任务就是以某张旧结果为输入时，必须保留该合法输入；规则不是过滤所有“AI 生成图片”，也不是对结果 URL 做全局黑名单。

### 2. 保存可恢复的生成记录，复用现有缓存

优先复用 Task.params 与 generationTaskId，梳理顶层参数和嵌套 params 的规范化，避免现有字符串提取丢失数值、布尔参数或图像角色。提交时固化输入顺序、素材版本及模型渠道，输出变化不反向改写本次快照。

针对任务历史可能被清理的情况，在结果元素的 `imageGenerationRecipe` 中保存 `{ version: 1, id: taskId, input }` 轻量记录。复用画布 JSON 保存、复制、撤销和备份，不新增独立记录库。参考图及蒙版使用现有媒体缓存的稳定 URL，导出时递归收集；不保存完整 Task 或凭据。自动插入与任务列表手动插入均写入记录，并读取完整持久化任务，避免从裁剪后的内存摘要推断零参考图。缓存失败不会丢弃已付费的结果，仍保留任务 ID 供历史恢复；用户明确删除缓存后恢复会提示缺失。当前缓存没有自动逐出策略，以后增加时必须识别画布记录中的引用。

原记录缺失时优先使用已有任务输入恢复。部分素材 URL 失效时仍可回填原列表，用户移除或替换后发送；完整输入记录缺失或格式不完整时明确提示重新添加原参考图，或显式使用“以此图修改”。不能将缺失记录猜成零参考输入直接提交。

### 3. 持久生成框与临时任务占位分开

新增主画布生成框元素，持久保留草稿与引用。复用 Plait 元素、选中、移动、序列化和历史体系；选中时绑定现有 AI 输入栏。

每次提交仍创建现有 generation-anchor / 对应媒体任务占位。生成框不随任务结束删除；结果占位由既有完成链路处理。对图片任务沿用实际来源右侧布局，并将持久生成框纳入避让。视频继续使用现有视频任务与插入流程，补齐草稿 ID、来源与输出归属。

第一版关系如下：图片 A、图片 B → 生成框草稿 → 点击生成 → 本次任务快照 → 新结果 C。再点生成仍使用 A、B；只有将 C 显式连入另一个生成框，才成为后续任务参考。

输入线与结果来源线保存不同的关系类型。既有 canvasAssociation 继续记录实际来源到结果的追溯关系；不增加一套重复的来源到结果线，不根据旧线自动反推并修改草稿。

### 4. 引用列表为唯一权威数据

生成框的有序 references 是唯一权威状态。输入线由该状态呈现，删线通过同一 action 移除引用；删缩略图同样修改 references。删除、恢复节点与引用更新组成可撤销的操作，不维持两个相互推导且可能循环触发的 store。

同一来源重复连接幂等，不按 URL 合并不同元素。混合上传与画布引用时使用稳定 referenceId、boardId、elementId / mediaKey，并保留顺序。视频引用明确 role；普通参考不能在切换模型时无提示地改成首尾帧。

连接到不支持的对象显示提示且不产生半条关系；原有图形连线仍保留。拖动命中处理需覆盖缩放、平移、旋转图片、鼠标和触摸指针事件，不能以 children 数量增加作为唯一新增线判断。

### 5. 任务与草稿隔离

提交前验证所有引用、模型能力、凭据和来源画板，生成请求只使用提交瞬间的快照。提交后更改/删除引用只影响下一次任务；本次任务不被悄悄更改。任务完成按 boardId、taskId 和 generationNodeId 归属，不依赖当前选择，避免切板写错位置。

删除输入来源时清理连线并标记缺失引用，保留其顺序和角色以便补图；提示用户移除或替换后才能发送。已经提交的快照继续使用可用缓存素材；删除生成框不自动取消已提交任务，也不删除已完成结果，未完成任务继续由任务队列管理。具体取消仍走现有取消入口。

## Field completion before PR

下列为逻辑字段；落地优先复用已有同义字段，不为重命名再建立一套模型。

| 数据 | 拟新增 / 复用字段 | 必须补齐的链路 |
| --- | --- | --- |
| 输入操作 | intent、sourceTaskId、操作来源元素 ID | 工具栏、回填事件、输入会话、绑定恢复、草稿切换、提交解析 |
| 生成记录（阶段一） | imageGenerationRecipe.version / id / input、modelRef、参数、参考顺序 | 创建、持久化、完成绑定、读取、历史回填、克隆、备份恢复、清理策略 |
| 单项引用 | referenceId、boardId、sourceElementId、稳定 mediaKey、role、mask key | 上传/选取/连线、去重、排序、缺失提示、移除、快照、adapter 参数 |
| 生成框 | 元素 type、generationType、draft、references、最新任务 ID | 类型守卫、渲染、命中、插入、选择、移动、保存恢复、复制/粘贴、撤销/重做、删除 |
| 输入关系 | relationType、sourceElementId、target generationNodeId、referenceId | 展示、吸附、断开、随端点移动、撤销与恢复；从引用列表派生 |
| 任务归属 | boardId、taskId、generationNodeId、recipeId | 工作流/SW 序列化、任务恢复、失败重试、完成插入、结果详情 |

跨画板复制时生成新 ID，重映射随复制内容一起存在的引用；未复制的来源转成已保存媒体引用或明确缺失项，不保留指向错误画板的 live ID。导入未知记录版本时保留原始数据并提示，不静默按空草稿覆盖。

新字段保持可选或读取时有明确默认，不把老普通图片推断为永久生成框。新增字段必须同时验证前台、后台任务消息、持久化与备份；缺一项不能提交 PR。预计无服务端 schema 迁移，实际实施仍需检查当前部署消息版本契约。

## Risks / Trade-offs

- 当前 AIInputBar 包含多条绑定与提交路径：统一输入解析要覆盖普通发送、回填、重试及异步选区，不只修改数组拼接。
- 历史素材失效：稳定缓存引用能降低概率，不能恢复已删除内容；明确缺失优于误用结果图。
- 现有模型的参考数量、首尾帧支持不同：复用能力校验，不设新的武断上限，不静默截断。
- 新生成框需要完整元素生命周期：临时 anchor 只能复用视觉/状态组件，不能直接复用销毁语义。
- 已有来源连线可以删除；对历史任务的追溯删线不能反向改变生成配方。输入断线才改变下一次请求。
- 主画布支持蒙版、语义替换、画框和多图：阶段一的原输入重抽不能把“以此图编辑”的输入一起移除。
- 分阶段减少每次回归面，但不会消除第二阶段的持久化与交互成本。

## Rollout and rollback

阶段一独立交付并验收，再交付阶段二。方案阶段不改变运行时设置或数据。实现时新增数据需向后兼容，并在现有备份链路验证可导出/恢复；回滚代码前保留生成框数据备份，旧版本未必能渲染新元素，不能把回滚描述为零成本。

## Confirmed scope

- 用户选择 B：阶段一先交付并验收，阶段二后续推进。
- “再次生成”直接提交一张并移除固定 seed；另设“调整后生成”保留原批量数和 seed。
- 第一阶段不包含把所有旧历史补成完整 recipe；无法恢复的条目明确降级。这是数据能力限制，不代表可以省略新字段写入链路。


## Phase 2 implementation details

- 生成框复用原生 `geometry` 元素，附加 `generationNode`（version、generationType、prompt、model、modelRef、params、count、references），通过专用组件显示摘要。沿用原生的命中、移动、缩放、旋转、选择与剪贴板几何计算，不另建元素存储。
- 引用条目使用 referenceId、role、url、sourceElementId 和 sourceElementUrl。live ID 仅在所属画板内有效，不另存一份可能过期的 boardId。复制一起出现的图片时映射新 ID；其余引用解除 live ID，保留媒体内容。普通上传的图片同样持有稳定引用身份。
- `generationInput`（version、nodeId、referenceId）标识输入线，并从 references 派生；移动、删除来源或撤销后重新对齐，不把现有 canvasAssociation 来源线当输入。派生线不新增历史批次，用户删线在同一批次修改 references。
- 生成框选中后绑定已有输入栏；结束编辑恢复进入前的输入草稿。画板切换结束绑定。异步读取输入后仍检查画板身份；已经提交的任务继续走原来的所属画板插入/恢复规则。
- `generationNodeId` 作为独立任务元数据通过 workflow args、主线程/SW capability handler、image/video task payload、任务存储与结果插入传递，不放进供应商参数。自动、手动和画框插入保留该字段；复制结果时重新映射或清除节点身份。无需新服务器字段或数据库迁移。
- 视频草稿显式保存 role，首尾帧模型提交时按角色生成 `[first, last]` 快照，任务继续复用已有 referenceImages 和 modelRef 字段；切换模型不重写角色，不截断多余图片。
- 参数缺少对应 UI 控件时，恢复同一模型范围的输入会保留这些原始 adapter 参数。原渠道不可用时不自动改写成另一渠道。
- 未知版本或不完整生成框保留原数据并提示，既不初始化为空草稿，也不自动执行。


## 2026-11-11 交互打磨补充（用户已选择 B）

- 原生 geometry 生命周期保留，生成框以圆角卡片展示参考缩略图、提示词摘要、模型及结果数；不增加持久化字段。
- 引用线改用原生曲线及绑定端点，每份 referenceId 对应独立输入点；历史直线在加载时按现有引用关系升级呈现。
- 图片连线手势使用暂态 SVG 预览，靠近生成框时吸附并高亮，落点后才提交历史操作；Escape、pointercancel 清理预览。
- 选中生成卡片时复用原 AI 输入栏，定位在卡片旁或下方，关闭位置动画；点击空白/其他对象自动离开编辑，保留草稿。
- 图像和生成框变化仅更新受影响的引用关系；平移、缩放与选区变化不重建引用线。
- 用户进一步确认菜单仅补齐已有可用能力：文本、图片、视频、快捷编辑、普通连线。文本进入已有带参考图的文本输入流程；快捷编辑打开现有图片编辑器。图片和视频仍创建持久卡片。音频和 3D 不在本轮范围内。
- 原工作目录被并行操作切换并暂存后，改动恢复到独立 worktree `canvas-interaction-polish`，保留两份原 stash。
